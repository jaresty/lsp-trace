## Decided selector contract

Validate the complete bounded hierarchical document-symbol result and every range. Gather the symbols whose nonempty `selectionRange` contains the query point (start inclusive/end exclusive). A target is selected **if and only if exactly one containing symbol has a selection range that is a proper subset of every other containing symbol's selection range**. If the containing set has one member, select it. If empty, unresolved. If equal minimal ranges, incomparable/crossing minimal candidates, or no unique strict subset of all others, unresolved. Crossing or equal *nonminimal* ranges do **not** independently invalidate a unique strict innermost selection. Thus two crossing containing outers plus one range strictly inside both select the inner; two crossing containing ranges without a common strict inner remain unresolved. Provider order, symbol name, display-range specificity and references results are not tie-breakers. Ambiguous or invalid target => no references WRITE and no invented target or final.

The current `SelectDocumentSymbolCandidate` implementation rejects any second containing range. It does **not** implement this contract; `CandidateVersionV1` and the test's pinned policy label do not fix that. Future private work must add adversarial selector tests for nested, crossing outers/common inner, crossing minima, equal minima, singleton and malformed results, then independently replay the target receipt and source/revision custody against host-held originals before owner integration. Tests here establish schema/shape/pins, not coherent-rehash runtime rejection.
