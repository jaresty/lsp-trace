# ADR 0011 — proposed references issuance contract-freeze addendum

**Status: PROPOSED / implementation-only review pending; not an independent acceptance or runtime qualification.** This document does not amend the independently accepted `REFERENCES_SYMBOL_V1` contract or its 162-row occurrence matrix. The historical omitted-selector `CALLS_ONLY` bytes remain unchanged. Authority remains 0, accepted=false, completeness=UNKNOWN, NO_PRODUCER_AUTHENTICATION. The selected local-single-user privacy/default limits are implementation defaults, not evidence of enforcement or runtime qualification. No paused producer implementation is reviewed here.

## Exact issuance boundary proposed for freeze

A single invocation is keyed by `(transaction_id, request_key, invocation_id, selected response-read identity)`. The owner must select one Manager response-read for the request and retain **the exact complete result byte slice from that read**, including `null`, `[]`, or malformed bytes, under an independently verified private raw receipt. An owner-controlled scanner consumes that same immutable byte slice independently of parser `items`; it classifies the complete top-level form and counts array members under a positive bounded work cap. Before evaluation the owner attaches exactly one keyed transition sink. At each `QUERY_BEGIN`, `ELEMENT_BEGIN(i)`, `ELEMENT_TERMINAL(i,VALID_PENDING_ADMISSION)`, and `QUERY_TERMINAL(ITEMS|EMPTY)` the sink records the transition **before state advances**; a failed callback forbids the advance. The sink seals a distinct event receipt before proposal construction. The scanner and sink cannot be reconstructed from returned parser items, counters, or a later serialization. Proposal → inert ordinal candidate → independently replayed final is acyclic; only final no-replace publication, exact readback, and owner-expected replay can issue `T=1,A=P`. Before then issued `T=A=0` even if provisional `B,E,E_B,E_T,P` were observed.

**Contract correction 1:** The revised `schemas/adr0011-references-issuance-records.proposed.schema.json` distinguishes `REFERENCES_RESPONSE_READ_V1` from `REFERENCES_RAW_RESULT_V1`; the event receipt requires **both** refs. The closed response-read record includes transaction, session/generation, request key/invocation, method/target refs, write/read observation digests, result presence, exact raw slice digest and byte length. Its `read_digest` is the digest of the complete owner-observed keyed response-read observation, not the raw result digest; replay resolves that separately retained observation and proves its exact extraction bounds and byte slice before comparing the private raw object. Merely supplying a consistent record is insufficient. Capture attachment and original producer custody remain implementation obligations.

**Contract correction 2:** The legacy `schemas/adr0011-references-private-raw.proposed.schema.json` remains a malformed-only diagnostic manifest. A distinct new `REFERENCES_RAW_RESULT_V1` closed receipt in the revised issuance schema carries the response-read ref, exact payload selector/digest/length and OWNER_ONLY access for **both valid and malformed** results. No `reason` or parsed outcome appears in the raw receipt. A malformed result cannot form a success proposal; a valid result cannot use the malformed-only manifest in lieu of the general receipt.

### Normative byte/identity calculus for implementation-only review

For every **new** record, encode strict UTF-8 JSON (RFC 8785 JCS with the tighter profile here): Unicode NFC strings prohibited unless their original input is already NFC; reject surrogate or invalid UTF-8; object keys sorted by UTF-16 code units; strings use JSON mandatory escapes only (`\"`, `\\`, control characters escaped as lowercase `\\u00xx`, except `\\b`, `\\t`, `\\n`, `\\f`, `\\r`); no whitespace outside strings; integers only in `[0,9007199254740991]`, shortest decimal with no leading zero or negative zero; booleans and null use lowercase literals; no floats; no duplicate decoded keys, unknown keys or trailing bytes. An independent parser must reject duplicate keys **before** map decoding and byte-compare the JCS re-encoding. Raw result bytes are not JCS-normalized: they are opaque exact bytes. Define `H(x)=sha256:` followed by lowercase hex SHA-256 over exactly x; ref `(schema_version,selector,digest)` requires `digest=recordDigest` and an owner-derived flat basename with digest hex, never a caller-supplied path. Every new record `schema_version` is its role/domain literal. For digest identity of a record the domain is its literal role; `recordDigest = H(UTF8(role) || 0x00 || canonicalRecordBytes)`; `payloadDigest = H(exactRawBytes)` instead (no invented encoding around raw). Let `LP(x)=uint64be(len(x)) || x`, where length is bytes and uint64be is exactly eight network-order octets. `transaction_id=H(LP(UTF8("REFERENCES_TRANSACTION_V1")) || LP(UTF8(session_id)) || LP(canonical(integer generation)) || LP(UTF8(request_key)) || LP(UTF8(invocation_id)) || LP(UTF8(query_occurrence_id)) || LP(canonical(source_identity_ref)) || LP(canonical(revision_identity_ref)))`; `occurrence_id=H(LP(UTF8("REFERENCES_OCCURRENCE_V1")) || LP(UTF8(transaction_id)) || LP(UTF8(query_occurrence_id)) || LP(canonical(method_ref)) || LP(canonical(target_ref)) || LP(canonical(integer ordinal)) || LP(canonical(returned_uri)) || LP(canonical(returned_range)))`. There is no delimiter ambiguity, key permutation, self-hash, or sorting of occurrences. Raw payload is exceptional: preserve the exact unmodified result byte slice, digest it directly, and include its byte length in a separately canonical manifest. `null` (`6e756c6c`) and `[]` (`5b5d`) must have different raw digests despite both yielding P=0. Schema validation alone never establishes canonical bytes, existence, custody, or digest/selector equality.

The schema ID for every new role is `https://jaresty.github.io/lsp-trace/schemas/adr0011-references-issuance-records.proposed.schema.json#/$defs/<definition>` where `<definition>` is exactly `methodRecord`, `targetRecord`, `preparedSource`, `sourceIdentity`, `hostGit`, `revisionIdentity`, `ownerRead`, `responseRead`, `rawResult`, `scanner`, `events`, `proposal`, `candidate`, `final` or `policy`; all share the byte digest of that entire schema file, not a detached fragment. The implementation must select this digest against a reviewed immutable commit, never trust the incoming record's own schema claim. The exact ref selector for each new role is `adr0011-references-issuance-v1-<role>-<64hex>.json`, where `<role>` is the respective lowercase `prepared-source`, `source`, `host-git`, `revision`, `owner-read`, `response-read`, `raw`, `scanner`, `events`, `proposal`, `candidate`, `final`, `method-policy`, `admission-policy`, `privacy-policy`, or `retention-policy`; the hex is the recordDigest without `sha256:`. Raw payload selector is instead `adr0011-references-raw-payload-v1-<64hex>.bin` using payloadDigest. All refs are owner-selected relative basenames, only within the selected private 0700 root. The role in a policy receipt is its one exact version among `REFERENCES_METHOD_POLICY_V1`, `REFERENCES_ADMISSION_POLICY_V1`, `LOCAL_QUALIFICATION_PRIVACY_V1`, `REFERENCES_RETENTION_POLICY_V1`; policy bytes are separate immutable JCS canonical JSON without self-reference; its `policy_bytes_ref.digest` is H(exact selected policy bytes). The receipt may not choose the policy; owner expectation must name the exact selected policy bytes/digest. These are the proposed exact version, JSON schema identity, canonical grammar, domain, digest and selector for **each** of: prepared source identity (normalized URI, prepared version/digest, position encoding), revision identity (root, commit, custody, two host Git observations without custody upgrade), subordinate target, references method, selected keyed response-read, exact raw result manifest/payload, independent scanner observation, evaluator event receipt, evaluation proposal, inert ordinal candidate, final issuance, and **separate** selected method, admission, privacy and transaction-retention policies. Policy selection is by independently pinned exact canonical bytes and digest, not a ref copied from a claimant. The method/target `Version` strings `lsp-trace.adr0011.references-symbol.method.v1` and `.target.v1` and flat selectors `adr0011-method-<64hex>.json` and `adr0011-target-<64hex>.json` are **prospective producer-output requirements**, not proof current test-owned code conforms. These two **new closed required shapes** in `$defs/methodRecord` and `$defs/targetRecord` use Go `encoding/json.Marshal` with their fields in the exact schema `required` order followed by one LF byte (`0x0a`), digest `H(exact bytes)` without role prefix, and flat selector hex equal to that digest. Unlike the observed unsafe test-owned `chainPair`, the required method record contains **no `ResultBase64`**; it references a separately verified exact raw receipt. This changes the future record shape while preserving only the observed Version and flat selector/digest semantics. The target record binds its own source/revision and target/result digests; owner independently replays target result. Current implementation is expected to change only after independent contract acceptance. The ref's `schema_version` means the predecessor `Version` value, not an added JSON field. The paused test-owned producer is excluded from this submission.

Replay must accept the **owner's independently selected** expected transaction, invocation, keyed response-read, source/revision, implementation and every policy/schema digest, not merely internally consistent documents. It first verifies exact final bytes/selector/digest and traverses final→candidate→proposal→method/target/raw/scanner/events/response-read/source/revision/policies; it checks complete dependency closure, equal contexts, read→raw byte identity, scanner count versus independently parsed raw top-level member count, event sequence/ordinals and one terminal, and each candidate ordinal/range against the original raw member. For the selected all-well-formed-locations admission policy, successful final replay requires `N=B=T=1`, `E=E_B=E_T=P=A`, `1≤P≤1000` for `COMPLETE`; `COMPLETE_EMPTY` requires `E=P=A=0`. Any nonempty response containing a policy-excluded location cannot issue a final under this narrower policy (and must never be mislabeled `COMPLETE_EMPTY`); adding partial admission requires a new policy version with explicit admitted-ordinal membership and independent replay. Proposal/candidate never have issued T/A. Equal-location occurrences retain distinct ordinal identities. No caller-selected candidate or proposal can start admission. A missing original dependency makes dependent claims INCOMPLETE; a substituted one cannot mint a new receipt. An already issued immutable historical record is not rewritten by later replay failure.

### Counterexamples required before freeze

| Mutation of otherwise plausible two-element valid result | Required outcome |
| --- | --- |
| Missing, duplicate, reordered, skipped-ordinal, post-hoc reconstructed, or cross-invocation event | No success proposal and no new T/A; partial sealed state remains private. |
| Scanner reports 1 while exact raw has 2, or scanner reads another response | No proposal or issuance even if parser has two items. |
| Raw result `[]` substituted for `null`, same P=0 | Digest or top-level form mismatch; no issuance. |
| Two identical ranges collapsed, swapped or relabeled | Reject ordinal identity; no issuance. |
| Self-consistent candidate with absent, wrong, or committed-unverified final | No newly issued terminal or occurrence. |
| Any method/raw/scanner/event/proposal/candidate/final precommit failure | `PRECOMMIT_FAILED`, no invented committed selector, issued T=A=0. |
| Any committed-but-unverified publication/readback | `PUBLICATION_UNVERIFIED`, retain exact potentially committed selector and expected digest privately, never retry/promote/evict, issued T=A=0. |
| Crash or callback failure between element begin and terminal, or at query terminal | No completed sealed event receipt or success proposal; issued T=A=0. |
| Source, revision, privacy, admission, method or retention policy changed one at a time while all downstream hashes are recomputed | Reject against independent expected identity; issued T=A=0. |

Successful separately replayed bounded diagnostic D remains a different arm with A=0; a malformed prefix cannot be promoted into whole-result P. Selected privacy denial is WITHHELD, whereas uncaptured/deleted/unreplayable evidence is INCOMPLETE. Do not put raw bytes, error text or source into D or uncertainty metadata. Local opt-in raw ≤1,048,576 bytes/object, 16 objects/16 MiB per run, 128 MiB root; issuance transaction ≤256 objects/128 MiB and ≤256 uncertainty entries/512 KiB, with block-on-exhaustion, no silent eviction. Separate selected framing (4 MiB wire, 2 MiB staged), Manager aggregate (4 MiB decoded and four response messages), canonical record (1,500,000 bytes) and D (16,384 bytes/record, 16 records/262,144 bytes) bounds retain their distinct units. Scanner/diagnostic work has the selected byte-visit units and 1,048,576-unit caps below; live allocation and monotonic deadline need positive seam-derived bounds. Every bound needs an exact counting point and edge/edge+1 rejection controls; none is yet a verified runtime claim. Default no durable raw retention cannot issue a replayable final.

## Required predecessor and policy bytes

The four exact selected policy byte artifacts are `policies/adr0011-references-{method,admission,privacy,retention}-policy-v1.proposed.json`: each is precisely its file's UTF-8 bytes with no newline, with closed keys and its own `schema_version`. The owner independently selects each by its reviewed-base SHA-256; `policy_bytes_ref.digest=H(exact selected bytes)`, selector `adr0011-references-policy-bytes-v1-<digesthex>.json`, and the enclosing receipt uses the role-domain digest. No policy receipt may choose or substitute a new policy. Privacy explicitly denies signed error code **including zero** by default, requires per-run live opt-in, and disables durable raw by default. Issuance retention distinguishes optional debug bytes from verified final dependencies and blocks on transaction/uncertainty exhaustion; no existing local default is redesigned.

Prepared source `REFERENCES_PREPARED_SOURCE_V1` records URI, version, encoding, exact text digest/length; the source identity independently refers to it and compares repeated fields. Prepared text is separately owner-retained at `adr0011-references-prepared-text-v1-<digesthex>.bin` with `H(exact bytes)` and exact length. The independently retained `REFERENCES_HOST_GIT_OBSERVATION_V1` BEFORE/AFTER records are the proposed implementation encoding of the accepted `HOST_GIT_PROBE_V1` observer evidence; each closed record requires `custody=HOST_OBSERVED_GIT`, **separate** from the revision identity's `workspace_revision.custody=CALLER_ASSERTED` for the eligible Go/gopls path. Neither value upgrades the other or authenticates the provider. They carry the exact registered worktree root and command cwd URI, host executable absolute file URI plus SHA-256 of its bytes as observed by the host, three ordered command observations, result root/commit/dirty fields, and a separate UTC RFC3339 timestamp for each command. Each command observation retains its exact argv, exit status, and **complete bounded stdout and stderr byte streams**, including zero-length outputs. For each stream the closed `{selector,digest,byte_length}` points to a separately verified 0600 no-replace object `adr0011-references-host-git-output-v1-<digesthex>.bin`; `digest=H(exact stream bytes)`, length is 0..1,048,576, and a zero-length stream still has a real empty-byte object. No truncation or elision is eligible; exceeding either stream bound prevents issuance. The three argvs are exactly `git rev-parse --show-toplevel`, `git rev-parse HEAD`, and `git status --porcelain=v1 --untracked-files=all`, without shell interpolation and with the recorded executable/cwd. Replay independently reads all six streams for **each** observation, compares exact digest, derived selector and byte length, and requires `rev-parse --show-toplevel` stdout to be the canonical absolute local filesystem path for the expected registered worktree followed by exactly one LF, `rev-parse HEAD` stdout to be the 40-lowercase-hex expected commit followed by exactly one LF, and `status --porcelain=v1 --untracked-files=all` stdout to be empty. Interpret the root stdout without trimming: remove only its final LF, require a slash-prefixed absolute POSIX path with no NUL, CR, LF, or `.`/`..` path segment, and percent-encode each UTF-8 path byte outside RFC 3986 unreserved characters and `/` (uppercase hex) into `file://` plus the encoded slash-prefixed path. Require that exact URI to equal the selected registered worktree URI; do not resolve a different root or normalize path spelling. Each exit status must be zero, all stderr streams empty, the recorded `dirty` flag must be false, executable URI/digest and cwd URI must equal the acquisition owner's expectations selected before query declaration, and before/after phases and per-command UTC timestamps must be nondecreasing as parsed instants without a missing or reversed timestamp. The owner must observe the same executable path and its exact-byte digest again at finalization; an executable change blocks issuance. The parent revision root/commit must match both observations and independently selected worktree expectations. Stderr is retained even on success; nonempty stderr disqualifies eligibility rather than being silently dropped. A failed or partial command, timestamp absent, unretained executable identity, mismatched argv or missing stream blocks new issuance with `T=A=0`; do not infer host/producer authentication from a self-consistent record. Final→revision→before/after probe→every stream is mandatory verified dependency closure (including retention); neither observation upgrades caller custody. Owner-read `REFERENCES_OWNER_READ_OBSERVATION_V1` records key/session/method, write/read observation digest and exact result offset/length. The independently retained keyed complete write/read envelope bytes use private flat selectors `adr0011-references-write-v1-<digesthex>.bin` and `adr0011-references-read-v1-<digesthex>.bin`, with H(exact bytes); replay extracts exactly the recorded read slice and matches raw digest/length before scanning. The closed response-read record references this owner-read; event receipt references both response-read and the **different** general raw-result receipt. All ancillary records use the shared `$defs` schema and new role-domain digest, while payloads alone use H(exact bytes).

The scanner work unit is one raw byte visited (including punctuation/whitespace); selected bound 1,048,576, reject at 1,048,577 before element evaluation. Diagnostic inspection uses the same byte unit and bound; allocation and monotonic deadline remain positive bounded seam-derived implementation values, with measured units and edge/edge+1 guards required before enabling either path. A scanner `MALFORMED` observation cannot enter the success arm. Schema validation alone cannot verify dynamic equalities, producer custody or callback independence: independent replay must check every edge, ordinal, exact byte length/digest/selector, complete dependency closure and policy/schema expectations. Tests here are contract counterexamples, not runtime evidence.
