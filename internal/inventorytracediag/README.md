# Opt-in inventory tracing diagnostics (prepared, runtime qualification pending)

The helper emits runtime/trace regions and checkpoint events **only when runtime tracing is already enabled**. It never owns tracing, starts/stops a trace, creates tasks, discovers a provider, admits input, renews a deadline or acquires source custody. Invalid code/mask values are suppressed. Disabled paths do not build payload text; mask construction at readiness is itself guarded. The isolated disabled-helper test currently observes zero allocations, not an enabled-path throughput or quote qualification.

## Closed payload contract

`Code` maps to a fixed uppercase vocabulary. Event category is `inventory.checkpoint`; region names use that same vocabulary. Capability categories are `inventory.cap.requested`, `.observed`, `.missing`. Their values are the closed strings0..15. No error rendering/parsing, source text, URI, credential, session/operation/handle identity, provider name or arbitrary caller string is accepted as a payload. This is not a guarantee that an entire externally-created Go trace (including runtime metadata and other loggers) is secret-free.

Capability bits:1=document symbols,2=call hierarchy,4=references,8=definitions. Requested always includes document symbols, then the existing native plan flags. Observed includes all four parsed support flags, even if unrequested. Missing=requested &^ observed. Masks are emitted after existing capability parsing and before the unchanged support check/discard. CAPABILITY_UNSUPPORTED therefore differs from a query returning empty; an earlier parse/readiness refusal does not fabricate observed capabilities or a query outcome.

## Sites and interpretation

- Execute: early REPLAY/EXECUTE_REFUSED use logging-only Background so unvalidated caller contexts are not queried for task metadata. The Execute region starts only after original identity/context/liveness checks; actual operation contexts are unchanged. Stage checkpoints cover window/start/readiness/capture/finish/observe. Lease callback region starts after the original first `checkpoints.enter()` statement. Capture, native-CALLS and issuance refusals are separate. LEDGER_EMPTY/UNAVAILABLE and CONFIRMED remain at their existing decision sites.
- Cleanup: DEFERRED_FINISH occurs before the existing Finish. Finish → failure attribution → abort remains exact; DEFERRED_FINISH_DONE follows abort and does **not** imply success, zero logical accounting objects or OS containment.
- Issuance: original ctx is used for logging only; owned deadline/identity/target/source checks, binding, query bytes, build, publication, replay and take-evidence boundaries have fixed checkpoint/region codes. The original operational arguments, error returns and wrapping are unchanged.
- Build/assembly: signatures are unchanged because an existing test directly calls Build. Contextless leaf regions/events use Background, claim **goroutine-local attribution only**, and do not claim parent-task attribution. Codes identify provider/kind/method validation, empty CALLS composition, typed preparation, projection, BuildInput and ParseAndAdmit. R/D empty/nonempty codes derive from the existing parsed item length, not fixture settings.
- referencegrouping: NATIVE_PROOF_WITHOUT_CALLS is emitted at the exact unchanged `native proof without calls` rejection. It uses Background, with no parent-task attribution claim. No error-string classification is used.

An independently authorized controller may establish a parent task **before** binding a custody-bound context. This patch adds no controller and never substitutes a task-derived context inside an existing bound operation. Actual enabled event emission, task/goroutine relationships, ordering, event volume, runtime overhead, deadline impact and native acceptance are NOT_RUN and require fresh finite authorization. Existing quotes/budgets remain untouched, not requalified for tracing.
