Expected-byte equality is not proof of the language server's analyzed source version.

### Private source-reader correction after independent REQUEST_CHANGES

The private producer no longer uses the historical `source.ReadRegularInputBounded` opener. On Darwin/Linux, `source_reader_private_unix.go` owns a descriptor-pinned workspace root, walks **every ancestor and relative directory component** with `O_DIRECTORY|O_NOFOLLOW`, and opens the final source with `O_NOFOLLOW|O_NONBLOCK`. Actual descriptor metadata and descriptor-relative named bindings are validated before reading and afterward; byte bounds and cancellation are checked before allocation/read. One file FD supplies the bytes. Source files may be ordinary read-only files; publication ownership, 0600 permissions and digest filenames are not imposed. Read/close uncertainty returns no source bytes, close errors are joined, and capture-root close failure suppresses the envelope result. Unsupported platforms explicitly refuse the private reader, without falling back to historical symlink-following behavior.

Expected-content equality remains a drift check, **not** the security gate against forbidden target access. FD-identity spies test equal/different-byte file and directory aliases, including replacement between pinning/opening. Tests also cover replacement after an actual Manager capability bind, retired/replaced roots, metadata changes, bounded allocation, cancellation and joined faults. The initial equal-byte capture fixture failed on the old private reader; removing `O_NOFOLLOW` from the repaired reader caused actual forbidden-directory/leaf-FD observations, and restoring it returned those guards to GREEN. Historical V2 still follows a contained source symlink in its explicit compatibility fixture; no historical source reader is changed. Descriptor pinning and safe-boundary checks do not establish arbitrary same-user namespace atomicity, time-bounded filesystem I/O or authenticated point-in-time analyzed source.

Every private envelope explicitly declares partial=true, source completeness UNKNOWN, accepted=false, authority=0, replay_admitted=false. No policy artifact is added to the native replay manifest. Existing public/default producers, V5 source admission and omission refusal remain unchanged. ## Policy, incoming coverage and claim ceilings

Distinguish (1) four-file **nomination scope**, holding the exact 25 initial targets; (2) six-file **query/source-read scope**, including allowed context; (3) **observed endpoints and occurrences**, which may extend beyond six without conferring query/read authority. Six-file permission is not six-file nomination. Directional observations are server reports, not complete bidirectional neighborhoods.

Example: seed A calls outside-set B. Retain A→B, its reported call sites and B's explicit frontier. Existing Slice semantics would start incoming from outgoing frontier B; policy prevents querying B. **Do not substitute incoming(A), silently reseed, or claim A's incoming neighborhood complete.** Successful-empty outgoing starts remain governed by existing semantics. Any change to start selection requires its own explicit approved semantic change.

Check canonical exact URI membership before every query, preparation/supply, source capture and projection read, tied to the frozen revision/content inventory. Record the stopped direction, endpoint and originating request. Outside-set call-site coordinates may be retained while their source remains policy-withheld, not missing or empty. This bounds tool-issued traffic and tool-owned reads, not language-server internal indexing.

Distinguish observed empty, nonempty, failed, unavailable, budget-blocked and policy-stopped. No fake success-empty; no silent dropping CALLS to satisfy limits. If valid returned data cannot all be retained, expose partial accounting or refuse the claimed milestone. Keep canonical FALSE, source closure UNKNOWN, diagnostics, omissions, exact native hashes and per-native provenance. A scoped disposition can describe accounted eligible work only; it cannot assert unobserved incoming coverage, whole-source closure, runtime execution, authenticated analyzed version, feature identity, permission or production authority.
