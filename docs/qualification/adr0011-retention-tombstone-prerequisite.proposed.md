# ADR 0011 — retention, cleanup and tombstone prerequisite (proposed, not implemented)

**Separate implementation-only review.** This lifecycle cannot borrow acceptance from a successful acquisition replay. The accepted references contract remains unchanged. Until both prerequisites are implemented and independently accepted, no row execution, issuance enablement, index or definition implementation follows.

## Ownership and states

The acquisition transaction owns verified immutable raw/result/source/method/target/policy objects before any admitted occurrence ledger. A successfully verified final ledger atomically records its exact immutable dependency set and becomes their retention owner; live derivatives add independent pins. Optional diagnostic files never acquire ownership of issued dependencies by proximity or shared root. An unverified publication is `COMMITTED_UNVERIFIED` or precommit failure, **never** an issuer or a live dependency owner. No automatic age-based deletion may remove canonical issued dependencies.

For each dependency, retain a monotone state derived from immutable evidence: `ACTIVE_VERIFIED` → verified intent `RETIRE_SELECTED` or `REVOKE_SELECTED` → verified all-dependent eligibility barrier `TOMBSTONED` → verified terminal removal `REPLAY_UNAVAILABLE_REMOVED`. A missing object without a verified terminal manifest is instead `REPLAY_UNAVAILABLE_UNEXPLAINED` regardless of its prior state; it cannot revert to ACTIVE merely because bytes reappear. Retirement without revocation may tombstone only after all pins are independently absent; revoke must tombstone every dependent first. An intent alone does not establish successful deletion; any uncertain stage blocks new use until reconciled. State precedence is unexplained loss over claimed success when terminal evidence is missing, verified tombstone over physical byte presence, and verified terminal removal over later physical reappearance. Historical original issuance bytes and counts are never rewritten. New traversal, grouping and admission require active replayable dependencies and must consult the verified barrier before use; a tombstoned ledger is ineligible even if a stale reader still has its bytes.

## Cleanup transaction

A maintainer-reviewed `RETIRE_DERIVATIVES_AND_REMOVE` decision names an exact ledger/dependency closure and expected selectors/digests. Acquire an owner-controlled **durable exclusion fence** over the selected dependency closure before taking the pin snapshot. The fence is a verified versioned no-replace intent plus a durable generation/epoch check consulted by all new pin writers and all new-use readers; no concurrent pin or use may cross it. Independently enumerate all active ledgers/derivatives and reject retirement if any remain. Revalidate the same epoch, complete dependent set and absence of newly admitted pins immediately before **each** unlink; a failed revalidation aborts further removal and retains an uncertainty record. Publish and verify the bounded no-replace intent with decision identity and full dependent set. Record each unlink attempt's pre-state (including already missing), syscall outcome, post-readback and parent-directory sync outcome in a bounded immutable journal; a missing-attempt object is unexplained loss unless an earlier verified terminal accounts for it. Only after all required attempts and syncs succeed may a no-replace terminal manifest assert success, followed by exact readback and replay. A partially failed deletion **cannot** be recorded as successful erasure. Retry is a new reviewed attempt with a fresh state observation, not reinterpretation of the old manifest. No cleaner may silently reassign an unverified object to an issued ledger.

A reviewed `PRIVACY_REVOKE` may override normal retention only through one **all-or-none eligibility barrier**: under the same exclusion fence, publish individual cascading tombstone records for the complete independently enumerated dependent set, then one immutable versioned root manifest binding their exact identities, set cardinality and epoch. Verify every record, root no-replace publication, directory sync, exact readback and full set replay before the root becomes the single eligibility cutover checked by all new-use readers. Partial child publication without a verified root leaves no falsely completed tombstone, keeps the fence blocking new use, forbids unlink and requires restart reconciliation; it must not restore eligibility by releasing the fence. Once the verified root cuts over, **all** dependents are ineligible as one unit, even if physical bytes remain. Missing or unverified root aborts removal rather than leaving a live ledger referencing erased bytes. Replay of a removed dependency returns `REPLAY_UNAVAILABLE_REMOVED` only if a valid decision plus terminal removal/tombstone witness accounts for it. Missing bytes without that witness are `REPLAY_UNAVAILABLE_UNEXPLAINED`, a fail-closed integrity failure, not cleanup success or retroactive privacy withholding.

## Crash and adversarial replay

On restart reconstruct ownership and eligibility solely from verified immutable intents, ledger refs, tombstones and terminal manifests. A crash after verified intent but before removal leaves objects held and historical issuance unchanged; the recovered fence remains active until a verified abort/reconciliation record proves no unlink occurred and restores eligibility, or a valid terminal completes the transition. A crash after some unlinks but before a verified terminal is **uncertain**, disallows new use of affected dependencies and demands reconciliation—never fabricates success. A crash after a verified root tombstone but before unlink leaves old bytes physically present but inactive for new use. On restart, validate the epoch and all dependent records before releasing any fence; physical reappearance alone never clears a tombstone. A failed directory sync, readback, missing object, replaced selector, repeated decision, concurrent new pin or publication collision must not upgrade a failed cleanup to VERIFIED, delete a still-pinned dependency, resurrect a tombstoned ledger, or erase an historical issuance claim. Distinguish logical invalidation from physical erasure and host backup copies.

## Bounded falsification and independent disposition

Freeze exact root, object/byte/work limits and the proposed retention policy SHA-256 `5e4a817e8dc8aed4bc6053e18e1f4dfda00a159cf909fed37e0ae39f4d1baa68` as independently selected expectations before testing. Required fixtures cover shared dependency pins, successful unpinned retirement, refused pinned deletion, a concurrent pin racing the exclusion point and each pre-unlink revalidation, revoke with multiple transitive derivatives, partial child tombstone publication without root, failed single unlink, partial multi-object failure, missing-at-attempt object, failed post-unlink readback or directory sync, no-replace conflict, committed-but-unverified intent/root/terminal, crash at each publication/unlink boundary, restart with bytes still present after a verified tombstone, restart reconstruction, unexplained loss, duplicated decisions and active-input replay before/after the eligibility cutover. Every fixture records original issuance bytes/counts before and after; assertions must demonstrate that cleanup neither promotes intermediate evidence nor silently erases historical issuance state. Default-off and no ordinary raw disclosure remain invariant.

Review the frozen implementation diff, exact immutable decision/manifest schemas and policy pins, tests with failure injection, and retained replay/readback artifacts separately from the production admission packet. Closed disposition: `ACCEPT_RETENTION_TOMBSTONE_PREREQUISITE_FOR_IMPLEMENTATION_ONLY` or `REVISE`. Acceptance does not prove physical erasure, authorize live retention, qualify an occurrence, or enable rows 015–017.
