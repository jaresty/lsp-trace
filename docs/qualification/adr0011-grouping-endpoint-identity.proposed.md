# ADR 0011 — grouping endpoint identity boundary (proposal)

**Status: PROPOSED, NOT FROZEN OR QUALIFIED.** This is a prerequisite for immutable `ReferenceGroupingInput`, **not** a new definition/reference occurrence-admission predicate and not permission to run Leiden. ADR 0011 requires exact node identities but does not yet select a cross-transaction/cross-kind resolver. Equal text or coordinates alone never merge evidence.

## Four different identities

| Identity | Scope and purpose | Cross-transaction reuse |
| --- | --- | --- |
| Immutable relation **occurrence ID** | Family/version, exact method/acquisition/terminal receipts, query, returned target and original ordinal; preserves duplicates | Never deduplicates, even when endpoints coincide |
| **Target-candidate ID** | One method transaction; equal returned targets may share a candidate while ordinals stay distinct | No implicit reuse; definition admission's first policy is transaction-scoped |
| `GROUPING_SOURCE_SYMBOL_V1` **node ID** | Independently resolved source symbol under this policy, with exact immutable source and resolver custody; used solely to map admitted occurrence endpoints into a grouping graph | Only if **all** canonical key fields and qualified resolver policy match |
| **Display ID** | Presentation-only name/full span/label under separately selected source-context and privacy policy | Never authorizes graph-node equivalence or occurrence admission |

## Proposed closed grouping-node key

Compute `sha256(domain || canonical(policy version, logical URI, source digest, source byte length, position encoding, clean workspace revision and custody, language ID, exact provider/profile ID, qualified resolver-policy ID/digest, exact half-open symbol selection range, exact full display range))`. **Session-local LSP document version is deliberately not in the cross-query node key**: two independently prepared versions may differ while exact source bytes and clean revision agree. Every mapping proof must still bind and replay-verify its own exact document version, session/generation and source digest; mismatched source or revision rejects. The independently verified resolver receipt selector/digest and server-reported symbol kind are also **obligatory mapping evidence**, not key fields: including a transaction selector or optional kind would defeat stable identity. For the first Go/gopls resolver profile, require a present, stable kind; absent or inconsistent kinds across otherwise equal keys yield `GROUPING_ENDPOINT_AMBIGUOUS` and no mapping. Another profile may define a separately qualified kindless rule but cannot inherit this one. A resolver may be a separately replay-verified document-symbol transaction with **unique strict most-specific containment** or a separately contracted language-specific range/symbol adapter. Record the resolver's method and source-custody limitations; neither a self-hash nor the server-reported span authenticates semantic truth. Query occurrence ranges and returned target ranges remain distinct from resolved selection/display spans. Names, filenames alone, package labels, ordinal and visual proximity are **not** node keys.

**Query occurrence derivation and grouping endpoint resolution are separate qualifications.** `GO_IDENTIFIER_RANGE_V1` establishes only the submitted token span and mandatory definition query receipt; it does **not** establish a grouping symbol's full display range or node identity. Proposed initial `GO_GOPLS_DOCUMENT_SYMBOL_ENDPOINT_V1` must independently acquire and replay-verify exact source-bound `textDocument/documentSymbol`, uniquely resolve strict most-specific containment, require a full display range plus present symbol kind, and publish a versioned resolver receipt and substitution matrix. CUE needs a separately frozen provider-specific resolver profile (document-symbol if actually supported, otherwise a separately qualified CUE syntax resolver); no Go or lexical-token receipt is relabeled CUE. For cross-kind community composition in one profile/revision, **both** reference and definition endpoints must use the same qualified resolver-policy ID or a separately qualified explicit equivalence map; otherwise identical source symbols under different resolver IDs stay separate and the mixed arm is ineligible, not silently fragmented. For a references target, resolve the already admitted referenced-symbol target to this key without altering its original occurrence. For a references source, independently resolve its exact reference location to one source symbol under a qualified profile (a containing source definition is not automatically the referenced target). For a definition source, resolve the independently admitted query occurrence. For a definition target, verify its returned `Location` or `LocationLink` URI/ranges against exact target source, then independently resolve the unique target symbol; a bare `Location.range` does not create an unverified symbol identity. A LocationLink's `targetSelectionRange` is evidence to compare, not license to bypass source/resolver verification.

**Missing, ambiguous or mismatched resolver evidence yields `GROUPING_ENDPOINT_UNRESOLVED`:** retain the immutable admitted occurrence and its method evidence, mark the prospective grouping input ineligible or exclude it under a separately frozen policy with explicit denominator. Never erase, recast, or silently merge the occurrence. Across methods, queries, or sessions, equality requires the *full* key plus a separate verified immutable resolver receipt for **each** mapping; a different source digest/revision/profile or selection/display span yields a different node. A different session-local document version **with identical source digest, URI, revision and all other key fields** does not change the node ID, but each version must independently verify its source. A missing/contradictory kind makes the mapping unresolved rather than silently merging or assigning a different node. Across provider/language profiles, no equivalence is inferred: a future versioned cross-profile mapping requires its own frozen contract, substitution matrix and qualification. Copying CALLS node IDs into D/R nodes solely because spans overlap is prohibited.

## Required qualification before composition

Pin this policy's version/schema/digest and each supported resolver profile. Its receipt must have a closed canonical schema for exact session/generation/document version, managed source, symbol result, chosen selection/display/kind, strict containment, resolver policy and predecessor selectors/digests. The `GO_GOPLS_DOCUMENT_SYMBOL_ENDPOINT_V1` qualification matrix must independently substitute URI, digest, byte length, document version (receipt changes; node key stable only with independently identical bytes), encoding, revision/custody, provider/language, selection, display, absent/changed kind, tied containment and resolver selector/digest. CUE resolver profiles require their own fixtures and review; passing a Go query-adapter matrix is not passing a grouping resolver matrix. Test equal coordinates across different revisions, equal names across files, overlapping ranges, duplicate relation occurrences, mixed relation kinds, mismatched LocationLink ranges and source-document absence. **Same-key example:** two exact managed transactions for `file:///w/a.go` at clean commit `R`, digest `D`, profile `GO_GOPLS_EXACT_V1`, resolver `GO_GOPLS_DOCUMENT_SYMBOL_ENDPOINT_V1`, selection `[4:5,4:9)` and display `[3:0,8:1)`, with independently verified document versions 1 and 2 and distinct resolver receipts, yield one grouping node if both report the same present kind. **Different-key example:** changing digest `D` to `D2` or clean commit `R` to `R2` yields a different node despite identical ranges; absent or conflicting kind yields no eligible mapping, not an alternate key. Both examples retain two distinct original occurrence IDs. Prove deterministic same-key/same-node and different-key/different-node under exact replay and input permutation; retain unresolved/excluded counts and exact predecessor receipts. Only then may a grouping-input qualification consider mapping admitted D/R occurrences to `PairWeight`. This boundary cannot qualify a method occurrence, grouping policy, representative, ownership, or feature identity.
