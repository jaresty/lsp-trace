## Selected semantic delta (candidate until decision)

Applicability returns only `SUPPORTED | UNSUPPORTED | UNKNOWN | MALFORMED`; `INVALID_CHRONOLOGY` is a separate transaction-level stop, **not a fifth selector outcome**. Any invalid chronology prevents an exact evidence receipt or authorization, including static+dynamic registration for the same method, and an unregister with no active exact `(registration ID, method)` match. A malformed JSON key/type is different from a syntactically valid but invalid unregister; retain both causes separately. Static support's contribution survives dynamic unregister *internally*, but static-plus-dynamic coexistence is invalid chronology and **never yields SUPPORTED**. A register/unregister after the held completed WRITE boundary cannot authorize or invalidate the earlier request. A claimant summary is never the expected chronology.

A dynamic `documentSelector:null` means evaluate the **independently held client-side selector** under the same grammar; missing held selector gives `UNKNOWN`. An asserted client selector from the claimant is not held evidence. A selector `[]` is `MALFORMED` (LSP 3.17 `documentFilter.md:42`: one or more filters). Missing `registerOptions` or missing `documentSelector` remains `UNKNOWN`; non-object options and known wrong types remain `MALFORMED`. Static absent/null/false is `UNSUPPORTED`; true/valid method-options object supports all otherwise eligible text documents. Static options/extensions are retained; a known malformed field fails, an unknown additional field with a complete known standard filter is ignored, an unknown-only future filter is `UNKNOWN` rather than a wildcard. **Deliberate successor-policy change from the earlier read-only packet:** that packet required independently established inertness for unknown fields; the user's new V3 selection explicitly instructs ignoring additional fields once a complete known standard filter is present. This is a local forward-compatibility choice, not inferred from LSP 3.17. It never repairs a malformed known field or grants support to an unknown-only filter. Strict full JSON and duplicate-decoded-key rejection apply throughout.

Query context is independently held exact URI bytes, language bytes or explicit absence, ordinary/cell kind, enclosing notebook originals or absence, workspace, session and generation. Compare ordinary language and notebook-object `notebookType` exact UTF-8 bytes; the pinned LSP 3.17 notebook-cell **string** `notebook:"*"` matches every notebook, and cell `language:"*"` matches every language (`notebook.md:145–156`). Otherwise compare notebook string/type/language exact bytes. Do not infer language from filename/provider. Extract **only** the URI scheme from the initial RFC 3986 grammar `ALPHA *( ALPHA / DIGIT / "+" / "-" / "." ) ":"` and compare ASCII case-insensitively, without normalizing any other URI bytes or decoding percent triplets. Notebook scheme uses the same rule and must use the *held enclosing notebook URI*, never the opaque cell URI. Any pattern-dependent positive applicability stays `UNKNOWN` until a separate exact glob/path contract; no host glob or guessed path. Known false filters do not become unknown merely because another AND operand is unavailable; known true language+scheme without pattern may support. Across filters OR permits one established supported filter, except that an independently known malformed array element invalidates the complete selector.

Selector identity is additive: common length-prefixed V2 ordering, but first component `ADR0011-GENERIC-EXACT/3`, method profile `GENERIC_LSP_REFERENCES_EXACT_V3` or `GENERIC_LSP_DEFINITION_EXACT_V3`, and digest of the selected V3 method policy. V3 SOURCE retains its separately accepted SOURCE-artifact and transaction-domain sub-preimages and SOURCE-only TX suffix, changing its outer domain/profile/policy components. All 36 role-specific vectors are recomputed; no V2 selector aliases V3. Keeping schema/transport V2 does not permit an unchanged V2 POLICY original to appear in a V3 role graph: exact V3 POLICY role/original selection requires separate B4-derived custody.
