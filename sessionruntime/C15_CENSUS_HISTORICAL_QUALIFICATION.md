# C15 historical census qualification record

This document preserves the former C15 v1/v2 catalog-generation procedure as historical evidence. It is deliberately outside Go `_test.go` discovery and is **not an accepted in-repository update procedure**. The checked-in catalogs under `testdata/c15-census-v1` and `testdata/c15-census-v2` are immutable historical pins. Do not regenerate, repin, or overwrite them from current production source.

Any future census must be an explicitly invoked manual tool, must require a caller-selected disposable output directory, and must refuse to write either historical fixture directory by default. Its output requires independent review before any successor artifact is accepted.

## v1 historical procedure

The former opt-in command was exactly:

```sh
C15_REGENERATE=1 go test ./sessionruntime -run '^TestPrivateB4C15RegenerateOfflineCatalog$' -count=1
```

`C15_REGENERATE` was the environment variable. Without `C15_REGENERATE=1`, the test generated a census from then-current production Go source and compared it byte-for-byte with the pins. With the variable set, it atomically replaced `candidates.tsv`, `classifications.tsv`, and their SHA-256 sidecars under `testdata/c15-census-v1`. This mechanism was never an accepted in-repository update procedure.

The exact generation logic was:

1. Read and hash-check `operation-mapping.json`.
2. Run `discoverPrivateB4C15Candidates` over production Go source.
3. For each discovered candidate, write `<candidate ID>\t<candidate digest>` to `candidates.tsv`.
4. Classify the candidate as `excluded`. Use category `ephemeral-runtime` and rationale `<kind> <display> has no privateB4ByteAccountV2 owner operation at this site`; when `<display>` contains `.`, use category `external-library` and rationale `<display> is library behavior outside privateB4ByteAccountV2 custody`.
5. For each operation-mapping row, append `<site ID>\t<sha256(row fingerprint)>` to `candidates.tsv` and `<site ID>\tC15-owned\t<account operation>\t\t` to `classifications.tsv`.
6. A separate former test temporarily renamed the two generated TSV pins, generated twice, and required byte equality to demonstrate that generation did not read its own outputs.
