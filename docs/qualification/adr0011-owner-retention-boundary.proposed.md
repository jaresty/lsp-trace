# ADR 0011 owner-side method capture — proposed boundary, not a receipt

**Status: HISTORICAL OPTIONAL FRAME DIAGNOSTIC / UNFROZEN; same-process resistance and mandatory exact-frame gates superseded by ADR 0011's CALLS-parity decision.** This document describes an executed private falsification prototype, not the required production method-transaction path, retained method receipt, privacy policy, replay authority, terminal-member ledger, query-target identity, or occurrence admission. [ADR 0011](../adr/0011-versioned-definition-reference-grouping-evidence.md) keeps `authority=0`, `accepted=false`, `completeness=UNKNOWN`; historical CALLS-only behavior is untouched.

## Source-backed dependencies

1. `internal/adr0011methodtransport/transport.go`: `Runtime` is an interface, and `Transport.Execute` forwards method, copied params, deadline, message bound, and byte bound to `Runtime.RoundTrip`. It currently sets neither D/R raw-frame opt-in. A fake `Runtime` can return self-consistent observations; the transport cannot assert who acquired them. Its `LocalWriteCorrespondence` is diagnostic only.
2. `sessionruntime/sessionruntime.go`, `request_write.go`, `response_read.go`, and `method_frame_correspondence.go`: the real `Manager.roundTrip` exclusively owns the child stream, constructs the request key, observes a completed framed write, and selects a response only after matching the key. By default it keeps only the completed request frame's digest/length; a subsequent bounded, default-off D/R opt-in can now retain exact request-frame bytes **only after a keyed successful response**, and exact D/R response frames are separate opt-in private copies. Neither capture is immutable or owner-published. The shared verifier checks request/write/read/frame/result byte agreement, but `TestMethodFrameCorrespondenceDoesNotAuthenticateReplay` proves that replacing the raw frame, decoded result, and read digest consistently can still pass. Local consistency cannot distinguish a real owner event from a copied value.
3. `internal/publication/selector.go` and `internal/publication/boundfile.go`: an explicitly opened, owner-only `publication.Root` pins a directory capability and can publish bounded bytes no-replace. A committed publication can have a non-success late `VerificationStatus`; committed bytes and digest prove *what was retained*, not *who produced it*. A root pointer supplied to arbitrary code is not owner provenance. `internal/captureset/publication.go` is for exact admitted V5 constituents and must not be reused as a D/R receipt.
4. Bounded structural context `sc_830effb3fe4bcad3eb0ed12f7f0e521e`, exact READY `project` generation 1, reports `Transport.Execute` to `RoundTrip`; graph `authority=0`, `source_graph_complete=UNKNOWN`, four external calls omitted. The source statements above, not that bounded graph, ground this proposal. A preceding symbol-only preflight returned `TARGET_NOT_FOUND` with `ENUMERATION_TRUNCATED`, not absence of implementation.

## Current parity route and optional diagnostic boundary

The required successor is a bounded immutable **canonical query/result transaction record** bound to the managed method, exact query occurrence and validated params, session/generation/key, selected capability/provider-as-reported, result presence/payload or explicit withholding, policy, terminal member ledger, and privacy limits. Verify those bindings and result ordinals offline without requiring exact LSP header/framing bytes; the manager path must still bind a keyed successful response and not accept a fake transport observation as authority. A result digest alone cannot supply missing payload for new admission. The 24-hour frame replay window and deletion probe are **optional diagnostic tools**, not a prerequisite for production method receipts, D/R admission, or Leiden. The user selected a private, default-off, bounded immutable canonical payload retained through an explicit qualification-review lifecycle and removed by reviewed decision, **not** an automatic 24-hour expiry; exact limits, owner/root, review/removal accounting and versioned policy remain unfrozen.

The following historical frame prototype remains useful for falsifying local wire substitution; its root and frame capture are not mandatory for the parity route:

- **Mint at the manager, not from a result.** A test-only, default-off owner configuration would supply a pinned private root and a named, versioned privacy/capture policy to a concrete `sessionruntime.Manager`. The managed transaction path would select its existing separately bounded, default-off raw D/R request/response frame options under **owner configuration**, not a transport-supplied result. After keyed successful acceptance and local byte correspondence, it could publish those exact request and selected response frames with its *manager-derived* session, generation, key, method, bounds, and terminal transport state. The existing in-memory request-frame option is only a prerequisite, not an owner publication hook; reconstructing from `Params` is not exact wire-byte capture. Do not accept an external `RoundTripResult`, arbitrary frame bytes, or a caller-selected selector as publication input. The existing method-transport interface and public CLI/MCP must not acquire a publication capability.
- **Separate assertion levels.** Test-owned execution may show that the configured manager emitted a publication after observing its child stream; that is an owner-path observation in the test's trust model, **not** provider authentication. No code-level API can stop a sufficiently privileged same-process actor holding the same root from independently publishing bytes. Offline digest/codec verification alone establishes byte integrity and consistency, not owner provenance. An independently attestable owner identity would need a separately chosen trust anchor/verification channel and threat model.
- **Private by construction, fail closed.** Root, policy, and positive frame/request/work bounds must be explicit at owner construction; absent configuration writes nothing. Before any write, reject unselected method, missing accepted matching response, error/failure, stale generation, over-cap frame, missing completed write/read, or failed correspondence. A publication failure or late verification failure cannot be reported downstream as a receipt or a complete method acquisition. The raw request URI/position/params and response locations are sensitive: a 24-hour private, default-off exact-frame **replay window with lazy cleanup** is now selected in [the private retention proposal](adr0011-private-method-retention.proposed.md); root access, numeric limits, deletion implementation, diagnostics, and redaction remain unfrozen. This decision does not authorize a production publisher. No raw bytes, paths, URIs, or error text enter public failures.
- **Candidate bytes, not receipt identity.** A future candidate codec would bind the exact framed request and response bytes; manager-owned session/generation/key/method; selected bounds, capability observation, provider-as-reported metadata, privacy and method-policy IDs; exact presence of result/error; and separate retained/withheld dispositions. Canonical serialization, collision-safe request identity across restart, duplicate-key handling, revision/document and source-custody bindings, and the receipt's independent verifier are unfrozen. Content-addressed no-replace publication may retain *a candidate artifact*, but a successful digest or selector does not upgrade its authority.

## Executed test-owned prototype (not an owner receipt)

`sessionruntime.Config.methodCandidateTestHook` is package-private and default nil; no production host config, public selector, or `adr0011methodtransport.Runtime` setting can enable it. On the concrete manager's post-acceptance D/R success path, it receives independent copies of the bounded exact request and response frames plus manager-local key/write/read observations only when local byte correspondence passes. Named guards cover both methods, references `null`/`[]`/repeated locations, missing caps, other method, over-cap, error, unmatched-only, timeout, stale, malformed, short write, default-off, and an early-hook RED/GREEN control. An external-package fake runtime can report transport success but cannot configure the package-private hook through `sessionruntime.Config`; this is a Go surface boundary, **not** same-process producer authentication.

The hook's `_test.go` consumer encodes an explicitly test-only `v0` candidate, publishes it to a test-owned 0700 `publication.Root` with `PublishBoundFile`, requires `VerificationStatus=VERIFIED`, reads exact bytes back, and checks no-replace behavior. A closed-root publication failure returns no publication receipt and does not change the method transport outcome. The test candidate's self-describing fields and verification closure can be reproduced by a privileged actor; neither the immutable bytes nor the manager-local callback produce an independently owner-verified or provider-authenticated method receipt. Late committed-verification failure is part of the underlying publication API's contract, not qualified as an ADR 0011 receipt by this prototype. Raw sensitive bytes never enter public failures; the test-only codec is not registered as a schema or product retention policy.

## Decisions required before production wiring

**Current threat-model decision (user decision): CALLS parity, with optional exact frames.** Same-process forgery is a **disclosed, unmitigated limitation**, no longer a blocker requiring independently authenticated ownership before bounded D/R structural grouping. A privileged actor with manager/root access can create self-consistent fraudulent records. The existing test hook, candidate codec, and `publication.Root` readback remain owner-path test observations, not production method receipts; neither a future same-process receipt nor its verifier may claim producer/provider authentication. Only a later, separately authorized stronger trust boundary could make such a claim.

**Deployment decision (user decision): isolated-owner prototype deferred.** The deferral remains in force. No production method receipt, terminal ledger, query-target admission, D/R occurrence, grouping policy qualification, or public D/R selector exists as a consequence of parity. Independent Describe acceptance and provisional ledger/identity work remain separate.

### Historical stronger-owner feasibility gate — not required for current CALLS-parity scope

At the inspected checkout source, `cmd/lsp-trace-mcp/main.go` constructs `sessionruntime.Manager` in the host, `internal/managedprocess/process.go` creates and returns the child's stdin/stdout pipes to that process, and `sessionruntime.roundTrip` writes/reads those streams directly (`sessionruntime/sessionruntime.go:721–767`). Bounded structural request `sc_edbf5d84d3904428f99179b9691062a4` reports that local `roundTrip` neighborhood with `authority=0`, `source_graph_complete=UNKNOWN`, and 28 external calls omitted; it does not authenticate pipe custody or exhaustively prove call-site ownership. The source and the test-only substituted-query publisher establish the present local ceiling. Local Darwin process-group supervision expressly does not prove anti-escape, owner-death cleanup, descendant containment, or `VERIFIED` (`internal/managedprocess/process.go:18–21`).

A separate signer that accepts a host-supplied frame, decoded result, manager-local digest, or root selector would still attest an input chosen by the in-scope adversary. Moving only publication or a signing key behind IPC does **not** meet this threat model. A candidate owner boundary would need to independently control child creation and the exclusive read/write stream or establish a separately qualified OS observation of those exact streams; validate the selected method, exact generation/key/query, capability and bounds at that boundary; and keep any provenance authority inaccessible as a general sign-these-bytes operation to the MCP host. A second same-user process or 0700 root alone is not an established security principal. No OS isolation mechanism, key management, verifier trust anchor, or migration of current session/lifecycle ownership is selected here. Provider-supplied content remains server-reported even if an isolated owner later attests that it observed its bytes.

**Required falsification only if stronger owner authentication is separately selected:** demonstrate, under a named OS/permission adversary model, that a compromised MCP process cannot read/replace the owner's secret or child stream, supply forged request/response frames for attestation, replay a prior generation/key or substitute a URI, or publish a valid owner claim merely by holding its own root. Demonstrate one genuine bounded method transaction from the selected owner and independent offline verification against a pinned owner identity. Separately select privacy/retention and redaction for query and response frames, including withheld evidence; retention caps do not bound live wire, CPU, or allocation. Without those tests, do not claim independently authenticated owner provenance. The current parity path still requires a production-bound immutable **canonical query/result** transaction record with a bounded offline *consistency* verifier and separately qualified privacy, query-target, terminal ledger, occurrence, and grouping-policy contracts before D/R admission. Raw framed LSP bytes and stronger owner authentication are not prerequisites.

1. Which canonical query/result payload and immutable binding can the managed acquisition path produce, and which offline verifier checks exact method/query/session/generation/key/policy/result identities and ordinals? A root and digest establish no independent authentication; a stronger owner trust anchor is a separate future decision.
2. Which privacy and resource policy governs the **mandatory canonical transaction payload**, its replay availability and withheld/expired dispositions? The separately selected 24-hour exact-frame replay window with lazy cleanup applies only to optional diagnostics; it does not set mandatory transaction retention. Bounds on stored bytes do not bound live wire/CPU/reader allocations.
3. How is the eventual **production** query/result record distinguished from the present test-only frame observation, with manager-bound keyed response, payload, and independently checkable byte/identity consistency? Neither form may claim independently owner-verified provenance under parity.
4. Separately select one terminal request-member denominator and reference query-target identity before `COMPLETE_EMPTY`, `COMPLETE`, or any typed occurrence. This proposal does not authorize grouped-edge integration, Leiden, public selectors, or a resumed Describe campaign.

**Current stop rule:** Do not add a production transaction publisher until a privacy/retention policy for the **canonical query/result payload**, an immutable codec, and offline byte/identity consistency verifier are selected and qualified. Do not re-label `VerifyMethodFrameCorrespondence`, `LOCAL_MATCH`, the test hook, or a bare publication digest as a method receipt; never describe a parity receipt as producer-authenticated. Optional exact-frame retention has its own private policy and may be disabled without blocking the transaction route. The stronger-owner tests above apply only if stronger authenticity is later selected. Query-target identity, terminal accounting, typed occurrence admission, and qualified Leiden policy remain separate mandatory gates.
