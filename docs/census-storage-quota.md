# Owned-store retained-content quota v1

## Contract, not a disk quota

New ordinary census stores use `durable-quota-v1`, default **2 GiB**, configured with initial `--storage-bytes`. This limits **application-owned regular-file content lengths plus outstanding storage reservations**, not filesystem allocated blocks. It is independent of existing logical H/work/native/semantic spending. None of those profiles is increased or refunded.

The scope is the complete configured store tree: policy/ledger, configs, immutable objects, head/CAS artifacts, native and child execution journals, selected/original evidence, semantic delivery/state, publication, named temporaries and regular orphans. Bound-file writers reserve twice the payload before creation/write to cover Darwin's anonymous original plus published clone and old/new CAS overlap. Direct publication reserves every artifact plus a bounded 16 KiB manifest envelope before mkdir/write. Hard-link publisher reservations conservatively include two path lengths. Zero-length locks/directories contribute zero content bytes; their filesystem metadata is **not** bounded by this capacity.

Filesystem `st_blocks*512` is separately measured for regular files and sampled anonymous descriptors. APFS clones/snapshots can share allocation: this sum is neither exclusive device consumption nor a hard allocated-block bound. In small-file controlled exhaustion tests allocated-block sums can exceed the configured content capacity. Do not advertise this feature as preventing ENOSPC, an OS quota, or a machine-wide storage limit.

Provider/source trees, compiler/model caches, external executables, external actor transports, stdout/stderr consumers, and unrelated stores are outside scope. The local executable/model staging lane is not qualified under a quota store and explicitly refuses placement there. The ordinary connected supplied-response lane does not use it. The separate network model acquisition/download writer is also not qualified here; the staging guard is not proof that the downloader is quota-aware. Darwin is the tested ordinary CLI platform; Linux low-level implementation is not execution-qualified by Darwin tests; other platforms reject quota configuration.

## Accounting and concurrency

For each integrated materializing write, while holding a store-wide cross-process flock:

```
observed regular-file lengths + uncertain/retirement reservations
    + prospective write upper bound + 65,536 control bytes <= frozen limit
```

The same stable `.storage-quota-v1` inode holds the lock and a fixed 4,096-byte checksummed record. The record is included in observed file lengths. It is never appended or renamed. Generic publisher/CAS-temp/removal APIs cannot target its reserved name. Nested quota configuration is refused. Initial configuration is exclusive and allowed only in an empty store; a partial initialization is not repaired automatically. An existing limit must match exactly. The limit is shared by all jobs, not a per-job entitlement. API callers opt in by calling `publication.ConfigureStorage(ctx, root, publication.DefaultStorageBytes)` (or an explicit limit) on an empty root before `DurableStore.Create`; historical direct API creation without configuration remains explicitly outside quota enforcement.

Reservation debt is synced **before data effects**. The exclusive storage lock lasts through the integrated write, verification, descriptor cleanup and bounded rescan, independently of job execution claims. CAS rename and private removal also take a zero-growth storage reservation so namespace reductions cannot race a scan; target locks are acquired only after the storage lock, avoiding lock-order inversion. Immediately before rename, CAS rereads the actual current predecessor under that same storage lock and checks its bounded bytes, digest and length (or real absence), independently of the earlier observation/scheduling seam. A changed predecessor refuses with `ErrStalePredecessor` before rename; the temporary and conservative retirement remain charged. Equal-content replacement by a different inode is permitted by the content-addressed predecessor contract: its actual verified length must equal the already reserved retirement amount, and the intervening remover separately reserved its old inode. Concurrent processes therefore cannot both spend the same free capacity. A clean verified completion releases only its own write reservation. Before head replacement or private-file removal, the old length is separately reserved permanently: another process can retain an open descriptor after unlink, invisible to a directory scan. This `RetirementReservedBytes` charge is conservative even when all readers actually closed, or a later replacement failed. No cross-process close proof/reclamation mechanism is provided. Errors/uncertain closes/interruption retain reservation debt, even when cleanup appears to have removed all files; this conservative version offers no debt-reclamation command. Materialized files plus debt may consequently double-count uncertain work. No restart scan turns uncertainty into free space.

The 64 KiB control margin is unavailable to ordinary data reservations. The fixed ledger's reservation-completion updates do not grow the file, status/refusal reporting goes to the caller rather than a growing store log, and verified unlink cleanup adds no content bytes. This margin is **not** a guarantee that semantic/native completion succeeds after data capacity is exhausted: an already claimed attempt may remain spent/uncertain under the existing lifecycle. It does not fund a new lease, retry or publication.

Uncertainty/torn checksums fail closed. Sync/readback is not a new power-loss/crash-durability guarantee beyond the underlying existing filesystem operations. No store evidence is silently deleted.

## Reopen and observation

Reopen/status/reservation scans use descriptor-relative no-follow traversal, batches of 128 entries, at most 65,536 entries and depth 32. Every regular orphan is counted regardless of filename. Symlinks, nonregular files, multiple hard links, wrong owners/nonprivate modes, inconsistent identities, traversal limit exhaustion and corrupt/truncated ledger records refuse. Reads verify bounded metadata and the quota checksum, **not every orphan's content hash**; existing custody readers remain responsible for object integrity. A cleanup that cannot fund the old-inode retirement reservation can also refuse rather than promise reclaimed capacity. A hard-link orphan after interruption can therefore make the store unavailable rather than being normalized or deleted.

`Storage` reports frozen Limit, ControlReserve, FileBytes, AllocatedBytes, Files, Entries, ReservedBytes (total), RetirementReservedBytes, UncertainReservedBytes (excluding retirement), AvailableBytes, PeakReservedBytes, SampledPeakFileBytes, SampledPeakAllocatedBytes and Reservations. PeakReservedBytes includes conservative outstanding debt/copy bounds; it is not actual disk use. Sampled peaks observe instrumented writer descriptors at successful write/clone points and scans (not arbitrary outstanding reader descriptors, which are conservatively reserved); they are not an exhaustive syscall trace, especially on failing paths. Current status contributes a fresh sample without mutating the ledger. Counters are bounded fixed-width metadata, not authority to execute.

Locks are held only for storage writes, not native queries, actor waiting or whole commands. Context-aware direct operations cancel while awaiting the lock; legacy bound-file entry points use a one-second storage-lock/scan window. This does not preempt blocking filesystem syscalls. Existing native/semantic active deadlines remain independently enforced. No pacing scheduler or throughput guarantee is added.

## Trust boundary and limitations

Enforcement covers the current integrated cooperative writers; mixing older uninstrumented binaries into a quota store is unsupported. It does not cover arbitrary `os.WriteFile`, a malicious process with the same UID, direct device writes or a privileged administrator. Unexpected outside files are charged or refused on the next scan; external actors can already exceed the limit before that observation. Application reservations cannot enforce an OS-level guarantee against such writers. No authenticated policy signature is claimed by the checksum.

Historical populated unconfigured stores remain historical no-quota stores; configuration refuses to upgrade them. Returned exact `--store` operands select the configured store regardless of HOME/current directory. For new jobs an environment-selected legacy store acts as a parent for the new namespace, not as permission to migrate its historical contents. A moved/substituted ordinary reserved namespace or already pinned configured capability is refused rather than silently reverting to uncapped writes. An uncooperative outside writer deleting the only policy marker from an arbitrary API-selected directory is outside this boundary; do not treat the checksum as an OS enforcement mechanism.

Quota exhaustion preserves already accepted immutable prefixes. It does not guarantee recoverability of an in-flight native/semantic attempt or make a READY metadata eligibility an advance storage grant. Failed claims retain existing spent/uncertain semantics. No automatic extension, reset, retry, oldest-file eviction or orphan cleanup exists.

Controlled test publications remain PROVISIONAL, Authority 0, Accepted false. Mechanical semantic fixtures do not establish independent judgments, real-provider qualification, arbitrary population support or accepted feature identity.
