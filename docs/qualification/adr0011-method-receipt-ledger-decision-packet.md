# ADR 0011 method receipt and terminal-member decision packet

**Status: UNFROZEN PRIVATE PROPOSAL.** This is a decision and falsification packet, not a schema, issued or verified receipt, request classifier, admitted occurrence, grouping input, policy qualification, or public surface. [ADR 0011](../adr/0011-versioned-definition-reference-grouping-evidence.md) controls. In particular, `authority=0`, `accepted=false`, `completeness=UNKNOWN`; historical omitted selectors remain `CALLS_ONLY`. The [transaction draft](adr0011-method-transaction-receipt-draft.md), [seam audit](adr0011-method-receipt-seam-audit.md), [private result grammar](adr0011-method-result-contract-v1.md), and [fixture matrix](adr0011-method-fixtures.md) supply the current scoped inputs. No proposed field or equation below admits an occurrence.

## Decision A: who can assert a method transaction?

**Assumption and basis:** `TransactionObservation` copies caller declarations and `Runtime`-reported metadata/counters; a fake `Runtime` can substitute them. `CompletedRequestWrite` observes a manager-local owned framed writer returning nil. `LOCAL_MATCH` checks a reconstructed frame against that local observation, not the raw parameter formatting or a provider's read. A supervised test peer can report a method trace but is not an arbitrary provider's authenticated statement. Therefore none of these values alone is a receipt or proves provider custody.

Under ADR 0011's CALLS-parity decision, an eventual receipt must specify a **managed acquisition path and an offline canonical query/result byte/identity consistency verifier**, not merely a hash. Exact framed LSP request/response retention is an optional private diagnostic, not a receipt or Leiden admission prerequisite. Neither path nor verifier authenticates the producer against a privileged same-process adversary; that limitation must remain explicit on every derivative. The candidate owner would have to bind one selected method and policy, exact validated query parameters and query occurrence, exact managed session/generation, selected capability observation, owned request key, completed framed write (if performed), response keyed to that request as acquired by the owned reader, exact bounded result payload or an explicit privacy disposition that forbids new occurrence admission when replay evidence is unavailable, optional raw response-frame diagnostics, typed terminal failure, position encoding, revision/document evidence at its actual custody level, and privacy/resource policies. A provider's initialize advertisement and returned locations remain *server-reported* even if a trusted manager attests that it observed their bytes. An owner cannot promote caller-asserted revision or document version into provider-verified custody.

**Unselected decisions:** manager-bound acquisition configuration (not an independent owner trust anchor); registration and publication mechanism; canonical receipt schema/ID/digest and allowed omissions; how the managed reader binds the accepted keyed response and canonical result payload to the write and generation (raw frame retention optional); atomic retention and replay verifier; capability-observation timing; revision/document evidence and its custody; bounds and their coverage (including actual resource consumption); private raw/error retention, withholding, and diagnostic redaction. A 24-hour, private, default-off exact-frame replay window with lazy cleanup has since been selected in [the retention proposal](adr0011-private-method-retention.proposed.md) **for optional diagnostics only**. The mandatory canonical query/result record needs its own separately selected privacy and replay-availability contract; diagnostic deletion/recovery cannot block D/R grouping. A self-hash, a manager-local completed write, a peer trace, or a fake-runtime replay cannot decide these. A successful `RoundTrip` alone is insufficient. No server error code, including `-32601`, maps to ADR `UNSUPPORTED` without a separately frozen method policy.

**Freeze gate A (consistency, not authentication):** a candidate production receipt and offline verifier must reject independently changed URI, range, raw parameter bytes where required by the selected identity, method, session/generation, request key, capability observation, keyed response identity and exact retained result payload, provider/adapter/policy, revision/document custody, and retained artifact bytes. If optional exact-frame diagnostics are selected, reject independent frame substitutions within that diagnostic contract. The verifier must preserve absence versus present-empty results and withhold prohibited raw/error data. Demonstrate accepted same-input replay and each mismatch against a pinned managed-path implementation; fake-runtime metadata and test-peer traces cannot substitute for that path. A coordinated same-process replacement of all compared fields may still pass: explicitly report this as `NO_PRODUCER_AUTHENTICATION`, not as an independently verified owner fact. Until the production codec, private publication, and replay verifier exist, all corresponding fields remain observations, not verified byte/identity bindings.

### Private canonical query/result replay probe (unadmitted)

`internal/adr0011methodresult.BuildCanonicalCandidate` now builds a bounded private `v0` candidate from a successful method transport with `LOCAL_MATCH`, required query metadata and exact copied params/result JSON. `VerifyCanonicalCandidate` checks closed canonical serialization, byte digests/length bounds, session/generation/key identity, replayed method parameter grammar, exact query coordinates, method-result parsing, `null` distinction, and item count **without exact wire-frame retention**. A supervised managed-peer test covers definition `null`, references `[]`, and two repeated reference locations while both raw-frame captures remain default-off; mutation and query substitution are rejected. A deliberately coordinated same-process replacement of result bytes, metadata and candidate digest passes, proving this codec does **not** authenticate its producer. Its source observations are still replayable from a fake `Runtime`, and the `v0` candidate is **not** a production manager-published receipt, terminal-member ledger, independently established reference query target, admitted occurrence, or Leiden input. Canonical transaction policy and retention of its result payload remain to be frozen.

## Decision B: what is counted at each layer?

**Assumption and basis:** the private result parser preserves zero-based returned-item ordinals on success and returns zero partial items on a malformed member. A syntactically complete `Location[]` can contain three elements even if item 1 is malformed; `len(Parse.Items)` is then zero, not three. ADR 0011 separately requires a declared request denominator, an evaluated-member count, and exactly one terminal outcome for each member whose evaluation began. Therefore these counts cannot be substituted for one another.

| Candidate quantity | Meaning and allowed observation | Must not imply |
| --- | --- | --- |
| Query units `Q` | Explicit, owner-declared exact query occurrences submitted to this bounded acquisition; the current private transport issues one method call, but no owner receipt declares an admission denominator. | That a response was received, evaluated, or complete. |
| Result elements `E` | Number of returned elements in a **complete bounded result value**, if its top-level shape permits a count: `null` and `[]` yield 0; scalar definition `Location` yields 1; an array yields its actual element count, including malformed elements. A partial/truncated/invalid top-level value has `E=UNKNOWN`, not a guessed final count. This is provisional raw-result accounting, not an authenticated count. | `Q`, terminal evaluation, admitted occurrences, or query absence outside the exact request. |
| Parser items `P` | `len(Parse.Items)` on successful parsing; malformed parsing returns no partial items and a failure ordinal. Valid repeated items retain independent ordinals. | A terminal member denominator or admitted multiplicity. |
| Terminal acquisition members `N`, begun `B`, terminal `T`, admitted `A` | **Provisional query-member unit; declaration and verifier unselected.** The eventual owner-declared `N` and immutable terminal member ledger must bind the same exact request and bounded result. Conditional query integrity is `0 ≤ T ≤ B ≤ N`; an outcome for an unbegun query member is forbidden. Once result-element evaluation is independently owner-bound, `0 ≤ A ≤ E_T ≤ E_B ≤ E` applies when `E` is known: one terminal query may admit multiple distinct occurrences. Without complete bounded `E`, that element-denominator equation is unavailable and neither `A` nor completeness may be inferred from a smaller observed count. These equations are necessary, not evidence that `N` was declared truthfully or that an occurrence is eligible. | `N=E`, an undeclared `N=Q`, `A=P`, or request `COMPLETE` without independent custody/identity and the selected aggregation policy. |

**Provisional model 1 for falsification, not Freeze B:** A terminal acquisition member is one exact **predeclared query occurrence**, not a response frame or returned location. For the current one-query D/R transport, a future owner-bound declaration would give `N=Q=1` *before* invocation; absent that declaration `N` is unestablished even if the transport returned success. A preflight failure or unsupported capability with no evaluation has `B=T=0`, not an invented `EMPTY` member. Merely writing a request does not begin member evaluation; `B` requires independently owner-bound evidence that evaluation of provider output actually began. `T` counts exactly one terminal query disposition per begun member, including failed/limited/malformed dispositions when appropriate; thus `T=N` alone never proves well-formed completeness. A successfully evaluated, verified `null` or `[]` query has a provisional `EMPTY` query disposition, `B=T=1`, and **separate** result-element count `E=0`. Until the owner declaration, invocation/evaluation, complete response, privacy bounds, and verifier are selected and proved, these numbers are conditional examples, not recorded ledger facts. Candidate model 2 (zero result-member outcomes plus a separate terminal query marker) is not selected because it adds another marker whose absence is indistinguishable from an unevaluated empty query without the same owner verification.

**Separate result-element subledger:** When a complete bounded top-level result establishes `E`, account for element ordinals `0..E-1` separately from query members. Track begun element evaluations `E_B`, terminal element evaluations `E_T`, and each evaluated element's single exact ordinal and outcome, with `0 ≤ E_T ≤ E_B ≤ E` when `E` is known; no outcome for an unbegun element and no invented element for `null`/`[]`. A single query with two independently admitted repeated locations can have `N=T=1`, `E=E_T=A=2`; an `A ≤ T` check would incorrectly collapse or reject it. A scalar definition has `E=1`; repeated locations remain distinct ordinals. A syntactically complete three-element array with malformed element 1 can have `E=3`, `E_B=E_T=2`, and no outcome for element 2 if evaluation stopped at 1; the query disposition is `MALFORMED`, not `EMPTY` or `COMPLETE`. The current parser returns `P=0` on that whole-result failure, while `ObserveEnvelope` can provisionally report `E=3`. When a bound or truncation prevents a complete safe count, `E` is unknown, not a smaller denominator. No provisional element observation establishes its own owner custody, admission, or request status.

**Falsification cases (conditional future owner-bound ledger, not fixture verdicts):** `null` and `[]` require one evaluated `EMPTY` query and zero element outcomes; a declared but uninvoked query and a timeout before any evaluable provider output require `B=T=0`, even though both have no returned locations. A malformed second member after a valid first requires the recorded ordinal-1 failure, no fabricated ordinal-2 evaluation, and ADR `MALFORMED` precedence. An over-bound or truncated result cannot shrink `E` into a complete result or yield `EMPTY`. A valid references array without an independently admitted query-target identity may reach a terminal non-complete query disposition, but cannot admit `REFERENCES_SYMBOL` or be labeled `COMPLETE_EMPTY` just because admission is zero. A complete array of valid repeated members must preserve every response ordinal and cannot use `P` as `N` or `A`. Falsify this proposal by showing a bound exact query that needs more than one terminal *query* outcome, an empty query that cannot be distinguished from non-invocation with owner-bound evidence, or an element whose ordinal/outcome cannot be reconciled without inventing a response member. The private `internal/adr0011methodresult/candidate_ledger.go` validator now checks structural consistency of caller-supplied candidate declarations and begun/terminal query and element events (at most 16 queries). Its fixture tests distinguish `N` from `E` and `P`, preserve repeated ordinals and malformed second-of-three accounting, and reject invented empty, over-limit, unbegun, duplicate, and post-failure events. **This is not owner declaration or terminal-member custody:** a caller can supply self-consistent false declarations, envelope observations, or begin flags; no request outcome or occurrence is emitted. A separate `CheckCandidateTransactionLedger` now joins **one** replay-checked unadmitted query/result candidate to one supplied declared query and terminal member. It checks method/session/generation/params-digest/query-occurrence equality, exact result form and element count, `null` versus `[]`, and all valid element ordinals without conflating `N=1` with `E`. Managed-peer tests cover zero elements and two repeated references; mismatched counts and query substitution fail. It returns only error or nil: no references target identity, `A`, `COMPLETE_EMPTY`, admitted occurrence, or Leiden input, and the supplied declaration/begin/terminal assertions remain untrusted.

**Conditional request-outcome guard:** only a verified, bound, well-formed request/result with the declared query denominator fully evaluated (`T=N` and every query disposition well formed), every returned element evaluated and well formed within the independently established `E`, no malformed required output, and independently verified admission facts can be considered for `COMPLETE` or `COMPLETE_EMPTY`. `COMPLETE_EMPTY` additionally requires a verified `A=0`; `COMPLETE` requires `A>0`. Apply ADR 0011's existing precedence to revision/policy mismatch, unsupported capability/method, pre-output cancel/timeout/resource/provider failure, malformed required output, and retained-but-incomplete evaluation. A parser success or zero-length result is not a request verdict. For a malformed second element, any separately admissible valid prefix may remain diagnostic, but later unbegun elements get no terminal outcome and ADR `MALFORMED` takes precedence over `PARTIAL`.

## Counterexamples that the proposed contract must separate

Each row is an independently falsifiable *future* receipt/ledger test, not a claim that the test has run or that its indicated disposition is implemented.

| Class | Counterexample | Required boundary |
| --- | --- | --- |
| Replay | Same method/result bytes and `LOCAL_MATCH`, but a fake `Runtime` replays a genuine result under a different declared URI or query coordinate. | Reject owner/query substitution; neither match nor hash authenticates provider custody. |
| Revision | Same URI/range and response with a changed workspace revision or custody (`CALLER_ASSERTED` versus verified). | Do not merge identities or upgrade asserted revision to verified. |
| Document | Same range under a different document version/digest or encoding. | Reject incompatible query-target/source binding; no checkout fallback. |
| Privacy | Response exists but selected policy withholds raw bytes or an error message. | Distinguish withheld from absent; do not publish raw bytes, a forbidden digest, or a reconstructed success/`COMPLETE_EMPTY` verdict. Replay eligibility must be separately specified. |
| Bound | Reported counters are within limits while raw result/error message exceeds them, or a result exceeds candidate/work limits after partial evaluation. | Enforce each selected bound before exposing results or errors; record whether evaluation began. Private numeric limits and logical work do not establish total CPU/memory/live-wire limits. |
| Query target | References return valid locations without an admitted query-target receipt, or with a different URI/range/version. | `TARGET_IDENTITY_UNRESOLVED`; no `REFERENCES_SYMBOL` occurrence or inferred referenced identity. Source context cannot repair it. |
| Null | Exact successful definition `null` and a transport-success but absent raw result both appear to contain no parsed items. | Preserve raw presence and exact bytes; only the former is a well-formed zero-return result, neither alone is `COMPLETE_EMPTY`. |
| Empty | Exact references `[]` (with `includeDeclaration=false`) and capability absent both produce no locations. | Only the former is an invoked well-formed result; absent capability has no member evaluation and is not empty evidence. |
| Malformed | Complete three-element response: valid item 0, malformed item 1, valid item 2. Parser reports ordinal 1 and zero partial items. | Preserve `E=3` if independently counted; do not fabricate terminal status for item 2 if not begun, admit item 1, or infer `N` from `P=0`. ADR `MALFORMED` takes precedence for required malformed output. |
| Limit | A complete array has more items than the selected candidate limit, or ends before its closing bracket. | Do not truncate into a smaller complete denominator; distinguish known provisional array count (if safely counted) from `UNKNOWN`; never emit `COMPLETE`. |

**Freeze gate B:** select exactly one denominator/member model and closed terminal-member vocabulary; specify where `N` is declared and how the owner/verifier binds it to full, bounded response bytes and request identity. Independently test per-member ordinal/multiplicity, `B/T/A` balance, `null` versus `[]`, malformed second member followed by a third, limits before/after evaluation, and transport failures before any output. Existing managed fixtures test selected wire/parse facts; the new private candidate-ledger tests check untrusted structural balance. Neither tests owner-bound pre-invocation declaration or a verified terminal ledger, so this gate remains open.

## Definition-side candidate projection (not reference-target admission)

The private `ProjectDefinitionCandidates` now projects a replay-checked one-query candidate and balanced untrusted ledger into **unadmitted** query-to-server-returned-target proposals. A managed test peer exercises two repeated `Location` targets, two repeated `LocationLink` targets, and `null`: ordinals and distinct occurrence IDs survive, while equal returned targets share only a **transaction-scoped candidate target ID**. A references candidate and a substituted query ID fail closed. This neither identifies a canonical cross-query definition symbol nor admits `RESOLVES_TO_DEFINITION`; zero candidates is not `COMPLETE_EMPTY`. It cannot be reused to invent the pre-existing referenced-symbol identity required by `textDocument/references`.

`internal/adr0011sourcecontext.Build` only interns caller-supplied document points/spans; it has no independent document-symbol/definition method receipt or identity verifier. A source point or matching display span therefore cannot serve as a references query-target receipt. The user selected unique `textDocument/documentSymbol` selection-range containment as the first derivation path, under its own admitted method/source/version custody. A private `adr0011querytarget.SelectDocumentSymbolCandidate` now tests **only** the bounded hierarchical-result selection rule against a separately declared query: it checks all symbols, source metadata shape, nested ranges, unique selection-range containment, duplicates, flat-only/unknown shapes, byte/nesting/item limits, and query/version-sensitive candidate identity. It does not invoke or retain `documentSymbol`, authenticate a source digest, verify document version, or bind a production method receipt. Identical caller-controlled source digest changes can still produce self-consistent candidates. No candidate symbol ID is a canonical `referenced_symbol_identity`; admission and Leiden remain blocked until an independently bound document-symbol transaction, source supply, and query-target receipt exist.

## Admission stop

Receipt byte/identity consistency verification (not producer authentication), query-target verification, terminal accounting, and occurrence admission are separate decisions. Even a later verified complete method request does not yield a reference target from returned locations, a source body from a URI, a `CALLS` edge, or feature identity. Only independently admitted typed occurrences could eventually enter the shared bounded traversal; neither `Parse.Items`, `TransactionObservation`, nor `directedwalk.Walk` candidates constitute that input. Source-context supply and grouping-policy qualification remain separate. This packet makes no ADR outcome mapping, schema freeze, accepted feature inventory, Leiden admission, CLI/MCP enablement, or new execution authorization.
