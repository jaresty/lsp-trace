# Graph semantics

An edge means the configured language server reported a static incoming Call Hierarchy relation. It does not prove runtime execution, reachability on a deployed configuration, frequency, or whole-program completeness. Discovery proceeds from callee to callers, while each edge is serialized in execution orientation: caller to callee.

Completeness is bounded by server capability and responses plus visible depth, node, timeout, cancellation, and error frontiers. Unsupported Call Hierarchy never authorizes a generic-reference fallback. Cycles describe graph structure; they are not roots or proof of runtime recursion.

The qualification fixtures include `StaticButNotExecuted`, whose call is behind a branch normal fixture execution does not take. A server may still report that edge, demonstrating the distinction between static evidence and observed execution.

## Completeness and bounds

`summary.complete` is true only when every discovered node was expanded successfully or reached a natural terminal. It is false when capability, cancellation, timeout, server error, invalid response, or a safety bound prevents complete expansion. `summary.truncated` is narrower: it reports depth or node-count truncation, not every cause of incompleteness. Consumers must inspect `terminals`, `frontier`, and `diagnostics` rather than infer a reason from either Boolean alone.

For v3, the producer and offline verifier derive `traversal_complete` from the same canonical evidence rather than trusting the submitted Boolean: truncation, frontier entries, unresolved calls, seed failures, lifecycle diagnostics, or non-natural terminal reasons force false. Capability quality is likewise canonicalized. `advertised` comes from the capability response; `prepare_succeeded` means at least one prepared target was retained; `incoming_request_successes` counts distinct expanded nodes evidenced by call-edge callee endpoints or natural incoming-call terminals; deterministic edge/call counters are recomputed; and language-neutral verification fixes `cross_module_edges` to `UNKNOWN` rather than claiming a module model.

A terminal records a node that was expanded or intentionally stopped; a frontier records a discovered node that remains unexpanded. Reasons are stable machine-readable values defined by the schema policy. `MAX_DEPTH` and `MAX_NODES` identify user bounds. The global `--timeout` bounds the whole command and produces `GLOBAL_TIMEOUT` when traversal-wide time expires; `--request-timeout` bounds each LSP request and produces `REQUEST_TIMEOUT`. Cancellation surfaces as `CANCELLED`, and an interrupt causes exit status `130` after JSON emission when possible.

## Bounded slice semantics

A v3 slice starts in exactly one mode. `--from-file` begins with every recursively enumerated document symbol that the server accepts through `textDocument/prepareCallHierarchy`; repeatable `--at` and `--seed-file` begin with explicit prepared positions using the existing seed labels and provenance. Outgoing breadth-first traversal assigns each node its shortest server-reported distance from that deduplicated starting set. Nodes at exactly `--down-depth` form the exact frontier. A node reached before that depth is an outgoing terminal only when its `callHierarchy/outgoingCalls` request succeeds with an empty result. The existing incoming traversal expands the native-ID-sorted union of exact-frontier and outgoing-terminal nodes using `--up-depth` as its maximum caller depth. It does not expand upward from every discovered node. Both values count call edges, and zero disables traversal in that direction.

The `slice` object records the source URI, ordered shortest-distance layers, `frontier_node_ids`, `outgoing_terminal_node_ids`, `upward_start_node_ids`, and outgoing discovery relations by canonical native node/relation ID. `upward_start_node_ids` must equal the sorted deduplicated union of the other two sets. A null or failed outgoing response is not a server-reported leaf; timeout, cancellation, and node-budget truncation likewise remain truncation/failure evidence rather than outgoing terminals. Nodes and edges remain single native graph records. These fields preserve bounded discovery provenance but do not establish feature identity, runtime execution, source completeness, or relationships the server did not report.

Each successful slice seed records its deterministic causal closure in `reached_node_ids` and `reached_relation_ids`: bounded outgoing reachability from that seed's prepared targets plus bounded incoming reachability from only the upward-start nodes in that outgoing closure. Converging seeds may therefore share descendants, callers, and relations without duplicating global graph records. Failed seeds retain explicit failure and empty membership. For new-format slices, semantic validation requires the union of successful seed memberships to equal the deduplicated global node/relation sets.

Slice captures server stderr through the same process buffer as `incoming`. If initialization or opening fails before a graph can be published, captured stderr is relayed before the transport/lifecycle error. If a structured slice is incomplete or has an outgoing-request failure, captured text is retained and printed as a sensitive `server-stderr` diagnostic. The raw stream is not a standalone replay artifact, and ordinary complete runs do not retain it.

`SERVER_CALL_SITE_OUTSIDE_CALLER_RANGE` is a recoverable server-quality diagnostic when the caller, callee, call-site range, and deterministic relation identity remain valid. The relation and server ranges are retained unchanged, traversal continues, and this diagnostic alone does not make the slice incomplete or prevent selector publication. Invalid call-site ranges, malformed or unattributable callers, node-identity collisions, and dangling relation references remain fail-closed structural errors. `source_graph_complete` remains `UNKNOWN`; recoverable containment says nothing about source-wide or runtime completeness.

## V3 custody and identity

### Field authority

- Caller-supplied: provenance values, requested invocation configuration, original seed labels/positions, server command/arguments, and explicit environment names.
- Server-reported: capabilities, prepared targets, call edges, Type Hierarchy associations, document-symbol candidates, diagnostics, and opaque response data.
- Tool-derived: normalization, canonical IDs, per-seed memberships, counters, boundaries, sensitivity/evidence metadata, and semantic/exact-byte commitments. Each v3 portable locator records the source node and selection range, normalization method/version, and this tool-derived authority in machine-readable provenance.
- Custody-only: receipts establish their defined integrity/custody properties without authenticating caller claims, server truth, producer identity, or hidden inputs.

Every original `invocation.seeds` entry maps to exactly one same-label `seeds` result, including failures. A result's `reached_relation_ids` are primary only in the bounded sense that they are direct canonical call-relation IDs reached by that exact seed occurrence. They do not include transitive-only relations, discovery relations, or relations attributable only to another seed.

V3 preserves server-relative completeness, caller-to-callee call edges, zero-support discovery nominations, and valid zero-discovery output. Caller metadata and tool/server version provenance are explicitly `CALLER_ASSERTED`. Source identity is limited to successfully resolved seed URI/content-digest pairs and a domain-separated aggregate scoped `RESOLVED_SEED_CONTENTS`; failures never become identities, and no repository, clock, server, version, or workspace-wide truth is inferred.

New producers derive `execution_bundle_id` from normalized invocation provenance and repeat it on native relations and seed memberships so extracted records from one execution remain mechanically joinable. This common provenance does not make co-bundled relations independent observations and adds no confidence or support. Native relation kinds are closed to call relations, dispatch associations, and sibling candidates; derived membership kinds are also closed, and unknown values fail semantic validation.

Portable-locator provenance makes normalized source-location derivation deterministic and replay-verifiable. Matching locator values or provenance establish only that the same normalization rule was applied to the same recorded node/range identity; they do not establish runtime behavior or feature correspondence. Historical v3 documents may omit execution-bundle identity, tool/server authority classifications, and locator provenance; new producers emit them.

The embedded `semantic_commitment_digest` commits to canonical bundle meaning. The selected generation's `exact_serialized_bytes_digest` commits separately to exact serialized artifact bytes. With identical invocation inputs and server observations, canonical artifact bytes are deterministic; immutable generation directory basenames may differ between publications. Changing an invocation input such as `--output` may change invocation-derived bundle identity and therefore the artifact bytes. Its custody receipt also reports `directory_durability`: `CHECKED` records a completed directory sync, while `UNAVAILABLE_ON_PLATFORM` discloses that the runtime cannot request directory sync and therefore makes no directory-entry persistence claim. Replay records use `replay_input_content_digest` and `replay_input_manifest_digest`; process-context claims use explicitly named process-context digests. `lsp-trace verify PATH` recomputes the semantic and exact-byte commitments offline and emits no graph on success. It checks the structure and commitment of replay/process-context claims but cannot reconstruct hidden inputs. No digest authenticates who produced the bundle, signs it, proves source truth, confirms hidden process inputs independently, or upgrades unavailable directory durability.

## Traversal completeness and provenance

The v2 graph document is also the invocation receipt. Its `invocation` object packages the effective workspace, target, server command and arguments, and traversal limits. Its `tool` object identifies `lsp-trace`. Invocation provenance is caller-authoritative: the provenance flags for invocation ID, caller, source, source revision, server version, timestamp, and tool version are copied exactly, while omitted values are `"UNKNOWN"`. No invocation provenance is inferred from ambient process, repository, current clock, resolved path, language server, or CI state. These receipt additions do not change the stream contract: stdout remains one graph JSON document and diagnostics remain on stderr.

`evidence_semantics` states the claim ceiling directly. A call edge supports only that the configured server reported the canonical caller-to-callee relation. It does not prove runtime execution, feature identity, whole-source completeness, or independent source confirmation. Discovery relations nominate separate investigation and contribute zero call support. V3 assigns stable identities to all three relation families and separately binds each seed occurrence to the call relations and discovery evidence produced by that seed; a shared source URI does not collapse distinct seed occurrences.

V3 `process_context` embeds no inherited or explicit environment values and no working-directory path. Its cwd digest is computed from the cleaned absolute process path without resolving symlink aliases, so it does not establish filesystem-object identity across lexical cwd aliases. Its role-specific process-context digest fields record tool-derived claims for the effective inherited-plus-override environment, cwd, and explicit environment names, plus the effective variable count and explicit redaction state. The sensitivity policy's `automatic_redaction: false` means these omissions are specific projection rules, not a promise to scrub arguments, names, paths, opaque data, diagnostics, stderr, or transcripts. These fields bind the issuer's execution-context claim into the semantic receipt; offline verification checks their structure and receipt commitment but cannot independently reconstruct or authenticate hidden process inputs. `replay_input_manifest` separately records source, protocol-transcript, and stderr artifacts with explicit `PRESENT` or `ABSENT` state and role-specific replay-input digests.

Within that document, `evidence_receipt` is the evidence-accounting envelope for optional discovery nominations and associations. Every projected record is a discovery nomination with zero support contribution. Its domain-separated stable identity denotes the caller-supplied source revision, relation kind, direction, locator, and semantic endpoints—not its array position or discovery order. Consumers must not count these records as call edges, caller support, or proof that a nominated or associated symbol participates in execution.

`trace_receipt.content_digest` commits to the canonical compact v2 graph content with `trace_receipt` omitted. The exclusion avoids self-reference. A matching digest proves that the receipt content is unchanged under this encoding; it does not establish that caller-supplied provenance is true or promote structural evidence into runtime evidence.

Traversal completeness is server-relative, not source completeness. For example, source inspection may show `CrossModuleCallers.aliased_cross_file/1` calling `Calls.leaf/1`, yet a server may return zero callers for `leaf/1`. In that result, `NO_INCOMING_CALLS` means only that the configured server reported an empty incoming-call list for that prepared item; it does not erase the known source caller or prove no caller exists.

Terminal provenance is carried by the terminal's `node_id`, `reason`, and optional `message`, interpreted alongside the invocation's server command, capabilities, target, and retained server version. The v1 graph does not embed a source-inspection oracle or server version, so those belong in qualification evidence rather than new graph fields. A complete traversal can therefore be incomplete relative to source truth, and a source-known/server-zero-caller discrepancy blocks the relevant interoperability qualification without changing `lsp-trace.graph.v1` semantics.
