# ADR 0011 — references issuance-barrier decision handoff

**Decision requested from the receiving maintainer:** `ACCEPT_REFERENCES_ISSUANCE_BARRIER_DELTA_FOR_IMPLEMENTATION | REVISE | REJECT`. The current independent decision is **REVISE**. This packet is a request to close the *local release implementation contract*, not permission to issue references or a request for a nontechnical stakeholder to choose byte counts. lsp-trace is a local single-user developer tool; hosted/shared/remote/centralized/automatically CI-retained operation is unsupported and out of scope, not a later prerequisite. “Production” in inherited document names means regular local release implementation; preserve identity-bearing names.

## Why this is needed

The current test-owned references chain can publish a terminal claiming `T=1,A=P` before the occurrence ledger is verified. If a later publication/readback fails, persisted bytes appear to claim admission even though the accepted matrix requires **no newly issued terminal or occurrence (`T=A=0`)**. Its malformed-result diagnostic path also publishes a method object containing raw result bytes before it publishes a redacted diagnostic. Neither path is enabled for the regular local release implementation.

The proposed correction is an acyclic **evaluation proposal → inert occurrence candidate → final issuance receipt**. Only successful publication, byte-exact readback, and independent replay of the *final* receipt may issue `T=1,A=P`; failures leave `T=A=0`. A separate owner-only raw artifact permits replay of malformed results without putting those bytes in the redacted diagnostic `D`. These two ideas were selected **in principle**, not accepted as an implementation contract. The accepted references contract and matrix at `ed91b585` remain unchanged; historical omitted-selector `CALLS_ONLY` must remain byte-compatible.

## What the controls protect (not a questionnaire for stakeholders)

| Control | What goes wrong without it | Who must propose and substantiate it |
| --- | --- | --- |
| Exact predecessor versions, selectors, and digests | A well-shaped ref can name the wrong method/target or a self-asserted source/policy. A final receipt could appear verified while its dependencies are not. | References contract owner: pin actual predecessor record grammars and owner-computed identities; reviewer tests substitutions. |
| Independent scanner and evaluator-transition record | Parser item counts or an after-the-fact copy of `items` can manufacture `E`, `E_B/E_T`, or `P` and thereby `A`. Transport write/read observations do **not** prove evaluator transitions. | References implementation owner: specify the response-read→scanner→transition-sink seam, keyed invocation, failure behavior, receipt schemas/identities, and independent replay. Do not claim the current `evaluateCompleteReferences` event slice is independent. |
| Result, frame, Manager aggregate, message, work, allocation, and deadline ceilings | A 1 MiB raw result can be rejected earlier by Manager's aggregate decoded-message-body cap; raising that cap alone currently disables owned-pair capture. A large frame or malformed payload could consume resources or escape redaction. These measure **different bytes**, so one cap cannot stand for another. | Runtime/transport owner: measure the exact boundaries, select justified positive limits, keep owned capture eligible, and supply boundary and over-limit tests. The proposed 4 MiB Manager/wire limits are *candidates*, not authority. |
| Valid **and** malformed exact-result evidence | Raw provider bytes can contain secrets; without retained exact `raw_result_ref`, digest, length and all other final dependencies, normal in-memory use cannot claim replayable successful issuance. Redacted-only D cannot replay arbitrary malformed bytes either. | Select the normative local-single-user profile: in-memory default, secret-free synthetic fixtures for durable behavior tests, explicit per-run live local capture of valid/malformed keyed results for final or D replay, and separate ad hoc malformed diagnostic-only investigation. Missing/deleted evidence makes dependent claims `INCOMPLETE`/`WITHHELD`. No organization roster or privacy tombstone is needed for optional raw. |
| Bounded **issuance** transaction uncertainty | A committed-but-unverified final can remain on disk; interpreting it as issued is unsafe. Unlimited failed transactions can exhaust disk. | Publication owner: propose bounded object/byte accounting and private exact uncertain-selector custody. On cap or unverified final **block new issuance**, never promote, retry or silently evict. Keep the accepted lifecycle of actually issued receipts distinct from user-managed deletion of optional local raw debugging files. |

`adr0011-local-qualification-privacy-v1.proposed.md` now defines four local behaviors. Its raw ≤1,048,576 bytes/object, ≤16 objects/16 MiB per run and ≤128 MiB root, and the issuance transaction envelope of 256 objects/128 MiB plus 256 uncertain-publication entries/512 KiB are unapproved **candidate** numbers. Technical owners should return justified separate local-capture and issuance-accounting bounds; the stakeholder need not select byte counts. Unsupported hosted/shared/remote/centralized/automatically CI-retained operation is **not a current or future local-work gate**; adding it would require a new ADR.
