# ADR0011 generic launch, retained-byte accounting and restart expiry — correction packet

**REVISE / INCOMPLETE; proposal for independent read-only review.** This packet revises the *candidate numerical adoption decision*, not the already reviewed finite-limits packet or any schema/policy original. It selects no limit, role URI, provider, qualified occurrence, lifecycle D transition, public route or cross-process clock authority. Accepted references V1, its pins and historical records remain unchanged. A generic successor cannot issue retained evidence until the independent maintainer selects exact policy/original bytes, implementation and tests and accepts each gate separately.

## Observed seams and claim ceiling

Assumption: current implementation is evidence of gaps, not a generic successor contract. `internal/managedprocess/identity.go:13,63-76,95-151` observes a pre-Start path and hashes at most 1 MiB with a domain prefix; it records ordered args and environment digests and compares file identity/size/mtime before and after, but neither hashes the whole executable nor follows an interpreter/script/JAR chain. Its regular-file check and path reopen are not a generic no-follow multi-artifact launch custody protocol. `internal/adr0011lifecycle/v2_publication.go:135-210` constructs selected V2 refs and performs bounded held readback with regular/single-link and no-follow checks, but is explicitly a private single-record seam without complete enumeration or successor admission. `internal/adr0011acquisition/owner_read.go:238-263` validates a V1 private record via bounded readback; it does not impose a new launch quota or expiring cross-process access. `internal/publication` bound-file mechanisms and acquisition policy records provide private publication/readback precedents, not a generic deduplicated transaction ledger. The predecessor `adr0011-generic-lsp-finite-limits.packet.proposed.md:24-27` proposed 16 MiB per executable, 33,554,432 B total retained, and 24 h access only in a continuous monotonic process epoch; these are unselected candidates. In particular the old packet's equality fixture permits access at exactly terminal+86,400,000 ms; the choice below needs explicit maintainer resolution rather than silent reinterpretation. Nothing here authenticates the responding process or proves its actual mapped memory, runtime dispatch, source completeness or honest provider identity.

## Candidate launch-chain custody (open-world, finite)

Assumption: a generic process may be launched by a native binary, an interpreter and script, `node` and entry script/package files, `java -jar` with application and dependency JARs, or an executable wrapper that delegates to another executable. A single executable-path digest is therefore insufficient. Candidate capture is an **ordered role-bearing chain**, not a provider/name allowlist: record launch argv and exact selected working directory/environment/config provenance; for each selected file record ordinal, role (`native`, `interpreter`, `script`, `node_entry`, `java_runtime`, `application_jar`, `dependency_jar`, `wrapper`, `delegate`, or explicitly versioned extension), argument/reference edge, original path locator and resolved path, device/inode identity, byte length and full-file SHA-256, selected policy and phase, plus an exact retained-byte reference when original-byte replay is claimed (otherwise an explicitly hash-only identity record with no replay claim). A repeated file may have multiple role/edge references; distinguish those references from unique stored bytes. Define how classpath wildcard expansion, Java manifest class-path, Node module resolution, shebang arguments, wrapper delegation, symlinks and runtime downloads are deterministically resolved *before* claiming closure. Unknown generated, remote, environment-selected, dynamically loaded or otherwise opaque required links return typed `LAUNCH_CHAIN_UNSUPPORTED`/`LAUNCH_CHAIN_UNRESOLVED`, not a one-file verified chain. Open-world means unfamiliar chains may be supported by a newly reviewed resolver; it does not mean unbounded discovery or silent trust.

Candidate bounds, **not adopted**: at most 16 regular files in a selected launch chain, at most 268,435,456 B (256 MiB) per file, at most 1,073,741,824 B (1 GiB) summed selected file bytes, and at most 32 role/edge references including aliases. These permit several JARs rather than assuming exactly one. If a real chain exceeds any bound, return a typed resource-limit or unsupported-chain terminal and request a revised policy; never truncate a chain into a verified claim. Use checked integer additions and cap+1 reads, and reject file-size overflow before allocating optional retained bytes. Stream the **entire** opened file through the digest; the digest is SHA-256 of raw file bytes (not the existing domain-prefixed identity hash). Exact retained launch blobs are optional only for an explicitly limited hash-only identity claim, which cannot reproduce or independently replay the original launch bytes. If the selected claim requires exact original-byte replay, every required original launch artifact must be retained and independently readable under privacy policy and quota before issuance; missing bytes, denied retention, or readback mismatch mean no such selector is issued. Neither a hash nor an optional reference implies replay custody. A full-byte hash is bounded local measurement, not a bound on total read work except via file/chain byte ceilings and not proof of running memory.

Candidate acquisition uses a host-selected regular path with no-follow open (including intermediate component policy), `lstat`/opened-fd `fstat` dev+inode/link count/mode/size before streaming, a post-read `fstat`, and a fresh selected-path no-follow recheck against the opened fd immediately before Start; detect mutation by size, mtime/ctime where available and repeated full digest if metadata cannot establish stable bytes. Reject links, writable or multi-linked unsafe files under selected host policy; a path replacement, inode mismatch, byte change, short read, inaccessible artifact or unresolved launch expansion gets a typed race/unavailable failure. Recheck the selected argv/config binding at Start. Even this narrows a time-of-check/use window; without a reviewed host-specific execution-handle correspondence or stronger process observation it cannot claim the OS executed precisely these measured bytes. Do not claim memory image correspondence from path and inode checks.

## Candidate aggregate retention reconciliation

Assumption: predecessor numbers include exact complete inbound wire aggregate 8,388,608 B and prepared source 4,194,304 B per document, but did not select a finite source-document count or reconcile simultaneous distinct blobs. Candidate source count **4 documents** per transaction yields a worst-case source allowance of 16,777,216 B. With launch selected-file sum **1,073,741,824 B**, wire **8,388,608 B**, sources **16,777,216 B**, and separately bounded metadata **8,388,608 B**, the checked no-dedup category-maxima sum is **1,107,296,256 B**: 1,073,741,824 + 8,388,608 + (4 × 4,194,304) + 8,388,608 = 1,107,296,256. This candidate **does not promise simultaneous admission of every category maximum**. Propose an independently configurable transaction retained quota of **1,073,741,824 B**, strictly below that sum, subject to maintainer selection and privacy review. An otherwise category-valid combination above this independent quota returns typed `RETENTION_QUOTA_EXCEEDED` before issuance; neither the old 33,554,432 B ceiling nor simultaneous-maxima admission is silently preserved. Check multiplication, each addition and the final reservation for overflow before comparison, accounting for all distinct retained launch blobs (when required), up to four source blobs, complete wire and metadata. Per-file and chain ceilings bound measurement even when hash-only identity omits optional launch blobs; the quota charges only actual retained bytes, not unretained measurements. Distinguish per-file reading caps from optional retained-byte caps and do not assume every prepared document must be persisted if the contract explicitly permits omission.

Charge each distinct content-addressed stored blob by exact serialized byte length once; every role/ref/edge, manifest, clock anchor, terminal, schema/policy reference and index metadata is separately charged in the metadata bucket even when its target blob is shared. Alias only after digest **and length and exact-byte equality** against independently read existing bytes, not hash alone; digest collision or mismatch fails typed publication, never overwrites. Reserve worst-case incremental bytes using checked arithmetic under an atomic per-transaction quota before no-replace publication; adjust reservation for proven exact dedup only under the same root lock and after independent readback. Publish complete role references and blob ledger atomically or quarantine committed-but-unverified bytes; release reservation on precommit failure, never leak a partially issuable selector. Fresh final readback checks each counted blob and every role/ref against independently selected originals; deletion/revocation and transaction GC require their own reviewed lifecycle, not an inference from access expiry. A shared blob's physical byte charge is once, but references and metadata cannot disappear from accounting. Host-wide concurrent storage quota and root-lock behavior also require separate selection; a per-transaction ceiling does not bound total disk across transactions.

## Candidate restart-safe access expiry

Assumption: a monotonic clock establishes elapsed time only inside a live epoch; a raw wall timestamp is not a trusted restart anchor. Candidate durable trusted-host record binds terminal selector/digest, transaction identity, exact terminal timestamp in a host-selected persisted time domain, clock authority identity and epoch, last accepted watermark, retention duration, and publication/readback status. Persist terminal anchor and watermark under a root lock with no-replace or monotonic update protocol and durable sync before exposing owner access. Same process computes remaining time from monotonic elapsed since terminal, cross-checking trusted-host time/watermark. A normal restart reads and verifies the committed anchor and watermark with a reviewed durable clock authority, computes **remaining** window from original terminal (never a fresh 24 h), and durably advances watermark before access. Concurrent processes need a common lock/linearizable watermark; an untrusted local clock or mutable file timestamp cannot establish this authority.

Candidate boundary for explicit decision: `allow ⇔ 0 ≤ elapsed < 86,400,000 ms` (deny at exactly 24 h). This differs from the old packet's exact-equality success fixture; reviewer must explicitly choose `<` or `≤` and revise successor fixtures/policy additively, without editing the old packet. Access expiry is not physical deletion. Only missing/invalid anchor, inconsistent timestamp or epoch, time rollback below watermark, failed durable update/readback, or expired window fail closed with distinct typed `RETAINED_CLOCK_UNAVAILABLE`, `RETAINED_CLOCK_ROLLBACK`, `RETAINED_ACCESS_EXPIRED` outcomes; an ordinary verified restart **within** the window must preserve access. Any tolerance for clock skew must be independently specified and cannot extend the original window. Until the durable trusted-host time/epoch and anti-rollback authority is selected and reviewed, cross-process retained access **cannot be claimed**; same-process monotonic-only behavior remains a narrower candidate, not general restart safety.

## Model interpretation

This is a candidate successor correction, not a retroactive change to the predecessor. Assumptions: four source documents and an 8 MiB metadata allowance expose checked worst-case storage arithmetic; the proposed independent 1 GiB aggregate quota intentionally denies some category-valid combinations. Retained launch bytes are optional only for a labeled hash-only identity claim, not for exact original-byte replay. Gaps: actual chain correspondence to executing memory, cross-process clock authority, root-wide concurrency and implementation seams remain unproven. Verification items: independent reviewer selects counts/quota; selects strict or inclusive expiry; confirms isolation seams before implementation. Improved framing: make launch closure, charged retained bytes and durable elapsed time separately reviewable prerequisites of any retained generic claim.
