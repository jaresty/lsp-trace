## 1. Executable measurement: subject and acquisition

**Selected subject, not yet observed in production:** the installed executable's *opened regular file*, pinned by no-follow path and file identity (device/inode, length and opened-handle SHA-256), measured completely at process startup before selecting an attempt. A canonical `ADR0011_INSTALLED_EXECUTABLE_MEASUREMENT_V1` original binds V1 profile digest, executable file digest/length, fixed `LINKED_INTO_INSTALLED_EXECUTABLE_ONLY_V1` adapter scope and `PIN_OPENED_EXECUTABLE_FILE_COMPARE_PATH_AT_START_PREWRITE_POSTCAPTURE_V1`. `implementation_digest` hashes those complete canonical measurement-original bytes; target implementation identity is separately domain-separated over measurement plus independently selected target schema/policy/role. The executable cannot embed a digest of itself. Recheck the *same opened file bytes* and current path identity immediately before first method WRITE and after capture; replacement or inability to recheck yields no WRITE (if pre-WRITE) or no issuance (if later). A linked-out adapter/plugin not covered by that file is ineligible unless separately pinned under a reviewed new version. A zero-length, truncated, symlink-substituted, nonregular, or incoherent byte observation is nonissuable.

**Current evidence ceiling:** `internal/adr0011builtinprofile/replay.go:174–179` freezes supplied canonical original bytes; `internal/adr0011acquisition/owner_private_builtin_test.go` supplies a *synthetic* `sha256(installed)` measurement. No owner startup opened-handle measurement, postcapture recheck, or actual installed-executable identity has been shown. Source-only `reviewedSyntheticSourcePin` measures checkout files, **not** an executing binary. Even a successful opened-file check establishes local file-byte consistency, not running-memory correspondence, build authenticity, producer authentication, or same-UID adversary resistance. Required offline falsifiers before considering wiring: replace path between startup and pre-WRITE, replace between WRITE and postcapture, change opened bytes/length, substitute another executable with coherently rehashed claimant records, omit measured adapter code, and attempt to use a missing executable observation.

## 2. Binding measurement to the executing owner

The process that calls the managed owner must independently select its own opened executable descriptor, session/generation, invocation and root before any method WRITE. A claimant plan or response cannot choose the expected executable digest. Replay must compare complete measurement original, its selected source, `plan.implementation_digest`, target implementation identity and held selection against the owner-held expectation. A completed manager WRITE supplies its **actual** key only afterward; pre-WRITE custody and initiation contain no planned key. Post-WRITE `attemptRequestKeyObservation` binds the actual key, wire ID and completed framed WRITE to prewrite custody; missing WRITE/READ never fabricates a terminal or final. `sessionruntime/request_write.go:25–30` exposes `CompletedRequestWrite`, but that accessor alone does not prove the executable measurement or correspondence to running code. An independently held expected owner/plan identity and a startup/prewrite/postcapture observation chain are **missing**. A measured file may have been replaced after load or may not correspond to mapped memory; explicitly preserve that claim ceiling instead of calling the measurement an attestation.

## 3. Durable local profile and exact originals

V1 built-in profile/schema/policies/limits and derivations are selected by the installed program on an *eventual explicitly invoked* references operation, never by a request, result, provider, adjacent mutable file or `latest`. The proposed fixed `os.UserConfigDir()/lsp-trace/private/adr0011-references-v1` root is only a locator: select a canonical absolute path, reject symlink/unsafe or known synced ancestors and workspace/repository containment, open a private 0700 directory with owner-only 0600, regular, single-link, no-replace files. No background directory creation or unsolicited retention. Independently select originals for profile, subordinate target schema/policy, executable measurement, source, Git BEFORE, plan, declaration, witness, custody and selection; publish/read back complete bytes and domain/role links before WRITE. Post-WRITE manager-key observation and subsequent descendants have *predeclared role/selector/derivation expectations* before invocation, but their actual bytes can only be bound after observed production and verified fresh readback. Do not invent pre-invocation result bytes.

`internal/adr0011builtinprofile/replay.go:174–179` clones in-memory exact originals; `owner_private_builtin.go:72–85` returns a snapshot/digest and logically restores against a separately supplied digest. These do not persist a root selection, prove that the digest is held independently across processes, or prevent a second process from selecting a conflicting attempt. A durable implementation needs a verified original-byte/selector index and an independent expected snapshot digest outside claimant descendants, with no-replace publication, reopen/readback, bounded size and root identity; do not store snapshot and its only expected digest in the same rewriteable claimant record and call it independent.

## 4. Restart under V1, not current defaults

On restart, identify the exact retained attempt and V1 profile ID/digest from a separately held host-selected index; independently reread all V1 originals (including plan/selection, prewrite declaration/custody, policies, target schema, measurement and relevant postwrite records) and compare their complete bytes to selected refs. Call `RestoreV1` only with a truly independently retained expected snapshot digest; the existing private test passes a separately saved in-memory digest, **not** a demonstrated persistent authority. Never regenerate nonce, plan, selection, key or missing terminal, and never resolve V1 through V2/current defaults. Missing, ambiguous, stale, removed, differently versioned, or unverified originals yield `REPLAY_UNAVAILABLE`/incomplete, not success or zero counts. Falsify with two local processes, crash/restart at prewrite and postwrite boundaries, a V2 installation lacking V1 verifier/bytes, altered snapshot plus coherent claimant digest, and an unchanged snapshot whose external expected digest is missing.

## 5. Crash and committed-unverified states

No-replace namespace installation is not sufficient for verified receipt. `publication.PublishBoundFileWithTrace` may return a committed receipt with `VerificationStatus=COMMITTED_VERIFICATION_FAILED`; it cannot be upgraded by an in-record flag or treated as absent for immediate retry. A verified receipt needs selected complete-byte equality, safe close/directory-sync accounting and a **separate fresh bounded read** under the pinned private root. On postcommit verification failure, retain redacted selector/digest failure inventory and quarantine potential committed bytes; no terminal `T=1`, no admitted `A>0`, no public result. If commit succeeds but parent sync/close fails, record an explicit uncertain durability state and block issuance/restart promotion until separately reviewed reconciliation. Precommit failure makes no verified receipt. Crash between any two steps must recover from verified immutable originals, not process-local flags. `internal/adr0011acquisition/owner_private_builtin.go` demonstrates verified synthetic publication and fresh readback for a *derived, non-wire descendant* only. It has no production crash journal, manager-key observation, canonical LSP payload retention or production issuance. Falsifiers: kill after install before verification, after verification before independent read, after uncertain sync/close, and after only a partial child set; subsequent restart must neither silently retry no-replace nor fabricate closure.

## 6. Lifecycle dependency, not replacement

Lane C lifecycle contract remains `REVISE`: `adr0011-lifecycle-cutover-delta.proposed.md` calls for root-wide cross-process exclusion, persisted fence/epoch, verified all-dependent cutover, restart reconciliation and unlink/tombstone outcomes. Process-local selector locks and the private in-memory held digest do **not** establish those properties. The references custody packet may specify required read/pin integration points, but must not implement lifecycle cutover, infer tombstones from missing bytes, delete evidence, or rewrite historical final accounting. An active occurrence must retain replayable dependency pins; revoked/removed dependencies become typed `REPLAY_UNAVAILABLE_*` for new use while historical bytes and temporal claims remain unchanged. Production wiring and lifecycle eligibility are separate decisions; until the requisite fence and cross-process host selection have accepted contracts and tests, a competing process must fail closed. No lock is held during arbitrary provider calls.
