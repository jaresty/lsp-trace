# ADR 0011 — built-in local references profile V1, proposed exact-byte freeze

**Product direction selected by maintainer; contract bytes NOT YET ACCEPTED.** The installed tool should choose a reviewed, versioned built-in profile automatically when a user explicitly invokes an eventual references operation. No authority file, service, signing ceremony, manual digest or policy configuration is required of a local developer. This supersedes the *recommendation* of `adr0011-production-authority-models.decision-packet.proposed.md` (21,156 bytes, SHA-256 `5ec3309085f991206fb36614cb210e2b164328929b9a37faea9c732f4c72af55`), **not** its source findings or the accepted references contract. Model name: `BUILTIN_LOCAL_REFERENCES_V1`. The profile is the installed program's proposed source of expected values, not a result record's, request's or provider's self-selected authority. Selecting this product direction does **not** select these new exact schema/policy bytes as production authority, wire `owner.go`, authorize live/qualification rows, or expose an operation. The current installed product still constructs `NewDisabled` and `PublishReferences` is fail-closed. Future no-configuration usability and present fail-closed production are separate facts.

## Canonical identity and ordering rules proposed for private implementation

1. **Built-in profile.** Embed the exact 4,008 manifest bytes in a future installed binary under the V1 ID; compute SHA-256 over those bytes and compare to the compile-time independently reviewed digest. Never load `HEAD`, a mutable adjacent file, request-supplied policy/schema, or ambient fallback as the expected profile. A release changing any selected bytes, schema role map, limits or derivation semantics needs V2 with its own immutable bytes; old attempts keep their V1 profile ID/digest. A V2 binary may replay V1 only if it still holds the exact reviewed V1 originals and verifier; absence means `REPLAY_UNAVAILABLE`, not a V2 reinterpretation. Current code has **not** embedded or selected this profile.
2. **Canonical codec.** Proposed profile and new role originals use one UTF-8 JSON value with keys sorted by Unicode code point, JSON-standard string escaping, integer decimal numbers, no floats, duplicate decoded keys, invalid Unicode, extra members or whitespace; no trailing LF. Strict decode, role-specific schema validation with format assertion, and complete-byte re-encoding must agree. The profile's `role`/schema URIs and exact file digests are compile-time candidates; JSON Schema proves shape, not cross-object identity or producer authentication. Existing predecessor records retain their historical codecs and bytes; do not rewrite them to this proposal's codec.
3. **Executable measurement.** The future owner opens the installed executable file by a no-follow verified path and retains that opened file identity, complete length and SHA-256 *at startup*. A private `ADR0011_INSTALLED_EXECUTABLE_MEASUREMENT_V1` original binds its **file** digest/length, V1 profile digest and fixed rule `PIN_OPENED_EXECUTABLE_FILE_COMPARE_PATH_AT_START_PREWRITE_POSTCAPTURE_V1`. `implementation_digest = sha256(complete canonical measurement original bytes)`; no binary embeds an expected digest of itself. Immediately before first method WRITE and after capture, recheck the pinned file descriptor's bytes and current path identity; disagreement, unavailable bytes, linked-out plugin/adapter that cannot be measured under `LINKED_INTO_INSTALLED_EXECUTABLE_ONLY_V1`, or replaced file means no final and no new admission. A pre-WRITE mismatch means no WRITE. This establishes consistency of a measured installed file, **not** correspondence to the running memory image, a trusted build, software authenticity, or malicious same-UID/host resistance. Those limits are explicit qualification constraints, not inferred guarantees.
4. **Plan and IDs.** Before either `documentSymbol` or `references` WRITE, the owner validates explicit invocation parameters, READY session/generation, canonical workspace and query URI/point, prepared source/version/encoding, host Git BEFORE, private root, schema/policy pins, positive bounds and the startup implementation measurement. It allocates a random 16-byte-or-greater hex `invocation_nonce` and constructs one closed `ADR0011_LOCAL_REFERENCES_PLAN_V1` original under the new role schema. Plan bytes contain every selected field but **no** `plan_id` or result. `plan_id = sha256(UTF8("ADR0011_LOCAL_REFERENCES_PLAN_V1") || 0x00 || canonical complete plan bytes)`. `invocation_id = sha256(UTF8("ADR0011_LOCAL_REFERENCES_INVOCATION_V1") || 0x00 || canonical({"generation":G,"nonce":N,"session_id":S}))`. These are different from the manager-assigned key; no actual request key enters the prewrite plan/custody. Source, BEFORE Git, execution measurement and policy originals must themselves be separately readback-verified; copying their digests from the plan is not verification. Plan selector/complete-byte SHA-256/length are retained separately from domain-separated `plan_id`.
5. **Declaration and selection.** Derive the already proposed `productionQueryDeclaration` from the **held plan original** using its own accepted-for-implementation role-domain occurrence ID rule; verify exact mapped fields, nonce, `plan_id`, source, Git BEFORE, schema/policy and implementation identities. Publish source/plan/declaration/witness/custody originals no-replace, verify receipts and independently reread expected complete bytes **before the first WRITE**. Then freeze an `ADR0011_LOCAL_REFERENCES_SELECTION_V1` original binding exact profile digest, `plan_id` and original ref, declaration ref, `implementation_digest`, policies/schema, private root identity, session/generation, nonce and expected custody ref. Selection ID is `sha256(UTF8("ADR0011_LOCAL_REFERENCES_SELECTION_V1") || 0x00 || canonical complete selection bytes)` and is held outside claimant manifest/ledgers. Its root identity is a digest of a canonical private record of the canonical absolute root path plus opened directory's device/inode; this is a local consistency check, not host authentication. **No circular ref:** custody binds declaration/policy; the selection then binds the independently calculated expected custody ref; the selection is not an immediate final dependency. Require complete publication/readback and an independently held expected ref before method WRITE. Missing target means an honest nonissuable incomplete state, not a fabricated method terminal.
6. **Key and issuance barrier.** Only *after* completed framed manager WRITE can the key observation bind actual key/wire/frame to prewrite custody. A completed WRITE without independently retained exact frame remains incomplete. Keyed begin requires an actual matched READ. Ledger N/B/T/E/P/A and external final publication proof are **not** supplied by this profile. `COMMITTED_VERIFICATION_FAILED` cannot be retried/upgraded as verified; no `T=1` or `A>0` follows from profile or in-memory fixture validation. `PublishReferences` stays fail-closed.

## Local root, process, restart and privacy

The proposed locator `OS_USER_CONFIG_DIR/lsp-trace/private/adr0011-references-v1` means the platform's `os.UserConfigDir()` result joined with these fixed path components, evaluated/validated as a cleaned absolute path under the current user's account. The owner must verify no symlink in selected path components, no workspace/repository containment and no **known** sync-root containment before opening a pinned owner-only `0700` directory descriptor; otherwise fail closed. This cannot detect every user-configured sync service or authenticate a same-UID actor. Future implementation must test environment/home spoofing, path replacement and root rebind rather than assume `os.UserConfigDir` is an authority principal. Do not create a directory during startup or background discovery. Creation/retention is permitted only by a separately authorized, explicitly invoked operation under the selected privacy policy; the present public operation is **not authorized**, so no live or raw capture is authorized by this proposal. Bound files remain `0600`, no-replace and independently read back. Failure after install is privately accounted as committed-unverified, not absent or verified.

One owning process may select attempts **only after** an exclusive root/attempt selector is independently implemented and verified; a second process must fail closed. Current process-local selector mutex does not prove exclusion. Startup loads the built-in profile and measures executable bytes without publishing or issuing. An attempt freezes V1 even if the process later changes or a V2 is installed. Restart may verify and replay an already retained exact V1 selection/plan/profile and original bytes; it may not regenerate its old nonce/plan or choose `latest`. No shared-fence or crash durability proof exists yet. With a missing, ambiguous, stale, unverified or differently versioned selection, restart reports incomplete and makes no new admission. Old attempt eligibility, revoked dependencies and physical removal remain Lane C `REVISE`, not solved by profile selection.

## Exact proposal-only checks and independent decision request

`go test ./docs/qualification/schemas -run '^TestADR0011BuiltinLocal' -count=1` under `GOPROXY=off GOSUMDB=off GOTOOLCHAIN=local` passed **2 synthetic tests** at preparation time. They check complete-file digest/length pins, exact profile canonical JSON, closed role-schema shapes, historical twenty-role map plus production declaration URI, ordered witness roles, a domain-separated plan ID change under a changed nonce, and selected profile non-override. They **do not** establish actual executable measurement, host selected originals, pre-WRITE time, lock, restart, no-replace publication, policy semantic acceptance, producer authentication or live qualification. No schema shape can establish those facts. Before private wiring require assertion-specific negatives for request/profile override, V1/V2 byte substitution, changed executable at startup→pre-WRITE and postcapture, coherent claimant rehash against held plan/selection, missing source/Git/policy original, committed-but-unverified publication, restart replay and competing second process. Failures must be typed and nonissuable. Do not expose a public DTO or run rows as part of this stage.

Independent reviewer: verify every input pin, exact file-schema role URI map, that a fixture's schema-valid digest is not mistaken for runtime authority, the plan/declaration/selection noncircular order, byte identity/codec, no self-digest, local out-of-box behavior versus privacy policy `capture_default:OFF` and `live_capture:EXPLICIT_PER_RUN`, no phantom cross-process protection, and no alteration of accepted 21-role/historical CALLS bytes.
