# ADR 0011 — references issuance-barrier independent review submission

**Decision requested (implementation-contract scope only): `ACCEPT_REFERENCES_ISSUANCE_BARRIER_DELTA_FOR_IMPLEMENTATION | REVISE | REJECT`.** Prior disposition was REVISE; this submission does not record ACCEPT. The new `adr0011-references-contract-freeze.addendum.proposed.md`, proposed issuance schema, contract counterexample tests and four exact selected policy JSON artifacts are the prospective producer-output proposal. Earlier worksheet statements about missing contract choices are historical, superseded for this review by the addendum; seam-derived allocation/deadlines and actual producer conformity remain implementation work, not prerequisites for specifying required outputs. Maintainer-selected privacy, retention and numerical implementation defaults below are no longer open policy choices. The accepted references contract/matrix at `ed91b585` remain immutable; regular local release `REFERENCES_SYMBOL_V1` issuance, definitions, grouping, held-out CUE, Leiden and CLI/MCP exposure remain disabled. “Production” in older document names denotes the local release implementation, not a hosted service. Preserve historical omitted-selector `CALLS_ONLY` bytes.

## What changed after the previous review

- The addendum specifies prospective closed method/target output shapes with observed `Version` literals and flat selector/digest semantics; the unsafe observed `ResultBase64` shape is **not** approved as future required output. The revised closed host-Git observer record now binds exact ordered command arguments, status, bounded stdout/stderr object refs, timestamps, cwd, distinct `HOST_OBSERVED_GIT` custody and executable identity for both accepted `HOST_GIT_PROBE_V1` observations; independent replay must follow the final→revision→probe→all stream dependencies. The owner-read record now names exact bounded parameter slices in retained keyed writes as well as result slices in reads; the subordinate target names separately retained document-symbol result bytes, query point, selection fields and independently recomputed IDs. These are required prospective producer shapes, not evidence that the producer emits them. Test-owned producer code remains uncommitted and unaccepted seam evidence, outside reviewed hashes. Source/revision/raw/scanner/event/policy roles and independent replay are specified as required outputs; their real production and qualification remain later work.
- **Stakeholder privacy decision:** signed server-error codes, including zero, are denied by default. A matched-error D is allowed only when a future explicitly versioned authorization under the selected privacy policy permits disclosure of the **exact** code. Under a selected policy that intentionally denies code disclosure issue `WITHHELD` and no D; without an established replay seam the claim remains `INCOMPLETE`; policy denial alone is `WITHHELD`. The draft diagnostic schema rejects a code-erased matched-error D; its passing shape test does **not** establish authorization or replay. The unsafe `ResultBase64`-before-redaction path remains disabled for local release diagnostics.
- **Normative product scope:** local single-user operation is the complete supported use case. `adr0011-local-qualification-privacy-v1.proposed.md` distinguishes normal in-memory operation, synthetic qualification, explicit live local qualification capture for valid **or** malformed bytes, and ad hoc malformed investigation. The profile is maintainer-selected for implementation, not implemented or qualified. Hosted/shared/remote/centralized/automatically CI-retained operation is unsupported, not a later acceptance gate; adding it would require a new ADR. The stated numerical limits are selected implementation-contract defaults subject to falsification; scanner/diagnostic byte-visit work is selected in the addendum; allocation and deadlines remain seam-derived and unselected.

## Independent resource-limit worksheet (selected defaults; seam-dependent values open)

The listed numeric defaults are **maintainer-selected for the implementation contract, not observed enforcement or qualification**. Falsifying boundary evidence requires a reviewed revision, not silent adjustment. For each boundary record measured quantity, enforcement point before allocation/publication, rationale, edge and edge+1 control and over-limit response. The addendum selects byte-visit units and 1,048,576-unit ceilings for scanner/diagnostic work; live allocation and deadline values remain seam-derived positive bounds to select and falsify during implementation.

The numbers above are **not** interchangeable: wire framing, staged bytes, Manager remarshaled body bytes, exact raw-result bytes, canonical record bytes, work and live allocation have different measurement units. Raising Manager `MaxBytes` alone currently prevents owned-pair capture. The owner must resolve that conflict with reviewed guards and controls, not declare the selected 1 MiB row passed from a synthetic fixture.

## Predeclared falsification before seeking ACCEPT

1. Omit, duplicate, reorder, forge after parsing, or cross an invocation boundary with an evaluator event while preserving a plausible item array: no proposal or issued `T/A`. Change scanner count while events/items remain plausible: replay fails.
2. Fail precommit and committed readback at method, raw, scanner, events, proposal, candidate and final. Retain exact potentially committed ref in bounded private redacted **transaction uncertainty metadata** on committed uncertainty; issue `T=A=0`, no retry/retro-upgrade.
3. Substitute each source/revision/policy/schema/implementation/ref/digest and each ordinal or range one at a time; a self-consistent candidate without final cannot admit. Preserve duplicate equal locations as distinct original ordinals.
4. Exact 1 MiB and 1 MiB+1 under an owner-eligible Manager; independent wire/staging/Manager/message/work/allocation/deadline edge/+1 controls. Mark any shadowed boundary `INCOMPLETE`.
5. Synthetic secret canaries in valid and malformed bytes, server error message/data/code, URI, source, provider error, logs and uncertain-publication metadata: absent from D/ordinary CLI/MCP/error/log/metadata; raw only in explicitly opted-in local capture. Code zero included in both explicitly authorized and default-withheld controls. Verify fixtures contain no copied real secrets and that the tool does not intentionally upload, commit or copy live raw to known synchronized/CI-managed locations; do not demand proof of host-level backup settings.
6. Exhaust issuance transaction and local raw caps separately; simulate uncertain committed final readback, deletion of genuinely optional debug raw, loss of an **issued final dependency**, and missing replay. Block new issuance on uncertainty. Deletion makes every claim dependent on the original captured bytes `INCOMPLETE`; a synthetic fixture may independently qualify equivalent implementation behavior but never restore the original provider invocation, identity, custody or completeness. Do not silently evict or promote.
7. Omitted-selector historical `CALLS_ONLY` schema/output byte controls, separately from references behavior. Execute the full 162-row matrix later against pinned implementation and clean managed Go/gopls evidence; shape tests are not this evidence.
