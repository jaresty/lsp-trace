# ADR 0011 definition schema candidates (unregistered)

These are **proposed**, not registered or pinned production schemas or policies. No definition implementation, issuance, admission, grouping, or qualification follows. References qualification remains independently required. The accepted references implementation contract is not a definition approval. `adr0011-definition-records.proposed.schema.json` defines eight closed, version-disjoint record roles; select an individual `$defs` role for role-specific validation. `adr0011-definition-lsp.proposed.schema.json` exposes separate `$defs/params` and `$defs/result` entry points. `adr0011-definition-policy.proposed.json` is proposed policy data, not a digest or self-authenticating receipt. Its `managerCountedBodyBytesPerRequest` refers to remarshaled decoded JSON-RPC message bodies (no frame headers); `exactFramedWireBytesPerRequest:null` is an **unselected bound**, not a production value or a claim the Manager currently measures exact framed bytes. The profile cannot be accepted while that field is null. All IDs use the explicit `urn:lsp-trace:draft:unregistered:` namespace; no production registration is implied.

## Independent replay guards, not schema-validated

- Strict decode the exact UTF-8 bytes, reject duplicate decoded keys (including escaped equivalents), invalid Unicode/surrogates, noncanonical integers and trailing content. For canonical records enforce fixed field order, Go `encoding/json` encoding, one trailing LF, byte-for-byte re-encoding and the 1,500,000-byte ceiling. Check SHA-256 over exact complete bytes, role separation, no-replace publication, readback and pinned selector identity; JSON Schema cannot establish any of these.
- Resolve canonical absolute local `file:` URI custody, registered root containment, clean host Git before/after, caller-asserted revision, managed READY generation, actual advertised capability and reported provider executable/profile. Assert source version/digest/byte length and valid UTF-16 positions in exact source, including surrogate boundaries. JSON Schema `format` may be annotation-only.
- Query range must be the one uniquely scanned identifier from the separately qualified language adapter, with cursor at start/interior, not end; source and capability receipts must be independently replay-verified before invocation. Reject missing/substituted/stale query receipt with zero invocation. Do not infer query identity from a result or references target.
- Validate range start ≤ end, `targetSelectionRange` containment, and any `originSelectionRange` exact equality to the independent query range. Validate scalar and homogeneous array distinctions against exact raw result; scalar LocationLink, mixed arrays and malformed later elements invalidate the whole result. Preserve null versus empty array and raw parameter formatting/digest.
- Correlate completed keyed write and exactly matched read, response presence, raw result payload digest and wire limits. Count E using a bounded complete top-level scanner; an over-limit/incomplete scan is UNKNOWN, not a guessed count. Replay ordered QUERY_BEGIN, optional TOP_LEVEL_COUNT before elements, contiguous zero-based ELEMENT_BEGIN / ELEMENT_EVALUATED pairs, bounded half-open offsets and element digests against retained raw result bytes; positive work accounting and cumulative budget are required. Whole parse failure means P=A=0 even if diagnostic valid-prefix events exist. No parser slice or ledger flags may manufacture evaluation transitions.
- For partial body prefixes independently verify observed Content-Length, key before result prefix, completed write, exact prefix bytes, offset/digest, complete member boundaries, absence of duplicate response IDs and actual read-phase/cause. Withheld/uncheckable prefix cannot prove element evaluation. A partial result cannot become a verified completed method pair.
- Check outcome precedence and `0 ≤ T ≤ B ≤ N`, `0 ≤ ET ≤ EB ≤ E` when E known, `0 ≤ P ≤ E`, `0 ≤ A ≤ P`; E unknown forbids numeric comparison to E. COMPLETE requires A>0; COMPLETE_EMPTY requires A=0 and fully balanced, well-formed verified denominator; E>0 fully excluded has query disposition EXCLUDED, not EMPTY. All-or-none target supply: one missing source excludes every target. Verify element disposition aligns with events and terminal, never silently admit provisional observations.
- Publication states before verification are not issuable terminals: precommit failure and committed/readback failure require separate quarantine handling; no T or A from unverified bytes. Every admitted occurrence pins query, method, capability, source and cross-document target supplies, evaluation, terminal, provider/revision/policy and original ordinal. Equal targets may share candidate identity only in one transaction; occurrence IDs stay ordinal-distinct. Never equate authority=0 with producer authentication.
- Under a root-scoped lock, check complete sorted unique dependency sets, previous digest and strictly monotonic generation, allocate pins before ACTIVE publication, recheck active reader leases and generation before use, publish complete-set tombstones before deletion, quarantine failed deletions, and distinguish explained tombstones from unexplained missing payload. The manifest schema cannot prove ordering, atomic visibility, completeness of the dependent set, or physical erasure.

The draft record schema rejects MATCHED methods without both transport observations, present results without a payload or positive length, absent results with a payload or nonzero length, link occurrences with null selection range, and privacy/prefix mismatches. MATCHED does **not** imply `resultPresent:true`: the method role has no explicit server-error field, so a matched error response may lack a result; an error-versus-success conditional needs an explicit discriminant before it can be imposed. `git.clean:false` is still accepted structurally because diagnostic mismatch records may retain dirty probes; cleanliness for admission remains replay-only pending a documented role-specific rule. Cross-record request keys, session/revision identities, prefix lengths/digests, event/accounting replay, exact JSON bytes, and provider profiles are not schema-enforced.

No JSON Schema can prove SHA-256 semantics, policy digest registration, execution-time transition order, lock discipline, privacy selection, source equivalence, cross-record consistency, or qualification. Independent executable fixtures and maintainer review remain necessary.
