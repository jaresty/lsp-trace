# LOCAL_QUALIFICATION_PRIVACY_V1 — proposed local privacy profile

**PROPOSED / NOT SELECTED / NOT IMPLEMENTED.** lsp-trace is a **local, single-user developer tool**. Local operation is the complete supported product scope, not an initial or reduced profile. Hosted, shared-service, remotely accessible, centralized, and automatically CI-retained operation is unsupported and out of scope. Adding one would require a new ADR; no speculative policy for it blocks local implementation or qualification. In older filenames or decisions, “production” means the regular **local release implementation**, not a deployed service. Historical filenames, decision tokens, schema identifiers, and accepted bytes remain unchanged.

## Four local behaviors

1. **Normal local operation (default):** process provider results in memory without durable exact raw-result retention. Emit only bounded redacted diagnostics. No raw bytes in ordinary CLI/MCP responses, logs, errors, public selectors or committed artifacts. Without exact retained `raw_result_ref`, digest, length and all required replay dependencies, **no replayable final references issuance receipt may be claimed**; evidence-dependent claims are `INCOMPLETE` or `WITHHELD`. A matched server-error code, including zero, is denied by default; without an independently selected explicit disclosure authorization, use `WITHHELD`, never a code-erased supposedly replayable D.
2. **Synthetic qualification (preferred durable evidence):** self-authored, secret-free fixtures (no copied user source, personal paths, credentials or provider secrets) may be committed. Use them for malformed results, resource edges and redaction canaries. Exact replay proves tested implementation behavior only, **not** real-provider identity, producer authentication, completeness or unexecuted matrix rows.
3. **Live local qualification capture:** explicit per-run opt-in may retain **valid or malformed** exact result bytes when successful final issuance or diagnostic replay requires them. Capture is bound to an owner-observed keyed response, never to caller-supplied bytes. The final success-arm receipt requires the exact raw-result ref/digest/length and all other verified dependencies throughout replay. Any missing required dependency prevents new replay/admission; deletion makes the dependent claim `INCOMPLETE` unless an independent sanitized fixture proves that *same claim* (not real-provider identity).
4. **Ad hoc malformed investigation:** separate explicit local opt-in permits diagnostic replay. It does not authorize successful issuance unless the entire independent final-issuance contract is also met.

## Proportionate local capture boundary

Durable raw capture is default-off. For either opt-in mode the local user selects a root **outside tracked workspaces and known synchronized paths**. Require a 0700 directory and 0600 regular single-link files, no-replace writes, exact readback and owner-bound keyed capture. Proposed bounds are **1,048,576 exact result bytes/object, 16 objects and 16 MiB per run, and 128 MiB under the selected root**; these are review candidates, not measured or accepted enforcement. Count before copy/publication, reject on exhaustion and never truncate or silently evict. Do not intentionally upload, commit or copy raw bytes to known synchronized or CI-managed locations, ordinary CLI/MCP outputs, logs, diagnostics, errors or uncertain-publication metadata. The local user remains responsible for host-level backup settings; proof that host backup/sync is absent is **not** an acceptance prerequisite. An explicit **local administrative** operation may reveal the configured root for cleanup/debugging, but ordinary public evidence, diagnostics and MCP results must not expose raw roots or private selectors.

Manual deletion of optional local raw evidence needs no organizational custodian, access roster, enterprise ACL, backup administrator, maximum debug-file age or privacy-revocation tombstone. Availability must be checked at each replay: a stale digest cannot sustain a claim after deletion. Self-authored synthetic fixtures can persist independently. No centralized quarantine service or global privacy-revocation cascade for optional debug files is required.

**Issuance correctness is separate and mandatory.** Proposal/candidate/final transactions require bounded object/byte accounting, exact selector/digest custody, no-replace publication and verified readback. Potentially committed but unverified objects are non-issuable: no retry, promotion, silent reinterpretation or eviction. Missing required final dependencies prevent new replay/admission. Before final verification issued `T=A=0`; only verified final issuance may set issued `T=1,A=P`. The accepted lifecycle of actually issued immutable receipts is not relaxed by optional debug-file deletion. Resource measurement, scanner/event independence and the Manager owned-capture conflict remain separate unresolved implementation-contract inputs.

**Authority and decision ceiling:** `authority=0`, `accepted=false`, `completeness=UNKNOWN`, `NO_PRODUCER_AUTHENTICATION`. Historical omitted-selector `CALLS_ONLY` bytes remain compatible. No `REFERENCES_SYMBOL_V1` qualification, definition admission, grouping, held-out CUE evaluation, Leiden, CLI/MCP authorization or `ADR_0011_COMPLETE` follows from this proposal. A maintainer must independently review/select this profile and later evaluate full-matrix release qualification separately from `ACCEPT_REFERENCES_ISSUANCE_BARRIER_DELTA_FOR_IMPLEMENTATION`; these edits record neither decision.
