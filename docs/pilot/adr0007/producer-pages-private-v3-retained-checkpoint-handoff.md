## Durable bindings and accounting

The bounded canonical manifest binds exact schema/preparation revision, application/config, source spec/scope, original enumeration/runtime digests, page revision/terminal chain, original object/batch/target denominators, root paths/device/inode, ledger root identity, allowance, exact ledger generation/tip/cumulative charges, continuation intent, lifecycle generation/previous checkpoint, semantic stage, selected spool and report-reference roots. Object metadata is a linked sequence of separately paired entries, not an unbounded root array or decoded whole-origin/capture array. Enumeration target counting streams the already-owned original bytes.

Create-only fsynced anchors, lifecycle markers and one exclusive continuation claim prevent ordinary stale generation/duplicate continuation. Admission verifies the complete canonical reservation chain one bounded record at a time against the actual latest live ledger tip; missing/torn/noncanonical/interrupted records refuse. Later uncheckpointed reservations can never be refunded or silently turned into data progress. From an old checkpoint tip alone, an intervening reservation causes the unchanged ledger opener to refuse. If the caller possesses an actual newer tip, admission verifies all charges and resumes only the checkpoint's admitted data progress. A spent continuation without a successor checkpoint can refuse permanently; no automatic recovery permission is invented.

All new source/page/hash/clone/parse/math/spool/metadata/journal verification work is reserved before that work under the shared application ledger. Source reservation preserves the conservative `B*24/B*32` policy maxima; stage accounting preserves `256*(131072 + frozen bytes + 4*unit)`. Additional checkpoint/index/journal work is charged, not dropped. No default unlimited allowance or automatic extension exists. Caller-side bootstrap loading/opening and original acquisition/session/inference are not represented as whole-application accounting by this processing slice; the existing ledger opening API is unchanged.

Same-user malicious journal/index editing or whole-history rollback remains outside this unauthenticated private contract. No cryptographic rollback guarantee is claimed. Source/root borrowing remains nonconcurrent and non-atomic. Unit limits remain unchanged (maximum 16 MiB contiguous object); spool framing can honestly refuse a boundary-sized unit. This is not a measured whole-process heap bound, arbitrary malformed-input guarantee, streaming solution above the unit cap or arbitrary application-total scalability result.
