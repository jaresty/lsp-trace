# ADR 0011 references diagnostic D — proposed private policy

**Status: PROPOSED / NOT SELECTED / NOT QUALIFIED.** This is a diagnostic-only contract proposal subordinate to `adr0011-occurrence-falsification-matrix.review.md` and `adr0011-production-admission-gate.review.md`. It does not enable production issuance, public selectors, occurrences, CALLS, or source completeness. Schema: `schemas/adr0011-references-diagnostic.proposed.schema.json`, version `lsp-trace.adr0011.references-diagnostic.v1`. No producer authentication is claimed. The owner must pin a digest of the finally selected policy and schema before any qualification.

## Selection and capture boundary

The matrix requires independently replayable bounded redacted D for its malformed and matched server-error rows, or `WITHHELD` under the *selected* privacy policy. **Stakeholder preference recorded (not independent policy acceptance):** permit a separate, owner-only, independently capped exact canonical raw-result object for malformed-result replay while keeping D redacted. The raw artifact is not D, a successful method receipt, or a public selector. Its canonical schema, numeric caps, owner access and retention policy remain to be independently selected and pinned before use. A redacted summary cannot reconstruct arbitrary malformed JSON; until the maintainer selects a replay mechanism that actually replays the diagnostic claim, rows requiring exact parser replay remain `INCOMPLETE`, not `VERIFIED_DIAGNOSTIC`. A digest alone, fixture input controlled by the claimant, or the current caller-supplied pair cannot substitute for independent owner-bound response evidence. Where selected privacy forbids even D, issue no D and use `WITHHELD`, not `PROVIDER_FAILURE` with a fabricated verified receipt. Privacy withholding before evaluation yields B=T=0. D never contributes P, A, an admitted target, or an occurrence, and a diagnostic prefix is not a successful whole-result parse.

**Unsafe existing path:** `internal/adr0011methodresult/references_diagnostic.go` calls `expectedPair`, which builds a method record containing `ResultBase64`, then publishes that raw record before the diagnostic terminal. This path must remain disabled for production diagnostic capture until replaced; merely redacting the later terminal does not sanitize the earlier object. No raw over-`MaxResultBytes` frame, base64 copy, exception string, log, or quarantine inventory is allowed. An overcap observation can retain only a bounded redacted limit fact, subject to the independent D cap and privacy decision; if unavailable, `N/WITHHELD` as the matrix prescribes.

The owner must acquire an exact keyed completed request/response observation and bind the D record to method, invocation identity, query-target receipt, session/generation, request key, source/revision custody, policy IDs, exact params digest, selected read/write observation digests, and response presence. Store digests/opaque identifiers only where selected privacy permits them; identifiers are not proof of authenticity. Server-error code has an explicit `codePresence` discriminator: `ABSENT` forbids `code`; `PRESENT` requires the exact signed integer, including **zero**. A matched error is distinct from a transport-success response with **missing result** (`resultPresence=ABSENT`); neither carries `message`, `data`, error text, arbitrary provider fields, URI strings, source body, raw params, or payload bytes in D. Error text is treated as sensitive even if generated locally: publish only a closed reason code. Unexpected errors fail closed; no verbatim exception or frame excerpt enters D, inventory, log, or response.

## Proposed D allowlist and independent hard limits

Only the closed fields in the accompanying schema may be serialized; unknown keys, duplicate JSON keys (including escaped aliases), trailing content, noncanonical encoding, unsupported versions/reason codes, or cross-object mismatch fail replay. An external JSON Schema validator alone does **not** detect duplicate keys or canonical encoding; a strict byte parser and exact readback comparison are required. D's numeric caps are **proposed**, not inherited from the success arm: maximum 16,384 canonical encoded bytes per D; at most 16 D objects and 262,144 aggregate D bytes per acquisition; at most 65,536 bounded inspection work units and 64 consumed response messages, with positive owner deadline and allocation cap pinned before use. Count bytes *before* publication; never truncate a canonical record to fit. Count inspection work for each visited byte/token/element and reject before exceeding the cap. These D bounds do not raise `MaxAcquisitionQueries=16`, `MaxResultElements=1000`, `MaxParamsBytes=65536`, `MaxResultBytes=1048576`, or `MaxCanonicalRecordBytes=1500000`. The independent wire/frame maximum, allocation and deadline values remain owner-selection blockers; overcap frames must not be copied into a raw staging object. If a D bound is exceeded or privacy suppresses a mandatory field, withhold D and its terminal claim; do not relabel it a verified success or silently drop fields.

D carries a closed `reason`, outcome and query disposition, observed counts `N/B/T`, `E` as either known integer or `UNKNOWN`, `E_B/E_T`, `P=0`, `A=0`, diagnostic valid-prefix length and optional failing ordinal. Counts reflect *independently recorded* evaluations, not a parser's speculative walk: pre-evaluation resource limit has B=T=0, E unknown; complete malformed first/second element has B=T=1, E=2 and respectively E_B=E_T=1 or 2, prefix 0 or 1; countable 1001-element limit has E=1001, E_B=E_T=0; post-evaluation limit may have E=2, E_B=E_T=1. Query dispositions remain the matrix's `NONE/MALFORMED/LIMITED/FAILED`; D outcome is never a newly invented request outcome. Server error has `PROVIDER_FAILURE/NONE`, B=T=0; successful transport with missing result is its separate reason. Transport short write or unmatched short read has no D. Cancellation/timeout before output has no D. A parser diagnostic and a verified terminal are distinct from a successful method/target V receipt.

## Replay, custody and failure

A replay verifier must start from independently retained bounded owner observations and pinned policy/schema/implementation identifiers, not the D's claimed counters. Verify exact keyed write/read, response presence, target receipt identity, source/revision and method/query identity, caps and privacy, then recompute classification and counters; compare exact canonical D bytes, no-replace selector/digest and post-read bytes. With redacted-only D, replay can establish only facts that the independently retained observations actually support; malformed failing ordinal and prefix need replayable parser input or equivalent independently witnessed bounded parse events. The proposed private raw profile would store exact raw bytes **only** when within both the original result bound and a separately selected raw-object/aggregate cap, behind a separate selector/role, never inside D; its actual bounds, access/retention decision and leak tests still need independent maintainer approval. Do not retroactively call redacted-only evidence exact-byte replay.

Owner-only default-off root: pinned host-bound private 0700 directory, no caller-supplied root, 0600 single-link regular no-replace objects, exact readback, closed selectors and independent expected identities. Proposed retention is **until reviewed diagnostic retirement or privacy revocation**, with active replay dependencies pinned and no automatic 24-hour expiry; the exact maximum duration, owner/access roster, backup handling and deletion decision remain unresolved. Failed deletion or committed-but-unverified publication quarantines exact selector/digest (when known) in a separately bounded root-bound **redacted** inventory, with access limited to the designated owner/reviewer, no automatic retry or upgrade, and reviewed resolution; no raw bytes/error text in inventory. Missing bytes without reviewed manifest mean replay unavailable, not a legitimate tombstone. If D publication/readback fails, no verified D or diagnostic terminal is issued; this is not the success-arm T/A publication failure, which has its own `PRECOMMIT_FAILED`/`PUBLICATION_UNVERIFIED` barrier. A successful D is terminal **diagnostic-only**, with A=0; no success-arm T/A is inferred. Qualification records `INCOMPLETE` whenever a required independent D cannot be replayed, including privacy states not mapped to the matrix's explicit withheld row.

## Required falsification before selection

Use independent keyed fixtures with exact owner provenance and pinned policy digests: code present 0 versus absent with identical message, and nonzero; no message/data/error text leakage; malformed first/later element and duplicate result key; missing result versus exact null; 1000/1001 and result-byte/work/wire cap edges; cancellation after a complete prefix; privacy withholding; D byte/object/aggregate cap; unknown/duplicate/trailing D field; substitution of each target/key/source/policy/observation digest; precommit versus committed-readback failure and failed deletion. Insert unique secret canaries independently into error message/data, malformed raw result, provider error string, source, URI, frames, logs and quarantine failure strings; assert none appears in D bytes, failure inventory or any public/diagnostic response, including error paths. With a later approved raw profile, the restricted raw object is the **only** explicitly exempt private location, never D, inventory or logs; test access and removal separately. A replay test must corrupt the original observation while leaving a self-consistent D and its digest unchanged: replay rejects it. Passing offline schema shape checks alone cannot qualify the runtime.

## Unresolved maintainer decisions

1. The stakeholder selected separate private exact raw replay in principle; independently select and pin its canonical role/schema, per-object and aggregate bounds, owner access, retention and dependency policy, and the owner-bound capture/replay seam. Until then malformed D qualification is blocked.
2. Pin actual wire/message/work/allocation/deadline caps and the D limits above, redaction algorithm/canary coverage, selected privacy-withhold criteria, and allowed opaque identity fields.
3. Pin root custodian/access roster, retention duration and backup/deletion semantics, quarantine inventory bound and committed-readback resolution procedure.
4. Decide whether matched server-error code disclosure itself is permitted under every selected privacy policy; if not, use WITHHELD, not a code-erased D masquerading as replayable.

No decision above is accepted by creating this draft. The schema is a proposed shape, not proof that its producer satisfies the capture, privacy or replay contract.
