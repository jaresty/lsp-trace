# ADR 0011 production record identity delta — independent review draft

**PROPOSED ONLY.** This supplies identities missing from the implementation-only production-admission proposal at SHA-256 `d2989cc6db0d5bb8a389707a34dcf218f49f2927aaba4899395e84e6f5f3956a`. It does not amend accepted contract/matrix bytes, enable the owner, or promote the test-only `QUERY_OCCURRENCE_TEST_V1` record. No implementation may select these drafts as accepted schemas before independent review.

## Complete schema selection

Create a **new** whole-file Draft 2020-12 successor schema with a distinct `$id`, closed `$defs` for `productionQueryDeclaration`, `productionDependencyInventory` and `productionAdmissionFinal`, `additionalProperties:false` recursively, exact integer/URI/digest/selector bounds and the four pinned policy-reference roles. Do not reuse the test-only schema ID or silently append definitions to the already-pinned successor file (`sha256:86bb214e419f7c69b80ff5dfbdf0f0760c495c9bf0f88d06bdc227b77920fc8e`): changing that file invalidates its accepted hash. Independently select the **complete new schema file hash and each role URI** before production publication. Historical predecessor and private test objects remain under their original IDs. Mixed schema revisions in one new closure reject.

## Pre-invocation declaration

The host owner, not a request payload or provider, selects a private root, session/generation and collision-safe invocation nonce and freezes an expected `GO_GOPLS_EXACT_V1` query plan before any `documentSymbol`/`references` write. `productionQueryDeclaration` contains one closed, canonical object: role/version, plan ID, session/generation, workspace and query URI, zero-based line/character, negotiated encoding, prepared document version/length/SHA-256, host Git root/commit and BEFORE observation ref, selected implementation/schema/policy digests, invocation nonce, and source-body selector/digest. No post-response/result field enters its identity. Its occurrence ID is SHA-256 of domain `ADR0011_PRODUCTION_QUERY_DECLARATION_V1\0` followed by canonical JSON of every listed field **except** the ID; record selector is `adr0011-production-query-v1-<hex SHA256(full canonical record)>.json`, with role-domain digest independently stored. Publish source and declaration no-replace, verify close/directory sync and exact readback, and independently replay against the owner-held frozen plan before allowing method invocation. Missing, duplicate or substituted declaration yields no method invocation and no newly issued T/A. The host plan itself must be independently selected and retained before declaration; the declaration is not self-authenticating or producer-authenticated.

## Closure identity and ordering

`productionDependencyInventory` is a separately retained **validation witness**, not an additional immediate final dependency or a replacement for its 21 refs. It is a versioned closed 21-entry map computed from precisely the final's accepted enumerated immediate roles and multiplicities, replacing only the test declaration with `productionQueryDeclaration`. Canonical ref fields are `schema_version`, `selector`, `digest`, and `byte_length`; ref schema version includes full `$id#/$defs/role` of the selected new schema when new, and exact prior selected IDs for unaffected immutable predecessors. Encode each ref with strict canonical JSON, sort encoded strings byte-lexicographically, and reject duplicates, extra/missing roles, wrong BEFORE/AFTER order, wrong symbol/references owner-read assignment or mismatch with independently selected expected refs. Inventory ID is SHA-256 of `ADR0011_PRODUCTION_DEPENDENCY_INVENTORY_V1\0` followed by canonical full inventory bytes; no inventory entry may refer to itself or to a final record. Every entry's transitive predecessor closure (including exact four policy byte objects and original source/result bodies) must be read, role-validated and hashed under its selected schema; never trust a claimant-supplied list as the completeness oracle. A separately pinned role/multiplicity table is the oracle.

`productionAdmissionFinal` retains the accepted **21 immediate `dependency_refs`** unchanged in cardinality and role mapping; it additionally binds the independently derived inventory ID and digest as canonical context metadata, **not** as a 22nd immediate ref or a replacement for any of the 21. Its context includes target/declaration/request-key/invocation identities, result/accounting digest and P/A. Publication status is verified externally from an independently selected no-replace publication/readback proof and fresh readback, never a self-asserted final field or a 22nd immediate ref. Its domain-separated digest/selector is derived from complete canonical bytes; no final self-reference. Recompute inventory and complete transitive replay **before** no-replace final publication, then read/replay final and dependencies and perform an independent fresh final readback before any typed receipt. `COMMITTED_VERIFICATION_FAILED`, missing dependency, mismatched pin or stale generation remain non-issuable with no fabricated terminal. Issued T=1,A=P applies only to that verified private implementation path; public behavior stays default-off pending a separate enablement decision.

## SCHEMA/ROLE STAGE delta — ancillary ledger direction (proposed)

The independently selected inventory now carries exactly three additional `ancillary_refs`, each with a separately selected exact role URI under the whole-file proposed `$id`: `production_terminal_ledger` → `#/$defs/productionTerminalLedger`, `production_occurrence_ledger` → `#/$defs/productionOccurrenceLedger`, and `production_accounting_record` → `#/$defs/productionAccountingRecord`. They are **not** appended to the final's exactly 21 immediate `dependency_refs`. Direction is selected historical predecessor original bytes → terminal and occurrence ledgers → accounting → final; neither ledger may refer to inventory or final. Inventory is a selection witness, not an upstream input into either ledger.

Terminal ledger binds declaration/request/invocation, target/result, four policy digests, B/T, outcome/disposition and selected historical predecessor refs. Occurrence ledger binds the same invocation context, parsed P with explicit parsed identity/evidence entries, and a mandatory admitted-identity array (including `[]` when empty). The admitted identities must be a unique subset of parsed identities and counts must agree, but JSON Schema alone does not enforce those relational assertions. Accounting binds exact terminal and occurrence ledger refs, historical predecessor refs, declaration/request/invocation, target/result, policies, N/B/T/E/E_B/E_T/P/A and disposition/outcome. `context.accounting_digest` must be SHA-256 of **complete canonical accounting bytes**, not a domain-separated record ID; the prior candidate surrogate is no longer a permissible production accounting identity. Selection, byte equality, closure, cross-record equality, cardinality and subset checks are deferred to independent replay over original bytes. The current positive oracle's `candidate.proposed_p=0` against final `p=a=1` is invalid; it must not be locally patched or cited as GREEN in this schema stage.

## Host-selected attempt witness closure — revised contract proposal

Before invocation the host allocates a collision-safe invocation identity but does **not** claim the actual managed request key: that key is selected only after the owner observes a completed framed WRITE. It freezes the invocation, declaration, policy, session and generation in independently selected custody, and retains and readback-verifies the exact `attemptWitnessPolicy` original (role URI `#/$defs/attemptWitnessPolicy`) selecting role-specific schemas for initiation, keyed begin, terminal journal and scanner knowledge, and selects the pre-invocation declaration. The separate `#/$defs/attemptHostCustody` original binds policy and declaration refs, host session/generation, invocation and pre-invocation selection phase, with no `request_key` field (`additionalProperties:false`); the owner retains its expected canonical ref **outside** the claimant ledger/manifest graph before invoking the method. Its own phase flag is not an ordering proof: verifier compares exact custody/policy/declaration originals, readbacks, expected refs and independently observed invocation order. A rehashed post-response policy plus custody plus manifest is still rejected against that pre-invocation owner-held ref; if the owner-held selection or ordering observation is absent, replay is blocked. Every witness is a closed original-byte record with its own exact role URI (`#/$defs/attemptInitiation`, `#/$defs/attemptRequestKeyObservation`, `#/$defs/attemptQueryBegin`, `#/$defs/attemptTerminalJournal`, `#/$defs/attemptScannerKnowledge`), complete-byte SHA-256, byte length and basename selector. The host, **not the ledger claimant**, selects these originals after observation into immutable `#/$defs/attemptEvidenceManifest`. Its `initiation_ref` and `policy_ref` are required; `key_observation` separately has PRESENT with the exact `#/$defs/attemptRequestKeyObservation` ref or ABSENT_NOT_OBSERVED with no key/ref. The postwrite observation binds the preinvoke custody ref, declaration/invocation/session/generation, actual manager request key and wire ID, and original WRITE selector/digest/byte length; it asserts completed framed WRITE, **not** successful response or provider receipt. The owner retains expected WRITE/frame/key independently. A keyed begin requires the observation ref and actual matched response key; no observation means no begin, terminal or scanner and no fabricated key. `begin`, `terminal`, `scanner` each has `PRESENT` with an exact role-specific ref or `ABSENT_NOT_OBSERVED` without a ref. The manifest cannot refer to any ledger, inventory or final. For a pre-invocation unresolved target, only initiation/custody/manifest and a host-selected `#/$defs/attemptIncompleteInventory` witness are eligible; that role has no 21-ref array, explicitly absent target/result and an independently selected observed-predecessor subset. Failed post-begin missing-result paths also use explicit `ABSENT_NOT_OBSERVED`, never a placeholder digest. The complete production inventory is reserved for final eligibility; it alone retains exactly 21 historical immediate refs. Incomplete inventory selection is owner-held outside the claimant graph and does not become a final ref or replace any of three ancillary inventory refs. Host selection policy and actual original-byte publication/readback remain independent replay obligations; schema-valid refs alone do not establish the observer. Inventory selects `attempt_manifest_ref` separately from exactly three ancillary refs; final remains exactly 21 immediate refs. Terminal, occurrence and accounting ledgers bind that same selected manifest ref, with no reverse edge. Any missing required original, alias, role mismatch, schema revision substitution, stale invocation or changed bytes blocks issuance.

`N=1` is derived only from the host-selected pre-invocation initiation and declaration originals; `B=1` requires the keyed begin original; `T=1` requires exactly one replayable terminal journal original bound to that begin. An absent begin or journal is not an implicit count-zero original: observed absence is a distinct manifest status. Scanner `E` is a nonnegative integer only for a complete bounded top-level count, otherwise literal `UNKNOWN`; absent scanner is not E=0. Original-byte replay checks `0≤T≤B≤N`, `0≤E_T≤E_B≤E` when E known, `0≤A≤P≤E` when known, whole-result parse and admitted identity subset; shape constraints alone cannot infer those relations. No fabricated terminal is permitted.

The table names permitted envelopes, **not** a schema proof of per-state source truth. Terminal and accounting target/result evidence are explicit PRESENT-with-digest or ABSENT-without-digest; accounting need not cite an occurrence ledger for nonmethod incomplete states. COMPLETE/ITEMS and COMPLETE_EMPTY/EMPTY each require T=1 and both target/result PRESENT, while incomplete/no-terminal has null method outcome; independently replayed terminal/accounting agreement is mandatory. Final has no `verification` member: the independently selected no-replace publication/readback proof and fresh exact final readback are external issuance preconditions, not claimant context or immediate refs. In particular the accepted contract allows an owner-bound request outcome only where it can actually be issued; `PUBLICATION_UNVERIFIED`, `TARGET_IDENTITY_UNRESOLVED`, and no-terminal `INCOMPLETE` are never method outcomes. Failed or unknown ledger/accounting originals may remain retained for diagnosis without creating a production final. The earlier positive fixture's `candidate.proposed_p=0` versus final `p=a=1` remains blocked and unchanged.

## Falsifiers and review request

Schema/codec tests must reject unknown/duplicate fields, altered occurrence ID, plan supplied by caller, omission of each of 21 roles, extra ref, duplicate ref, swapped owner reads or Git phases, mixed schema IDs, changed transitive policy bytes, missing source/result, final self-reference, changed pre-invocation nonce, wrong generation and postcommit readback failure. Include valid complete replay, independently selected expected inputs and exact no-replace publication proof. An independent reviewer should return `ACCEPT_RECORD_IDENTITY_DELTA_FOR_IMPLEMENTATION_ONLY` or `REVISE` against exact document plus new schema bytes. This decision is a prerequisite to writing the production admission path; it is not occurrence qualification or live authorization.
