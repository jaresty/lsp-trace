# ADR 0007 Describe V2 — source-checked semantic acceptance proposal

**Status:** proposed review procedure, not a frozen evaluation policy or accepted description set. **Authority:** 0; **accepted:** false. This document does not authorize `census --resume`, any worker invocation, external enablement, feature identity, or ADR 0011/0010 admission.

## Evidence and corrected prerequisite

The private four-case stop at `.pi/evidence/adr0007-describe-resume-THs7PZ/sample-1/SPOTCHECK_REPORT.md` used 151 retained packets and 159 validated requests. Three child worker processes ran; the fourth, a legitimate second alternative, reached `RunV2` once but was rejected by the then-current singleton batch preflight before child-worker start and without a response. That is a historical outcome, not a fresh failure: commit `c67ac008` split `describerequest.ValidateRecord` (intrinsic integrity) from `Validate` (batch ordering), and current `describeworker.RunV2` calls `ValidateRecord`. Focused `TestValidateRecordSecondAlternativeRetainsIntegrity` and `TestRunnerV2ProcessExecutionProducesVersionedTerminalRecords` passed locally with offline Go settings. These tests neither replay the fourth model response nor qualify semantic content.

`internal/describerequest/v2_production.go` asks for C1's behavior, the need of its mechanically supplied consumer if resolved, and one-layer contribution. `internal/describeworker/records_v2.go` validates syntax, bounds, and host binding, and emits `authority: 0`, `accepted: false`, `completeness: UNKNOWN`; its `admissible_evidence_basis` assigns eligible labels, not proof that each sentence follows from that source. `COMPLETE`, `ABSTAINED`, and optional model-attributed citation suggestions remain worker output rather than a source-check verdict. The older four-packet operational pilot in `docs/pilot/adr0007/FINAL-PILOT-REPORT.md` is local-only and expressly does not establish semantic correctness or the current census-to-Describe path.

## Proposed per-record review (no automatic promotion)

1. **Input gate.** Bind the exact retained packet, request record ID, alternative ID/ordinal, graph/source custody, C1 and (if resolved) C2 source ranges and bytes, and worker invocation/response IDs. Check whole-batch canonical ordering independently of individual `ValidateRecord`. Count selected, preflight-rejected, invoked, terminal-response, failure, and unevaluated requests separately. A missing source body or mismatched binding is **UNREVIEWABLE**, not an accepted abstention or an absent behavior.
2. **Mechanically fixed topology.** Read the packet's host `consumer_resolution` and supplied C1/C2 roles before seeing the model text. If resolved, require `consumer_need.status=RESOLVED` and check the *particular* C2 need; if unresolved, require `UNRESOLVED`, empty need, and no invented C2 or boundary consumer. Model prose cannot change the selected consumer or add a CALLS edge. Disagreement is **UNSUPPORTED** even when the worker says `ABSTAINED`.
3. **Claim-by-claim source support.** Split each nonempty `target_role`, `consumer_need.value`, `provided_behavior.value`, `boundary_contribution`, and each factual limitation into independently falsifiable claims. For each, record exact C1/C2 retained source span(s), the permitted inference (C1 implementation versus C2 call-site use), and verdict **SUPPORTED**, **CONTRADICTED**, or **NOT_SHOWN**. Absence of an exact source witness is NOT_SHOWN, not evidence of the opposite. Do not let a generic `admissible_evidence_basis` or model citation suggestion substitute for an inspected span.
4. **Relative-use and scope gate.** When `consumer_relative=true`, verify that C2 uses precisely the behavior attributed to C1; C1 alone proves at most its own implementation. Distinguish passing, returning, or storing an identifier from validating or authenticating data with it. Reject invented effects, unconditional claims from error branches, skipped consumer layers, runtime execution, ownership, product purpose, feature identity, value, and repository completeness. Qualify uncertainty explicitly in `limitations`; a caveat does not cure a contradictory main claim.
5. **Per-record decision.** `REVIEW_SUPPORTED` requires every material positive claim supported and no topology/scope mismatch; `REVIEW_UNSUPPORTED` applies if any material claim is contradicted, not shown, or too ambiguous to approve as written; ambiguity is not proof of the opposite; `REVIEW_UNREVIEWABLE` applies if required admitted source or identities are absent. A genuinely cautious `ABSTAINED` can be counted as a terminal worker outcome, but never as a usable positive description. This rubric is a proposed reviewer decision vocabulary only; it does not modify response records' `accepted: false` or establish stakeholder acceptance.

## Qualification boundary before any broader campaign

This four-case review is a falsification set, not a representative quality rate. First freeze reviewer labels and source witnesses for a separately authorized bounded sample, including resolved, unresolved, multiple alternatives, missing source, false causal use, and contradictory limitations; establish independent adjudication and explicit disagreement handling. Separately predeclare numeric quality thresholds, denominators, privacy/retention, resource and attempt limits, stop/replay policy, artifact/runtime identities, and the authority that can approve a wider run. Until then, an unsupported claim or an unevaluable member prevents automatic full-catalog resume. A mechanically passing worker or a future passing rubric never accepts a feature inventory without separate semantic and stakeholder correction/acceptance.
