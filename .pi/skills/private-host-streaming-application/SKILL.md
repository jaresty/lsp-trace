## Explicit activation-gated alternative

This deliberately changes HOST startup order only when selected. It does not change the source/request/policy bytes, role frames, permissions, or old `run REQUEST [RUNID]` API.

1. Complete prompts/setup as above and retain the expected application digest (Configuration.ApprovalSHA256), exact RunID and both compiled RoleTasks. Do not launch either role or invoke a role wait yet.
2. Use the deterministic `activation-bridge.py` recipe below. The owner has read/bash only, no source/bundle interpretation, role-control discretion, Agent tool or permission to launch models. The parent owns the actual OS-owner Agent ID. Do not use an unowned `bash ... &`, daemon, SDK or service.
