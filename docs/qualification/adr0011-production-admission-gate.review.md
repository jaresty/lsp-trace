## 3. Closed terminal and cardinality contract

`N` = owner-declared queries before invocation; `B` = queries whose provider-output evaluation began; `T` = begun queries with exactly one terminal member disposition; `E` = returned result elements if a complete bounded top-level value permits a count, otherwise **UNKNOWN**; `P` = elements emitted by a *successful whole-result parse* (zero on any malformed result); `A` = newly admitted immutable occurrences. Enforce `0 ≤ T ≤ B ≤ N`, `0 ≤ P ≤ E` when E is known, and `0 ≤ A ≤ P`. Distinct element accounting records element-begun `E_B` and element-terminal `E_T`, with `0 ≤ E_T ≤ E_B ≤ E` when E is known. A later malformed element may yield a **diagnostic prefix count** separate from P and A. No unbegun member/element gets a manufactured terminal outcome.

**Closed method request outcomes, in precedence order:** `REVISION_MISMATCH`, `POLICY_MISMATCH`; `UNSUPPORTED`; `CANCELLED`, `TIMEOUT`, `RESOURCE_LIMIT`, `PROVIDER_FAILURE`; `MALFORMED`; `PARTIAL`; `COMPLETE_EMPTY`; `COMPLETE`. Exactly one applies only when an owner-bound request outcome can be issued. For references, `TARGET_IDENTITY_UNRESOLVED` is a separate **pre-invocation admission-gate disposition**, not `COMPLETE_EMPTY` or a fabricated method request outcome: it bars method-based admission with B=T=A=0. A valid response cannot create the target. Exact `null`/`[]` can have E=P=A=0 but cannot alone prove `COMPLETE_EMPTY`; the declared denominator and all policy/receipt checks must pass.

**Closed terminal query-member dispositions:** `EMPTY` (fully evaluated E=0), `ITEMS` (well-formed fully evaluated E>0), `MALFORMED`, `LIMITED`, `FAILED`, `EXCLUDED`. A member is not terminal until one of those is recorded; unbegun and begun-but-unfinished are states, not terminal dispositions. **Closed evaluated-element dispositions:** `ADMITTED`, `VALID_DIAGNOSTIC` (individually well-formed prefix in a whole-result `MALFORMED` request, never eligible for admission), `EXCLUDED`, `MALFORMED`, `LIMITED`, `FAILED_EVALUATION`. There is no fabricated `EMPTY` element for `null`/`[]`; valid-but-not-yet-admitted elements remain nonterminal. A malformed required later element makes the request `MALFORMED`, P=0 and A=0 for this policy even if an earlier element is independently diagnostic; a malformed element and any later unbegun element cannot be admitted. Admission exclusion with A=0 does not imply `COMPLETE_EMPTY`.

**Publication barrier within precedence:** after a keyed matched response but **before** a verified request receipt, parser-based request verdict or admission, any `COMMITTED_VERIFICATION_FAILED` becomes a distinct `PUBLICATION_UNVERIFIED` *acquisition/publication disposition* (not `PROVIDER_FAILURE` or a `COMPLETE_EMPTY` method outcome). `verified receipt = none`; `new occurrences admitted = 0`. Quarantine the potentially committed private bytes under the pinned root with selector/digest and a redacted failure inventory; no automatic retry or deletion can make them a verified receipt. A reviewed resolution may verify a separate no-replace successor or remove/quarantine-tombstone the bytes; it never upgrades the failed receipt retroactively. A precommit failure likewise issues no verified receipt. If terminal-member evidence cannot itself be independently replayed, no terminal request verdict is issued; record `INCOMPLETE` at qualification level instead of fabricating one.

## 4. Receipt, target, admission and retention dependency

Owner-selected private capture is default off; only the concrete managed acquisition owner chooses a pinned 0700 root, named versioned policies, positive limits and derived selectors. No public/transport caller supplies a root or overrides policy. Each no-replace 0600 regular single-link artifact must have post-read exact-byte verification and independent expected identity checks; `COMMITTED_VERIFICATION_FAILED` is never `VERIFIED`. The method receipt, query-target receipt, terminal ledger and occurrence ledger each use closed canonical versions, content-addressed selectors/digests, exact role/ordinal/multiplicity and cross-object links. Missing payload, stale generation, duplicate keys, unknown schema/kind, changed source/encoding/revision/policy or mismatched bytes blocks *all new* admission. Neither self-hash nor caller-supplied ledger flags authenticate production or independently establish `B/T`.

A references query target must be pre-existing and admitted under a separately replay-verified document-symbol transaction and matching exact URI/point/encoding/source/version/revision custody. Re-run unique strict most-specific nested selection containment. Only separately replayed, terminal, well-formed references results may issue one immutable `REFERENCES_SYMBOL` occurrence per original Location, oriented `REFERENCING_OCCURRENCE → REFERENCED_SYMBOL`. Equal locations keep separate zero-based ordinals and identities. Every occurrence binds method/target/terminal receipts, query and returned ranges, provider/adapter as reported, policy, session/generation/key, source/revision custody and `authority=0/accepted=false/completeness=UNKNOWN`. Unknown/partial/malformed/substituted inputs produce A=0. No connection to `PrepareTypedInput` or Leiden follows from occurrence admission.

**Deterministic retention lifecycle:** canonical query/result and target payload retention begins at owner-verified no-replace publication. Before admission the acquisition transaction owns the retained objects; upon admitted occurrence-ledger publication, that ledger owns an immutable dependency list of all method/target/source selectors and digests it needs for replay. Every live admitted ledger and derivative pins those dependencies. No automatic 24-hour expiration applies to canonical payloads (the optional framed diagnostics have their separate window). A maintainer-reviewed `RETIRE_DERIVATIVES_AND_REMOVE` decision permits removal only after the owner atomically verifies that no active admitted ledger or derivative references a payload; record an immutable removal/tombstone manifest with decision ID, exact selectors/digests, dependent set, outcome and failed deletions. A `PRIVACY_REVOKE` decision may force earlier removal only while atomically tombstoning **all** dependent admitted ledgers/derivatives so they cannot be used for *new* traversal, grouping or admission. Historical bytes and their original admission claims are not rewritten; tombstoned objects have `REPLAY_UNAVAILABLE_REMOVED`, not `VERIFIED`, and are no longer eligible active inputs. Missing payload without a reviewed manifest is `REPLAY_UNAVAILABLE_UNEXPLAINED`, a fail-closed integrity failure. Physical erasure, backups and secondary copies are not guaranteed by this logical lifecycle. References from retained occurrences must be checked before every deletion; no silent premature cleanup.

## 5. Occurrence-specific production qualification, then later gates

Before any **production** `REFERENCES_SYMBOL_V1` issuance, pin implementation, schema and admission-policy digests **for both the references path and its included document-symbol query-target receipt**. Independently execute every row and substitution in the [normative occurrence falsification matrix](adr0011-occurrence-falsification-matrix.review.md) against real clean registered Go/gopls fixtures and before/after Git observations; exact owner-default-off/capability/key/write/read/source and predeclared N; privacy/retention/publication limits; canonical no-replace replay; duplicate ordinals and malformed-prefix A=0; immutable admitted-occurrence artifacts and dependency/tombstone accounting. Synthetic peers remain controls. The required independent maintainer decision over that **occurrence-specific packet** is closed: `QUALIFIED`, `REJECTED`, `INCOMPLETE`. Absent evidence or acceptance is `INCOMPLETE`. No held-out grouping corpus is required to *admit an occurrence*.

**Downstream compatibility non-regression only, not admission predicates:** historical omitted-selector `CALLS_ONLY` bytes, CALLS schemas and typed staging rejection must remain unchanged. `programccompose`'s `MaxInputs=16`, `PolicyBytes` and strict `NODE_CONFLICT` are existing Program C composition invariants, not cardinality limits or authority for this occurrence gate; pin and regression-test their existing bytes/digests when separately enabling a new grouping-input family. Later `GroupingPolicyQualificationReceipt` requires its *own* frozen corpus/held-out results, composition policy, threshold evaluation and maintainer decision before Leiden. Source-context selection and any public CLI/MCP enablement have separate qualification; occurrence admission does not imply context completeness.
