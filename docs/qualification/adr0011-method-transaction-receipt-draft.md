# ADR 0011 private method-transaction receipt — boundary draft

**State: UNFROZEN.** This is a reviewable boundary and test inventory, not a schema, accepted method receipt, request-outcome classifier, occurrence admission, grouping policy, or public operation. [ADR 0011](../adr/0011-versioned-definition-reference-grouping-evidence.md) controls the claim ceiling. The [method-result grammar v1](adr0011-method-result-contract-v1.md) governs parsing only; the [receipt seam audit](adr0011-method-receipt-seam-audit.md) maps observed fields and gaps without claiming a receipt; the [fixture matrix](adr0011-method-fixtures.md) proposes, but has not executed, end-to-end cases.

## Four independent layers

| Layer | Required separation and claim ceiling |
| --- | --- |
| Method transaction | One bounded, exact-generation request for one selected method and exact query occurrence. Preserve request parameters, selected capability observation, provider/adapter and policy identity, limits, observed wire counters, terminal transport/error/result evidence, and raw-result retention under privacy bounds. A successful transport is **not** an admitted request or occurrence. |
| Method-result parse and request accounting | The parser accepts only a successful method result and returns exact response ordinals or a typed parse failure, never a relation. A separate request ledger applies ADR 0011's ordered outcomes and complete declared member denominator, with one terminal disposition per member whose evaluation began. `null` and `[]` do not independently imply `COMPLETE_EMPTY`. |
| Query-target and occurrence custody | A references request needs an independently admitted query-target receipt binding a pre-existing canonical identity to the exact query occurrence. Returned references cannot create that identity. ADR 0011's method-specific custody roles are `QUERY_OCCURRENCE`, `REFERENCING_OCCURRENCE` or lower-precision `REFERENCING_SYMBOL`, `REFERENCED_SYMBOL`, and `DEFINITION_TARGET`; they are not V6 `TARGET`/`CALLER`. Definition targets remain distinct returned items; no preferred target or endpoint-pair deduplication. Neither method creates `CALLS`. |
| Source-context supply | Exact query/target evidence and server-reported full display ranges are distinct. Document-symbol resolution and matching source supplies have their own bounded receipts and custody. Missing/withheld/ambiguous source is a separate terminal context disposition; it cannot repair missing target identity or erase a valid method occurrence. |

All resulting presentations retain `authority=0`, `accepted=false`, `completeness=UNKNOWN`; absence beyond the exact query, execution, feature identity, and repository completeness are never inferred. ADR 0011 now selects CALLS-parity producer-authentication limits: a future immutable method receipt and verifier may prove exact byte/identity consistency, never resistance to privileged same-process forgery or provider authentication. The present private observations and test-only publisher still do not issue such a receipt.

## Proposed transaction envelope, not a frozen serialization

An eventual immutable canonical query/result transaction record must bind, at minimum, the method and declared query member identity; exact request URI, position, position encoding, and (for references) `context.includeDeclaration`; managed session ID/generation; selected provider/adapter and capability observation; expected workspace revision/custody, document version/digest when available; method, privacy, and admission policy identities; requested deadline and per-request/document/message/byte/candidate/occurrence/work limits; whether invocation began; observed request/response message and byte counts; transport outcome; presence-aware JSON-RPC error code and bounded private diagnostic; exact bounded result payload with digest/length or an explicit withheld/unavailable disposition **ineligible for new occurrence admission without another qualified replayable source**; and a binding to the later parsed-result/terminal-member ledger. This list defines *questions for schema freeze*, not field names, canonical bytes, allowable omissions, receipt IDs, or numeric defaults. Do not copy error text or raw provider bytes into public failures.

Capability absence is separately recorded and forbids invocation. A server error is not an empty method result; the private transport now exposes `ServerErrorCode() (int, bool)` so code `0` differs from absence, but it does **not** map any code to ADR request outcomes. In particular, the proposed interpretation of JSON-RPC `-32601` as an explicitly unsupported selected method requires a separately frozen and tested method-policy rule; arbitrary server errors must not be collapsed to `UNSUPPORTED` or `COMPLETE_EMPTY`. Transport timeouts/cancellation, over-limit failures, and parser `MALFORMED` remain distinct. ADR 0011's request-level precedence (revision/policy mismatch; unsupported; pre-output terminal failure; malformed; partial; complete-empty/complete) applies only after separate identity, policy, member, and denominator evidence has been admitted. `TARGET_IDENTITY_UNRESOLVED` on references contributes no occurrence, irrespective of returned locations or source context.

## Next falsification gates before freeze

1. Select and version exact capability, method-request, and query-target receipt schemas, identity/digest algorithm, allowed omissions, byte/identity consistency verifier (not a producer-authenticating custody verifier), position encoding and revision policy; test mismatched generation/URI/range/version/digest, duplicate request keys at the receipt verifier, replay substitution, and privacy withholding. The private method transport now rejects duplicate decoded parameter keys (including escaped spelling) before metadata or wire calls, with a five-case RED/GREEN guard; that check does not bind a request receipt or query-target identity. Exact framed JSON-RPC request/response retention is optional diagnostic work under [the separate 24-hour frame-window proposal](adr0011-private-method-retention.proposed.md), not a prerequisite for this record or Leiden; canonical query/result bytes, terminal accounting, and their managed-path binding remain required. A private synthetic probe observed `uri`/`URI`, `line`/`Line`, and `includeDeclaration`/`IncludeDeclaration` pairs reaching `RoundTrip`, with the later value selected by Go decoding. The subsequent exact decoded-key preflight rejects single and competing aliases at the root and nested method objects before metadata or wire calls; eight alias cases were RED then GREEN. Canonical inputs retain their exact raw wire bytes in two controls. This private correction still does not authenticate a request receipt or admit a query target. A two-case RED/GREEN check also found and removed a caller-supplied duplicate member name from the private `FailureText()` diagnostic; this checks one preflight leak, not receipt-wide privacy. A method-result parser cannot supply these bindings.
2. Retain the private bound-precedence regression and verify it at the later receipt/admission boundary: a reported negative/over-limit server error with `-32601` cannot become `UNSUPPORTED` by bypassing selected hard limits. Separately test a bounded `-32601` versus other server codes, absent capability with zero calls, timeout/cancel, and raw-error withholding. No request-outcome mapping is frozen here.
3. Select the member-outcome vocabulary and declared-denominator model, then execute D/R-01–09 and R-10–12 from the fixture matrix against separate wire, parse, identity, ledger, and context assertions. Valid independent members may remain diagnostic under `MALFORMED`, but no malformed occurrence is admitted; unfinished members cannot produce `COMPLETE`.
4. Only after separate receipt/identity/custody verification consider occurrence admission and source-context projection; policy qualification, Leiden admission, CLI/MCP enablement, historical omitted-selector `CALLS_ONLY` behavior, and ADR 0010 attribution remain outside this draft.
