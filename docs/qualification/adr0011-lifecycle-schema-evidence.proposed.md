# ADR0011 lifecycle schema evidence — unaccepted

Independent implementation-only packet; no cleanup executed, no live capture, no row run, no public enablement, no alteration of historical issuance or CALLS. The lifecycle cutover delta is an unaccepted draft, and the bytes here must be independently reviewed before implementation.

## Exact roles and policy

The whole-file schema ID is `https://jaresty.github.io/lsp-trace/schemas/adr0011-lifecycle-v1.proposed.schema.json`; role URIs are that ID plus `#/$defs/fenceIntent`, `#/$defs/tombstoneChild`, `#/$defs/tombstoneRoot`, `#/$defs/unlinkAttempt`, `#/$defs/cleanupTerminal`, and `#/$defs/reconciliation`. Each role has one distinct domain `ADR0011_FENCE_INTENT_V1`, `ADR0011_TOMBSTONE_CHILD_V1`, `ADR0011_TOMBSTONE_ROOT_V1`, `ADR0011_UNLINK_ATTEMPT_V1`, `ADR0011_CLEANUP_TERMINAL_V1`, `ADR0011_RECONCILIATION_V1`. The record ID is SHA-256 of domain UTF-8, a zero byte and canonical JSON excluding `record_id`. Canonical JSON, URI and selector rules equal the admission packet. Selectors use `adr0011-<fence-intent|tombstone-child|tombstone-root|unlink-attempt|cleanup-terminal|reconciliation>-v1-<hex sha256(canonical complete record)>.json`. Refs bind original byte length, digest, role URI and selector. No self-edge, duplicate selector, role confusion or cyclic predecessor graph. Independently pin complete schema and lifecycle-policy hashes before selecting any implementation. Schema validation establishes shape, not truth of root identity, epochs, syscall reports or dependent completeness.

## Cross-process lock and durable cutover

The existing selector `sync.Mutex` is process-local and does not satisfy this policy. A future implementation must use an OS advisory exclusive file lock shared by all root participants (on macOS, `flock(LOCK_EX|LOCK_NB)` on an `openat`-opened no-follow lock file; bounded retry; never lock a replaced inode). Under the owner-only root, require regular 0600 single-link lock-file descriptor and independently verified root device/inode. All new publication, admission, pin, new-use replay and cleanup actors acquire this lock, verify the latest immutable monotone epoch and active fence, and fail closed on unsupported platform, stale epoch, missing/invalid record or lock timeout. No provider call occurs while holding the lock. A lock release or crash does not release a verified durable fence. A verified no-replace fence intent binds decision, exact closure, previous epoch digest and root identity, with directory sync/readback; under lock enumerate complete dependent/pin set and publish child tombstones. For revoke, publish and verify a root covering exactly the independently enumerated sorted dependents, one child per dependent and matching child digest, count, intent and epoch. Root verification plus full child replay is the single all-dependent eligibility cutover; partial children remain inert while fence blocks use and unlink. Readers under lock check the latest epoch/root; stale in-memory readers cannot grant new eligibility. For retirement, pin absence must be independently verified at the fence and before every unlink. Revoke tombstones all dependents first; logical invalidation is not physical erasure.

Before each unlink, under the same root lock, revalidate epoch, fence, exact current pin/dependent set and retirement eligibility or verified revoke root. Retain a fresh attempt with expected byte identity, pre-read, syscall, post-read, close and directory-sync status. `REMOVED_VERIFIED` requires every expected selector absent and every attempt plus sync independently replayed. Missing-at-attempt without an earlier verified terminal is unexplained loss; successful unlink followed by failed sync is uncertain durability, never successful erasure. Partial failure may yield an uncertain terminal but never release the fence or turn an unverified final into an issuer. A retry is a new reviewed attempt with fresh observations. On restart, lock and replay latest verified epoch, intent, child/root, attempts, terminal and reconciliation; a verified no-unlink abort may restore eligibility only after complete byte observation under lock. Once root is verified, physical reappearance does not restore eligibility. An unverified latest epoch or terminal keeps use denied. Backup/physical erasure claims are explicitly outside scope. Historical issuance bytes and counts never change.

## Negative counterexamples

Schema rejects: unknown field in each role, zero epoch, missing intent ref, duplicate identical child entry, invalid selector, negative ordinal, unknown syscall outcome and an empty terminal attempt set. Semantic replay rejects despite schema-valid bytes: two processes racing a pin across verified fence; stale epoch during second unlink; child/root set cardinality mismatch; correct count but swapped child digest; root publication without directory sync or exact readback; partial children without root; restart after verified fence with bytes present; unlink success but directory sync failure; already-missing object without earlier terminal; purported verified removal while an active pin remains; reused decision ID; root inode substitution; reappearing bytes after root; and reconciliation claiming no unlink while one selector is absent. These require cross-process and crash-injection tests at fence, child, root, unlink and sync boundaries in a later implementation stage, not live capture now.

## Executable proposal-only verification (not authority)

`schemas/adr0011_prerequisite_replay_proposed_test.go` uses `github.com/santhosh-tekuri/jsonschema/v6` with `AssertFormat()` and compiles **each** lifecycle role at its exact `$id#/$defs/<role>` URI, not the permissive bare root. Each role receives valid and missing/extra/wrong-role shape fixtures; empty terminal attempts fail shape validation. Original canonical bytes and duplicate JSON names are checked independently. Schema-valid replay counterexamples are run against independent expected epoch, intent, dependent set, child set, observed bytes, attempt and root-readback inputs: partial children without verified root, count/child mismatch, stale epoch, already-missing object, unlink-success/sync-failure, byte reappearance and no-unlink abort while bytes are missing all reject. The fixture is a proposal-level semantic model, not a production filesystem or process-lock test. Two-process contention, crash injection and actual lock/no-replace publication are **implementation-stage** acceptance gates, not prerequisites to this schema-contract review.
