# ADR 0011 — RESOLVES_TO_DEFINITION occurrence contract (proposal)

**Status: PROPOSED / INDEPENDENT READ-ONLY REVIEW RECOMMENDED `REVISE`; NOT ACCEPTED, IMPLEMENTED, ADMITTED, OR QUALIFIED.** Review identified open query-range, origin-hint, cross-document exclusion, identity, evaluator-observation, strict-parser and retention-state policies. Drafting and correction may overlap references qualification. Definition implementation may begin only after an independent `QUALIFIED` decision on `REFERENCES_SYMBOL_V1` **and** acceptance of a closed definition implementation contract. Definition qualification is a separate `QUALIFIED | REJECTED | INCOMPLETE` decision. No definition occurrence, grouping input, Leiden edge, or public operation is authorized by this document.

## 1. Method and meaning

- Proposed method: exactly `textDocument/definition` against an exact READY, generation-pinned, capability-reporting managed session. A missing advertised definition capability means **zero method invocation**. Admission is language-neutral at the ledger boundary but each provider/language requires a separately frozen executable/version/capability/revision profile and a qualified range adapter. The first proposed profile is clean registered Go/gopls; it is **not** the only supported language. CUE needs its own range adapter and exact provider profile before CUE evidence is eligible. A historical session label is not a provider selection.
- A query is a **predeclared, source-bound submitted occurrence**, not an inferred reverse lookup and not automatically an admitted references target. It binds an exact URI, position and independently established occurrence range/identity, encoding, document version/digest, session/generation, host-observed clean Git before/after, and caller-asserted revision. **User-selected draft policy:** a versioned per-language range adapter resolves exactly one identifier in the prepared source; for initial Go use `GO_IDENTIFIER_RANGE_V1` with a bounded lexical scan of the exact source, half-open UTF-16 identifier span, cursor at its start or interior but not at its end or inside a surrogate pair, and a recorded source/version/digest and range-policy ID. Zero, ambiguous or over-bound matches reject before invocation. The owner must independently no-replace publish and replay-verify a **subordinate `DEFINITION_QUERY_OCCURRENCE_V1` receipt** containing exact source, range adapter/version, selected token/range, query identity, pre-invocation Git/capability and terminal disposition; the definition response cannot create its own query occurrence. Other languages must independently specify and qualify their own identifier/range adapter, not reuse Go parsing. No definition method may fill a missing references target silently.
- Each returned definition target yields its own `RESOLVES_TO_DEFINITION` occurrence oriented **submitted query occurrence → returned definition target**. `Location` binds URI and `range`; `LocationLink` binds URI, `targetRange` and `targetSelectionRange` (the latter must be contained in the former). **User-selected draft policy:** if `originSelectionRange` is present, require exact equality with the independently established query range; a mismatch makes the whole result `MALFORMED`, P=A=0 (any valid prefix is diagnostic only). A returned target is not independently verified semantic truth.
- Preserve original zero-based result ordinals, including equal returned targets. **User-selected draft policy:** target candidate identity is transaction-scoped; equal targets in one exact transaction may share it, never across queries by implication. Occurrence IDs remain distinct and bind domain/version, exact transaction/query, target bytes and ordinal. The existing private candidate ID is not automatically an admitted identity. No preferred target, collapsing of duplicate Locations, `CALLS` retyping, or arbitrary provider substitution is allowed.

## 2. Accepted shapes and exact transaction

**Selected draft grammar:** one scalar `Location`, one homogeneous array of `Location`, one homogeneous array of `LocationLink`, exact `null`, or `[]`. A scalar `Location` has one returned element; `null` and `[]` have zero but distinct canonical bytes and receipt identities. Scalar `LocationLink`, mixed arrays and arrays of scalar/null elements are rejected; a zero-length array retains its empty shape without inventing an element type. For initial Go/gopls only, all query and target URIs must be canonical absolute local `file:` URIs within exact registered clean source custody; other-language URI policies require their own profile. Mixed-shape arrays, scalar `LocationLink` unless independently contracted, unknown/duplicate JSON keys (including aliases), missing required ranges, invalid nesting or URI, and trailing content fail closed; a valid prefix of a malformed whole result is diagnostic only. Every returned cross-document target requires an independently supplied exact URI/version/digest under the selected source policy; no ambient checkout or implicit definition fallback. **User-selected draft policy: all-or-none admission.** If any required target supply is unavailable after a successful whole-result parse, retain a verified method/diagnostic terminal with `COMPLETE` method outcome, `EXCLUDED` query disposition, E/P as independently measured, A=0 for **all** targets. This is not `COMPLETE_EMPTY`; evaluated elements receive their independently observed dispositions. No occurrence ledger can claim partial admission.

Exact-byte transaction identity includes method, raw params and their digest (semantically equal reformatting is distinct), declared occurrence/range, negotiated encoding, capability/provider/adapter as reported, session/generation/key and collision-safe invocation identity, completed keyed write/read, result presence/payload/digest, query and target source custody, revision, and versioned privacy/method/admission policy IDs. Proposed `DEFINITION_CAPABILITY_V1` is a separate manager-owned receipt binding exact session/generation, READY state, reported provider/profile/executable identity, negotiated encoding, and present/absent definition support as advertised at initialization; no capability means no method invocation. Draft policy IDs are `DEFINITION_METHOD_V1`, `DEFINITION_PRIVATE_EXACT_V1`, `DEFINITION_OCCURRENCE_V1` and per-language range/resolver IDs. Each has an independently frozen canonical schema and digest before contract acceptance; the strings alone are not schema registration. Frames are optional diagnostics; canonical raw payload is mandatory. Source, revision, host Git, and LSP claims remain separate: `HOST_OBSERVED_GIT` does not make workspace revision `PROVIDER_VERIFIED`; producer authentication is not established. Every artifact has `authority=0`, `accepted=false`, `completeness=UNKNOWN`, `NO_PRODUCER_AUTHENTICATION`.

## 3. Bounds, outcomes and accounting

**Proposed fixed initial `GO_GOPLS_DEFINITION_EXACT_V1` limits for review, not yet accepted:** 16 owner-predeclared queries per acquisition; one query per method request; 1,000 returned targets; 65,536 exact parameter bytes; **524,288 result bytes** (below the current owned Manager's 1,048,576-byte total response-wire ceiling); 1,500,000 complete canonical-record bytes; 4 messages and 1,048,576 total wire bytes per request; 15,000 ms deadline; 262,144 bytes per prepared document; at most 21 document requests per query including the query source, 8,388,608 total prepared-document bytes per query; 100,000 bounded evaluation work units (one JSON token inspected, one source token scanned, or one document request is one unit); and 128 MiB maximum total canonical bytes retained per acquisition. The host owner must select a versioned privacy policy before any retention, with exact raw query/result payloads private and diagnostics redacted; the policy ID/digest and no-auto-expiry canonical retention are receipt-bound. A byte/work/wire limit reached before safe counting leaves E=UNKNOWN. Distinct caps must be independently exercised; a 1,001-target fixture must fit the lower result/wire bounds to test the element cap. Do not truncate targets. These choices are proposals subject to independent contract review and feasible Manager verification, **not** Program C limits.

Use the references contract's closed request outcomes and precedence (`REVISION_MISMATCH`, `POLICY_MISMATCH`, `UNSUPPORTED`, `CANCELLED`, `TIMEOUT`, `RESOURCE_LIMIT`, `PROVIDER_FAILURE`, `MALFORMED`, `PARTIAL`, `COMPLETE_EMPTY`, `COMPLETE`) and separately closed query/element dispositions, with definition-specific pre-invocation `QUERY_IDENTITY_UNRESOLVED` disposition proposed for review. Pre-invocation dispositions are **not** successful empty method results. A committed-but-unverified publication is `PUBLICATION_UNVERIFIED`, not a method outcome. Do not issue an unverified terminal.

Internal manager completion, evaluated request state, and **issuable terminal** are distinct. `N` owner-declared queries; `B` provider-output evaluations begun; `T` begun queries whose terminal-member disposition has passed independent no-replace publication/readback; `E` returned elements when a complete bounded top-level value permits a count, otherwise UNKNOWN; `E_B/E_T` independently observed element evaluations begun/terminal; `P` whole-result successfully parsed elements (zero for any malformed result); `A` newly admitted immutable definition occurrences. Require `0 ≤ T ≤ B ≤ N`, `0 ≤ E_T ≤ E_B ≤ E` when E known, `0 ≤ P ≤ E` when known, `0 ≤ A ≤ P`. Preserve scalar-versus-array result shape and original ordinals in the receipt. A diagnostic valid prefix never contributes to P or A. Parser-derived final item count alone is not evidence that evaluation transitions occurred.

**Proposed closed observation carrier `DEFINITION_EVALUATION_V1`:** bind the exact query receipt, keyed completed write/matched read or explicit no-match failure, method/result presence and exact bounded payload digest, source/revision/capability receipt, evaluator policy, work limit, and an ordered immutable event sequence. Emit `QUERY_BEGIN` only when output evaluation actually begins. For each inspected element emit `(ordinal, ELEMENT_BEGIN, bounded offset/digest)` before evaluation and exactly one terminal `ADMITTED | VALID_DIAGNOSTIC | EXCLUDED | MALFORMED | LIMITED | FAILED_EVALUATION` only when observed; an uninspected later element has no event. A separate bounded complete-top-level counter supplies E, including 1,001 without evaluating over the element cap; if it cannot finish under result/byte/work bounds, E=UNKNOWN. `WHOLE_PARSE_SUCCESS` records P only after all elements succeed; any malformed result sets P=A=0 despite diagnostic prefix events. `PUBLICATION_ATTEMPT/PRECOMMIT_FAILED/COMMITTED_VERIFICATION_FAILED/VERIFIED` records the independent terminal barrier: observed internal method completion may precede it, but no verified terminal means T=0 and no newly issued A. `VERIFIED_DIAGNOSTIC` may establish a non-success terminal only when its redacted record replays independently under privacy limits. Replay rechecks exact event order, ordinals and counts; neither a final parser item slice nor a caller-supplied ledger flag may manufacture events.

**Partial frames require a future managed observation seam:** a bounded manager-owned wire-prefix record must carry exactly acquired bytes/length/digest, request key, write completion, read phase, cancellation/timeout/limit cause and selected privacy disposition. The evaluator may count a valid complete prefix **only** from those observed bytes with recorded events; an absent/withheld prefix leaves E_B/E_T unproven and the partial fixture `INCOMPLETE`. A complete `RoundTripResult.CompletedOwnedMethodPair()` alone cannot establish this case. This is an implementation requirement, not a claim that such a Manager API exists today.

## 4. Publication, replay, and retirement

Only the concrete host owner may choose a private pinned 0700 root, default-off enablement after qualification, selected policies, and positive bounds; no transport caller provides root or enables issuance. Before method invocation the owner must publish and replay-verify the independently derived `DEFINITION_QUERY_OCCURRENCE_V1` receipt. It is a mandatory dependency of every definition method, terminal and occurrence ledger; missing, stale or substituted query receipt causes B=T=A=0 and zero invocation. Reuse *mechanisms*, not references semantics: canonical bounded method/query/source records, terminal and occurrence ledgers, no-replace 0600 single-link files, exact-byte readback with independent identity checks, and separately pinned selector/digest/dependency links. Every occurrence binds method, query/source, target supply, terminal, provider/revision custody, original ordinal, and direction. No verified mandatory payload means A=0. Precommit failure yields no verified receipt; committed verification failure quarantines exact potentially committed bytes and issues no new occurrence, without retroactively upgrading that receipt.

An admitted occurrence ledger pins all replay dependencies, including query derivation, source and target supplies. **Proposed lifecycle state machine:** under one root-scoped publication lock, allocate dependency pins before making an occurrence ledger active; publish an immutable active-ledger manifest with selectors/digests and a monotonic generation. Reviewed `RETIRE_DERIVATIVES_AND_REMOVE` may proceed only after rechecking zero active dependents under that lock and publishing the removal manifest before deletion. `PRIVACY_REVOKE` publishes one atomic complete-set tombstone manifest for every dependent admitted ledger/derivative *before* any payload deletion; readers treat the manifest as the eligibility barrier. Concurrent issuers must recheck root generation/tombstones under the same lock before publication. The versioned `DEFINITION_DEPENDENCIES_V1` manifest must bind generation, decision ID, ordered occurrence and derivative selectors/digests, each query/method/target-source/terminal/payload selector/digest, effective state (`ACTIVE | TOMBSTONED | QUARANTINED`), previous manifest digest, and attempted/failed deletions. The complete-set tombstone manifest is the single visibility barrier; readers check the newest verified manifest before using any dependency. A failed manifest write forbids deletion and new eligibility changes. Failed deletion is quarantined; unreviewed missing payload is `REPLAY_UNAVAILABLE_UNEXPLAINED`, not a legitimate tombstone. Historical immutable bytes are not rewritten. Source-context absence cannot silently change valid occurrence identity.

## 5. Required freezes and unresolved decisions

The user selected drafting policies for (1) per-language unique-identifier range derivation (Go first, other languages require their own qualified adapters); (2) rejecting `originSelectionRange` mismatch; (3) transaction-scoped target candidate identity; and (4) all-or-none target-supply admission. **Independent review must still test their exact source/range boundary and terminal accounting.** The draft now selects result shapes, initial Go/gopls profile and positive bounds, and proposes an atomic retention order. **Still required for contract review readiness:** prove these bounds are jointly feasible and independently review the proposed `DEFINITION_EVALUATION_V1`/partial-wire, strict parser, dependency manifest, capability receipt and closed schema/policy versions. These version strings are draft design identifiers, not registered schemas or pinned digests. Neither those design choices nor this document grants implementation acceptance. Pin contract and matrix digests for implementation acceptance; later pin implementation, schema, method/admission/privacy policy, and target/source/retention digests independently of references. Execute [the proposed definition matrix](adr0011-definition-occurrence-matrix.proposed.md) against synthetic controls **and real clean registered fixtures** before requesting an independent definition `QUALIFIED | REJECTED | INCOMPLETE`. References and definition decisions may not be combined. Grouping requiring definitions stays blocked until definition qualification.
