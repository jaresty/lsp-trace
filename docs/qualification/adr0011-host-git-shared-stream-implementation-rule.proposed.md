# ADR0011 host-Git shared output objects — implementation-only rule

Status: **PROPOSED**. This clarifies publication accounting for the accepted host-Git observation schema without changing its bytes, selectors, roles, or occurrence policy.

A host-Git observation has six mandatory stdout/stderr object references. Those references are content-addressed by the exact byte SHA-256, so equal streams—including every zero-length stderr and an empty status stdout—select **the same private object**. A BEFORE and AFTER observation in one local transaction may reference that same exact immutable object. This is not permission to overwrite it or accept a colliding preexisting object by hash alone.

The acquisition owner keeps a private transaction-scoped map indexed by the derived output selector. On a new selector, publish exact bytes with no-replace, require the publication receipt's mechanism, directory-sync and close statuses, perform independent exact readback, and record the owner-held VERIFIED selector/digest/byte-length and publication receipt status. Duplicate references inside that observation reuse only this VERIFIED entry, with another exact readback. A later AFTER observation may reuse a BEFORE entry **only when passed the same owner-held verified map from this transaction** and after checking selector, digest, exact length, and independent exact readback again. A different transaction, lost map, missing object, unknown prior receipt, or conflicting existing selector is not eligible for reuse, even when current bytes happen to match. Every logical stream is still independently reread during record replay. The immutable output object may be shared by multiple records; the records remain distinct by phase and timestamp.

Publication result accounting is conservative. Before any possible commit, failure is `ABSENT`. After any attempted no-replace publication with uncertain commit (including nil receipt, collision with unknown provenance, directory-sync/close failure, or readback failure), or after an earlier stream committed even if a later new stream fails before commit, the transaction outcome is `COMMITTED_UNVERIFIED` and retains the last possibly committed selector; it must not return `ABSENT` or authorize a host-Git record. A verified prior stream can be reused without a new publication only under the rule above. The last committed object is not the complete observation; an independently replayable host-Git record is `VERIFIED` only when all six output references are verified and its own no-replace record, exact readback and dependency replay succeed. Retained record replay may reread an object but cannot reconstruct a lost publication receipt as a new issuance decision. A verified transaction closure requires explicit VERIFIED stage for each selected predecessor, not merely successful decoding of a COMMITTED_UNVERIFIED object.

This map and its receipt statuses are private, in-memory implementation custody, not schema fields, producer authentication, general deduplication, or a public response. No ordinary traversal may silently publish, hydrate, replay, or rebuild these objects. This rule permits synthetic implementation/falsification only; no revision identity, final references issuance, nonzero authority, or occurrence qualification follows.
