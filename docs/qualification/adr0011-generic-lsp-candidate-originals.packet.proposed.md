# ADR0011 generic exact LSP: candidate-originals decision packet

**PROPOSED / authority 0 / no selected or issued identity.** Reviewer choices below are not defaults. This packet supplies candidate names and a byte-construction recipe for independent maintainer review, not normative schema IDs, approved policy bytes, registration, implementation acceptance, provider qualification, acquisition, or live issuance. `GENERIC_LSP_REFERENCES_EXACT_V1` and `GENERIC_LSP_DEFINITION_EXACT_V1` are proposed additive selector names; neither aliases nor changes accepted `REFERENCES_SYMBOL_V1`, `GO_GOPLS_EXACT_V1`, its 162-row matrix or 21 final-reference dependencies. Omitted selector remains `CALLS_ONLY`. No allowlist or mandatory per-provider profile is introduced. Existing definition proposals are not accepted originals.

## Decision boundary and vocabulary

Assumption: the successor implementation proposal requires independently selected role-separated originals before closed exact acceptance (see `adr0011-generic-lsp-admission-successor-v1.proposed.md` §§5, 43). Consequently every identifier in this packet is a **candidate label**, not a minted URI. Proposed deterministic label grammar: `CANDIDATE_ADR0011_GENERIC_<METHOD>_<ROLE>_V1`, where METHOD is `REFERENCES` or `DEFINITION` and ROLE is one of the exact ASCII tokens below. A shared transport role instead uses `CANDIDATE_ADR0011_GENERIC_SHARED_<ROLE>_V1`. No consumer may treat these labels as accepted schema `$id`, policy ID, selector, artifact selector or replay domain.

| Role | Owner-published original / necessary distinction | Candidate reader | Predecessors (all exact and same transaction unless stated) |
| --- | --- | --- | --- |
| `POLICY`, `SCHEMA` | Independently selected immutable bytes per method and role, respectively; private policy versus public schema publication undecided | owner, strict replay verifier | maintainer selection, not a producer claim |
| `QUERY` | predeclared exact URI, version, source digest/bytes, point, negotiated encoding, method, query and occurrence namespaces | owner, verifier | `POLICY`, `SCHEMA`, `SOURCE` |
| `SOURCE` | independently owner-held query bytes and every target's URI/version/digest/bytes with custody kind and before/after facts | owner, verifier | selected custody contract; never ambient checkout |
| `PROCESS` | configured path/URI, argv, relevant environment/config, complete measured executable bytes/length/digest, measurement phase and race/correspondence status; optional serverInfo assertions with explicit absence | owner, verifier | READY session/generation, selected process-custody policy |
| `CAPABILITY_EVENTS` | original initialize and ordered complete register/unregister notification bytes; event ID, method, original options/selector presence, observed generation/order and effective support snapshot | owner, verifier | `PROCESS`, session/generation; static and dynamic contributions distinct |
| `REQUEST_WRITE` | original params and complete framed WRITE with **actual** request key assigned only after completed write | owner, verifier | `QUERY`, `CAPABILITY_EVENTS`, `PROCESS`, `POLICY` |
| `INBOUND_FRAMES` | all complete inbound frames actually consumed, original header+body, ordered offsets and per-frame byte lengths; partial prefix separately recorded | owner, verifier | `REQUEST_WRITE` |
| `RESULT_READ` | completed matched keyed READ, exact original result token and offsets, response ID, raw-presence distinction and strict parse disposition | owner, verifier | `INBOUND_FRAMES`, `REQUEST_WRITE` |
| `TARGET_EVENTS` | original zero-based ordinals, begin/terminal events, whole-parse denominator, location/link typed spans, equal-return multiplicity and per-target source dependency | owner, verifier | `RESULT_READ`, target `SOURCE` |
| `TERMINAL` | N/B/T/E/E_B/E_T/P/A, earliest causal failure, typed disposition, no-replace publication state and quarantine state | owner, verifier | `TARGET_EVENTS`, `RESULT_READ`, all preceding originals |
| `READBACK` | independent readback of every selected original, then separate fresh external final readback and correspondence verdict | independent verifier, downstream reader | committed `TERMINAL` and all role originals |

These are candidate **logical roles**, not an assertion that one file per row is sufficient: reader and publisher identities, public versus private partition and permissible co-location must be selected. An edge points from dependent to predecessor; no receipt can authenticate its own missing predecessor. Original bytes cannot be replaced by normalized JSON, owner-reported hashes, latest-generation contents, or a claimant `verified` bit. The downstream typed grouping reader, if separately admitted later, reads only a verified bounded occurrence and never grants `CALLS`, semantic identity, accepted feature identity or production authority.

## Candidate byte and collision-domain recipe (not selected)

Assumption: a digest is meaningful only over fixed exact bytes with a separate role and domain. Candidate serialization for *new metadata envelopes only*: UTF-8 JSON with sorted Unicode-scalar key order, no duplicate decoded keys, integer decimal without exponent/leading zero, JSON standard escapes with shortest required escaping, no insignificant whitespace, no trailing newline; arrays preserve order, explicit `null` differs from absent, and binary originals are referenced by length and lowercase SHA-256 while retained separately byte-for-byte. This is a **review option**, not an instruction to reserialize LSP originals or an assertion of an existing canonicalizer. Alternative R: length-prefixed binary field encoding with separately fixed field tags and integer widths; reviewer must choose one and approve test vectors (empty, Unicode, escaped-key collision, absence/null, reordered array, raw-frame CRLF, 2,097,152 boundary) before deriving any accepted digest.

Candidate domain preimage (UTF-8 ASCII fields encoded as `uint64_be(length) || bytes`, concatenated in fixed order): `"ADR0011-GENERIC-EXACT/CANDIDATE/1"`, selector token, method token (`textDocument/references` or `textDocument/definition`), role token, role-schema exact-byte SHA-256, method-policy exact-byte SHA-256, session ID, generation as canonical unsigned decimal, and exact artifact-original SHA-256. Candidate artifact selector: `sha256:` plus lowercase SHA-256 of this preimage. A distinct **query** domain additionally binds exact URI bytes, source-version token, source-byte digest, negotiated encoding and nonnegative line/character; an **occurrence** domain additionally binds actual keyed WRITE, raw result-token digest and original zero-based ordinal. A `null`/`[]` terminal has no fabricated occurrence ordinal. This recipe does not settle namespace ownership, whether URI normalization is forbidden versus specified, stable source-version encoding, policy/schema registry URI, hash collision handling, preimage privacy leakage, or whether the private selector can safely cross publication boundaries. Reviewer must select and freeze exact byte fixtures, including two same-URI different versions/points and two equal locations at different ordinals. Never substitute a hash for retained original bytes.

## Candidate immutable policy fields and finite ceilings

Assumption: the successor proposal supplies a **selected wire invariant** but leaves other method ceilings and original custody unselected. A candidate policy must bind exactly: selector/version; method and strict capability options grammar; initialize static contribution; dynamic registration ID+method+event index, selector omitted/null/filter semantics, snapshot-before-WRITE rule; query-source custody variants and point/encoding validation; launch-chain/process correspondence and serverInfo absence semantics; method result grammar, duplicate-decoded-key rejection, raw token/ordinal preservation; event accounting and earliest failure precedence; exact role/schema IDs and digests; no-replace publication, quarantine, independent final readback; private retention/access/redaction/revocation; authority 0/accepted false/completeness UNKNOWN; and all limits below. Unknown field or absent mandatory original is not an implicit permissive default.

| Bound | Candidate for review, **not selected policy** |
| --- | --- |
| every complete inbound frame, header + body | **2,097,152** consumed bytes inclusive; over by one fails even for unrelated frame |
| definition decoded body / raw result | proposal's 1,048,576 / 524,288 bytes; reviewer must explicitly select or revise |
| references decoded body / raw result | **unselected**; accepted V1's 1,048,576 result cap is not automatically transplanted |
| partial frame bytes/messages/deadline/work, total messages/bytes, overall deadline, allocation/work, source/executable bytes, object/event counts, retained bytes and retention duration | **unselected positive finite values** for each; no closed acceptance until selected and independently tested |

The grammar is `references: null | Location[]`; `definition: null | Location | Location[] | LocationLink[]`, homogeneous arrays only. A scalar LocationLink, mixed array, escaped duplicate decoded key or malformed later element fails whole parse (P=A=0); equal references remain separate ordinals. Unknown denominator never becomes zero. A complete `null` or `[]` differs from nonempty exclusion. The definition-only proposed 2/2/1/0 `EXCLUDED_VERIFIED` witness requires both ordinal terminals, source unavailability proof, committed publication and independent plus fresh final readback; it does not authorize generalized nonempty exclusion. Partial EOF is not a complete frame. Committed-unverified stays quarantined, outcome null and T=A=0. These rules are candidates for dedicated method policies, not changes to V1.

## Reviewer-selectable decisions and stopping rule

1. **Role granularity:** select row-separated schemas or a shared envelope schema with per-role discriminators; in either case freeze each role URI/version, exact bytes/digest, publisher, reader, predecessor edge and collision domain. Reject co-location if original-event order or custody becomes unverifiable.
2. **Canonical metadata:** select the JSON recipe or binary alternative, with exact encoding fixtures and URI/version/absence decisions. Do not canonicalize wire originals.
3. **Policy separation:** select shared transport + two method policies or two fully independent method policies; fix references-specific decoded/result limits and every positive finite ceiling above, method options and selector-null rules, custody/private retention and executable-chain correspondence. Do not imply that static true plus later unregister becomes unsupported: static survives; dynamic ID and method must both match, and event ID+method are original evidence.
4. **Source alternatives:** select owner-held versioned buffer, managed virtual document, clean registered Git worktree, or a narrower reviewed set; each requires exact URI/version/bytes and target-source correspondence. No provider-name or binary allowlist; a changed process/source is distinct evidence, a raced or missing required original blocks issuance.
5. **Authority and release:** decide implementation-only acceptance separately from identity-original selection, synthetic assertion-specific RED/GREEN, real-provider qualification, held-out CUE, public wiring and lifecycle. Until all exact originals and independent reviewer choices are frozen, verdict is `REVISE / INCOMPLETE`, never closed exact acceptance.

No proposed JSON schema or policy file is emitted: finite limits, private byte custody, schema ownership and selector routing remain open, so synthetic GREEN over an arbitrary partial JSON file would falsely suggest a closed original. A meaningful synthetic RED/GREEN must independently falsify missing/wrong role or policy bytes, changed query URI/version/point/encoding, malformed capability event or ID+method, static support surviving dynamic unregister, same-transaction process race, absent target bytes, escaped duplicate key, equal ordinal multiplicity, unrelated frame at cap and cap+1, partial EOF, omitted terminal and failed final readback. Exact fixtures and expected counters must be selected first.

**Stop before closed exact acceptance.** Independent maintainer must record each choice, issue exact role/schema URI and version, exact immutable policy/schema bytes and SHA-256, collision-domain fixtures, publisher/reader graph and qualified bounded tests in a separate reviewed decision. This packet cannot perform selection by being merged or hashed.

## Model interpretation

Interpretive choice: candidate labels permit a concrete review without treating a proposal as an issued original. Assumptions: the predecessor implementation proposal and its authority-zero ceiling remain proposals; exact wire originals must survive metadata encoding. Gaps: all unselected fields and finite limits above. Verification: inspect sole-file prose diff, `git diff --check`, and independently review byte fixtures before schema/test work. Improved framing: approve a decision record first, then derive immutable bytes from it rather than retrofitting authority to a candidate hash.
