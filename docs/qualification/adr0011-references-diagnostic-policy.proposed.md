# ADR 0011 references diagnostic D — proposed private policy

**Status: PROPOSED / NOT SELECTED / NOT QUALIFIED.** This is a diagnostic-only contract proposal subordinate to `adr0011-occurrence-falsification-matrix.review.md` and `adr0011-production-admission-gate.review.md`. It does not enable production issuance, public selectors, occurrences, CALLS, or source completeness. Schema: `schemas/adr0011-references-diagnostic.proposed.schema.json`, version `lsp-trace.adr0011.references-diagnostic.v1`. No producer authentication is claimed. The owner must pin a digest of the finally selected policy and schema before any qualification.

## Selection and capture boundary

`LOCAL_QUALIFICATION_PRIVACY_V1` (`adr0011-local-qualification-privacy-v1.proposed.md`) separates **normal local use** (in-memory, no raw retention, bounded redacted D or `WITHHELD`/`INCOMPLETE`), **synthetic qualification** (self-authored secret-free fixtures preferred for durable replay), and **optional live-provider investigation** (explicit per-run capture to bounded owner-local 0700/0600 storage). The profile is proposed, not selected. Shared, hosted, remote or automatically CI-retained capture requires a separate policy. A local user does not need an organizational custodian, access roster, backup administrator or production privacy-tombstone infrastructure.

The matrix requires independently replayable bounded redacted D for its malformed and matched server-error rows, or `WITHHELD` under the *selected* privacy policy. **Stakeholder preference recorded (not independent policy acceptance):** permit a separate, owner-only, independently capped exact canonical raw-result object for malformed-result replay while keeping D redacted. The raw artifact is not D, a successful method receipt, or a public selector. The bounded private raw profile below proposes a canonical manifest, caps, owner access and retention handling; none is independently accepted, implemented, or pinned for qualification. A redacted summary cannot reconstruct arbitrary malformed JSON; until the maintainer selects a replay mechanism that actually replays the diagnostic claim, rows requiring exact parser replay remain `INCOMPLETE`, not `VERIFIED_DIAGNOSTIC`. A digest alone, fixture input controlled by the claimant, or the current caller-supplied pair cannot substitute for independent owner-bound response evidence. Where selected privacy forbids even D, issue no D and use `WITHHELD`, not `PROVIDER_FAILURE` with a fabricated verified receipt. Privacy withholding before evaluation yields B=T=0. D never contributes P, A, an admitted target, or an occurrence, and a diagnostic prefix is not a successful whole-result parse.

**Unsafe existing path:** `internal/adr0011methodresult/references_diagnostic.go` calls `expectedPair`, which builds a method record containing `ResultBase64`, then publishes that raw record before the diagnostic terminal. This path must remain disabled for production diagnostic capture until replaced; merely redacting the later terminal does not sanitize the earlier object. No raw over-`MaxResultBytes` frame, base64 copy, exception string, log, or quarantine inventory is allowed. An overcap observation can retain only a bounded redacted limit fact, subject to the independent D cap and privacy decision; if unavailable, `N/WITHHELD` as the matrix prescribes.

The owner must acquire an exact keyed completed request/response observation and bind the D record to method, invocation identity, query-target receipt, session/generation, request key, source/revision custody, policy IDs, exact params digest, selected read/write observation digests, and response presence. Store digests/opaque identifiers only where selected privacy permits them; identifiers are not proof of authenticity. **Decision: deny server-error code disclosure by default.** A matched server error may produce D only when the selected privacy policy explicitly authorizes disclosure of its exact signed code, including **zero**; otherwise issue `WITHHELD`, with no D or code-erased `PROVIDER_FAILURE` masquerading as replayable. The proposed D schema requires `codePresence=PRESENT` and exact `code` for `MATCHED_SERVER_ERROR`; `ABSENT` is reserved for non-error diagnostic reasons. A schema-valid code does not prove that a policy authorized it—replay must check the independently selected policy digest and permitted disclosure. A matched error is distinct from a transport-success response with **missing result** (`resultPresence=ABSENT`); neither carries `message`, `data`, error text, arbitrary provider fields, URI strings, source body, raw params, or payload bytes in D. Error text is treated as sensitive even if generated locally: publish only a closed reason code. Unexpected errors fail closed; no verbatim exception or frame excerpt enters D, inventory, log, or response.

## Proposed D allowlist and independent hard limits

Only the closed fields in the accompanying schema may be serialized; unknown keys, duplicate JSON keys (including escaped aliases), trailing content, noncanonical encoding, unsupported versions/reason codes, or cross-object mismatch fail replay. An external JSON Schema validator alone does **not** detect duplicate keys or canonical encoding; a strict byte parser and exact readback comparison are required. D's numeric caps are **proposed**, not inherited from the success arm: maximum 16,384 canonical encoded bytes per D; at most 16 D objects and 262,144 aggregate D bytes per acquisition; at most 65,536 bounded inspection work units and 64 consumed response messages, with positive owner deadline and allocation cap pinned before use. Count bytes *before* publication; never truncate a canonical record to fit. Count inspection work for each visited byte/token/element and reject before exceeding the cap. These D bounds do not raise `MaxAcquisitionQueries=16`, `MaxResultElements=1000`, `MaxParamsBytes=65536`, `MaxResultBytes=1048576`, or `MaxCanonicalRecordBytes=1500000`. The proposed Manager decoded-body aggregate is 4 MiB with at most 4 response messages; ephemeral per-frame raw capture remains at most 2 MiB (the existing correspondence ceiling). An independent exact framed-wire per-request cap of 4 MiB is proposed but unimplemented; allocation and deadline values remain owner-selection blockers. The reader's 16 MiB body default is a source observation, not policy authority. Owned capture currently rejects `MaxBytes > 1 MiB`; the proposed 1 MiB raw-result boundary remains **INCOMPLETE** pending reviewed Manager eligibility and result-guard changes. A wire limit, decoded aggregate limit, result limit and frame staging limit are separate predicates. An over-result frame must be discarded before any publication or diagnostic classification; no overcap frame may be copied into a canonical raw object or D. If a D bound is exceeded or privacy suppresses a mandatory field, withhold D and its terminal claim; do not relabel it a verified success or silently drop fields.

D carries a closed `reason`, outcome and query disposition, observed counts `N/B/T`, `E` as either known integer or `UNKNOWN`, `E_B/E_T`, `P=0`, `A=0`, diagnostic valid-prefix length and optional failing ordinal. Counts reflect *independently recorded* evaluations, not a parser's speculative walk: pre-evaluation resource limit has B=T=0, E unknown; complete malformed first/second element has B=T=1, E=2 and respectively E_B=E_T=1 or 2, prefix 0 or 1; countable 1001-element limit has E=1001, E_B=E_T=0; post-evaluation limit may have E=2, E_B=E_T=1. Query dispositions remain the matrix's `NONE/MALFORMED/LIMITED/FAILED`; D outcome is never a newly invented request outcome. Server error has `PROVIDER_FAILURE/NONE`, B=T=0; successful transport with missing result is its separate reason. Transport short write or unmatched short read has no D. Cancellation/timeout before output has no D. A parser diagnostic and a verified terminal are distinct from a successful method/target V receipt.

## Replay, custody and failure

A replay verifier must start from independently retained bounded owner observations and pinned policy/schema/implementation identifiers, not the D's claimed counters. Verify exact keyed write/read, response presence, target receipt identity, source/revision and method/query identity, caps and privacy, then recompute classification and counters; compare exact canonical D bytes, no-replace selector/digest and post-read bytes. With redacted-only D, replay can establish only facts that the independently retained observations actually support; malformed failing ordinal and prefix need replayable parser input or equivalent independently witnessed bounded parse events. The proposed private raw profile below stores exact raw-result bytes only within its independent bounds, behind a separate owner-only selector and role, never inside D; its limits, custody, retention decision and leak tests still need independent maintainer approval. Do not retroactively call redacted-only evidence exact-byte replay.

Raw retention is default-off. Optional live investigation requires explicit per-run opt-in and an owner-selected user-local 0700 root with 0600 single-link regular no-replace files, exact readback, closed private selectors and independent expected keyed observations. Do not automatically commit or back up captured bytes. No named organizational roster or automatic expiry is needed for local debugging; the user may delete raw evidence manually. Once missing, exact replay is unavailable and the affected row is `INCOMPLETE` unless an independently replayable sanitized synthetic fixture reproduces the claim. A committed-but-unverified diagnostic ref remains non-issuable; bound its private metadata and never leak raw bytes/error text, retry or promote it. If D publication/readback fails, no verified D or diagnostic terminal is issued; this is separate from the success-arm `T=A=0` barrier. A successful D is terminal **diagnostic-only**, with A=0. The accepted lifecycle of any actually issued immutable success-arm receipt remains unchanged.

## Separate owner-only exact raw replay profile (proposal, not issuance)

The proposed closed manifest shape is `schemas/adr0011-references-private-raw.proposed.schema.json`, version `lsp-trace.adr0011.references-private-raw.v1`. It identifies the exact request/response observation and the private canonical object by digest and byte length, not by embedding the raw JSON in D or the manifest. The manifest's `rawResultSelector` is the owner-derived flat basename `adr0011-references-private-raw-v1-<64-lowercase-hex>.bin` under the separate private root; the filename hex must equal the `rawResultDigest` hex and the SHA-256 of the exact readback payload, independently of schema validation. The canonical object contains the **exact result bytes** (including malformed JSON bytes, not a repaired or reserialized parse), at most 1,048,576 bytes per object; at most 16 objects and 16 MiB aggregate per acquisition. Count before publication, reject duplicates/unknown manifest fields and trailing bytes using a strict canonical parser, and compare exact no-replace write/readback bytes. A schema-valid manifest alone cannot establish that its referenced object exists or contains those bytes. `WITHHELD` publishes neither raw object nor a purported replayable malformed D when privacy forbids required evidence. Never place raw bytes in D, public errors, logs, quarantine or receipts; do not expose a private selector through public APIs.

The default-off live-capture root is owner-selected for the opted-in run, user-local 0700, with 0600 single-link regular no-replace objects and a distinct private selector; same-user access suffices for this proposed local-only mode. Replay starts from independently retained keyed write/read and target observations; verifies policy/schema/implementation identity, method, session/generation, invocation, params/source/revision custody, response presence, exact length/digest, and strict JSON framing with duplicate-key and trailing-content rejection; then recomputes parser classification and D and compares exact bytes. Malformed JSON is *input* to classification, not a reason to normalize it. No self-asserted manifest field proves capture authority. A separate issuance transaction, if attempted, proposes at most 256 objects/128 MiB and 256 bounded private redacted uncertainty entries/512 KiB; on exhaustion block new issuance, not local diagnostic-only investigation. No permanent quarantine service is needed for optional debug raw, and raw bytes/error text never enter uncertainty metadata. The optional local raw store instead has its own 16-object/16 MiB per-run and proposed 128 MiB root bounds. Uncertain committed readback cannot be promoted, retried or silently evicted. Manual deletion of optional debug raw makes replay unavailable—do not infer a production privacy tombstone or preserve a stale verified claim. The proposed local root needs no organizational backup, retention administrator or maximum debug-file age; automatic backup/upload is prohibited. Issuance transaction uncertainty remains separately bounded and fail-closed.

These are positive *candidate* ceilings rather than observations of enforced behavior. In particular frame capture is ephemeral and is not the private canonical raw result; the proposed 4 MiB framed-wire cap is independent and unimplemented. The existing 16 MiB reader body default does not authorize it. The 1 MiB Manager eligibility conflict and over-result discard-before-diagnostics guard need reviewed changes outside this draft. Schema-decidable shape tests cannot prove local root permissions, explicit opt-in, capture, strict replay, redacted canary absence across runtime sinks, or deletion-to-`INCOMPLETE`; each remains unverified pending independent evidence. Issuance transaction integrity is tested separately.

## Required falsification before selection

Use independent keyed fixtures with exact owner provenance and pinned policy digests: code present 0 versus absent with identical message, and nonzero; no message/data/error text leakage; malformed first/later element and duplicate result key; missing result versus exact null; 1000/1001 and result-byte/work/wire cap edges; cancellation after a complete prefix; privacy withholding; D byte/object/aggregate cap; unknown/duplicate/trailing D field; substitution of each target/key/source/policy/observation digest; precommit versus committed-readback failure and failed deletion. Insert unique secret canaries independently into error message/data, malformed raw result, provider error string, source, URI, frames, logs and quarantine failure strings; assert none appears in D bytes, failure inventory or any public/diagnostic response, including error paths. With a later approved raw profile, the restricted raw object is the **only** explicitly exempt private location, never D, inventory or logs; test access and removal separately. A replay test must corrupt the original observation while leaving a self-consistent D and its digest unchanged: replay rejects it. Passing offline schema shape checks alone cannot qualify the runtime.

## Unresolved maintainer decisions

1. Independently select and pin the local-only versioned privacy profile, candidate raw manifest/schema and storage bounds, explicit per-run opt-in and owner-bound capture/replay seam. Without exact evidence, malformed rows remain `INCOMPLETE` or `WITHHELD`; synthetic fixtures are preferred permanent replay evidence.
2. Review Manager eligibility/result guard for the 1 MiB boundary; implement and pin independent framed-wire/decoded/message/work/allocation/deadline caps and the D limits above, redaction algorithm/canary coverage, selected privacy-withhold criteria, and allowed opaque identity fields.
3. Pin user-local root validation, per-run/root accounting, no automatic backup/upload, deletion-to-`INCOMPLETE`, and bounded committed-readback uncertainty. Do not require a named roster, maximum local debug-file age, or production privacy tombstones for this mode; retain mandatory issuance transaction integrity separately.
4. Server-error code disclosure is denied by default; the privacy owner must explicitly authorize exact signed-code disclosure in a selected policy before any matched-error D, otherwise use `WITHHELD`. Pin and test that policy decision rather than treating a schema-valid code as authorization.

No decision above is accepted by creating this draft. The schema is a proposed shape, not proof that its producer satisfies the capture, privacy or replay contract.
