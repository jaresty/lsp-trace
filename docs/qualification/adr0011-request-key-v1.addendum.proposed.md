# ADR0011 request-key V1 identity-format addendum — PROPOSED

This is a narrow versioned proposal, not implementation-contract acceptance. The accepted freeze manifests and their hash assertions remain unchanged. The original `adr0011-references-issuance-records.proposed.schema.json` is frozen by those manifests; the successor `adr0011-references-issuance-records.request-key-v1.proposed.schema.json` is independently reviewable and is not an in-place replacement.

A request key is exactly `lsp-trace.request-key.v1:g=<generation>;id=<id>` in ASCII. The prefix, field order, semicolon and equals signs are fixed. Both numbers are unsigned uint64 in shortest base-10 decimal without sign, whitespace or leading zeros (except the single digit zero). Parsing must re-encode and compare exact bytes, reject out-of-range values, and fail closed for string JSON-RPC IDs; supporting those IDs requires a new key version. `generation` equals the runtime `lspwire.RequestKey.Generation` and the enclosing record generation; `id` equals runtime `RequestKey.ID`, `ownerRead.wire_id`, and the independently parsed **numeric** JSON-RPC request and response IDs. These comparisons are semantic replay obligations; JSON Schema alone cannot establish cross-record equality, parsed uint64 bounds or the numeric wire message identity. Replay compares the independently extracted raw JSON-RPC `id` tokens from both retained original bodies to the exact unquoted shortest-decimal encoding of `id`; converting an ID through a string-or-number decoder before this comparison is forbidden. In particular `"31"` must fail even if a caller could convert it to 31. No session ID is encoded. Invocation ID is separate, must be independently compared, and substituting a record across invocations with an equal request key fails identity comparison.

The successor schema references one closed `requestKey` definition in all six request-key occurrences: `context`, `events`, `responseRead`, `methodRecord`, `targetRecord`, and `ownerRead`. Its lexical regex and length bound are a first gate; the shared inert private Go parser is the second gate for uint64 and canonical round-trip. Neither produces a request, grants owner-read custody, changes `PublishReferences`, nor authorizes issuance. This candidate selects the exact successor schema digest recorded in `adr0011-request-key-v1-review.manifest.proposed.md` (SHA-256 of its complete bytes); independent contract acceptance must explicitly promote that digest as the owner-pinned trusted schema identity for these six roles and reconcile the frozen-base predecessor expectations. Until then replay must not silently substitute the successor for the accepted base. Acceptance must bind the successor `$id`, complete-byte digest, six field sites, codec behavior, and the unchanged predecessor commit; a schema claim within a record never selects its own digest. This identity correction carries `authority=0`, `completeness=UNKNOWN`, and `NO_PRODUCER_AUTHENTICATION`; it does not establish an admitted occurrence or alter omitted-selector `CALLS_ONLY` bytes.
