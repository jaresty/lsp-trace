# Private V3.1 host request / authority / limits

Stable explicit frontend: `/skill:private-host-paged-inventory-v3 ABSOLUTE_REQUEST_JSON` in an existing trusted host with an ordinary isolated Agent tool. Backend CLI: `private-host-v3 {preview|setup|run|resume|fail} REQUEST`; role IPC: `{ready|wait|respond}` as described in the skill. None is advertised in public help or MCP. No global settings or install is required.

`hostProductRequestV3` in `cmd/lsp-trace/private_host_product_v3.go` is the normative NEW request family (`private-existing-host-request.v3.1`). `internal/privatehostproductv3.Config` is the pinned product configuration. The production loader requires exact canonical Go JSON, rejects unknown fields, uses a new bounded no-follow private-file reader requiring canonical paths, 0600 regular single-link files, and validates the NEW profile. This is not old `ScopePreview` with automation.

Required request fields: Configuration, CensusArguments (including `--private-enumeration-projection --machine`), Policy, RevisionAssertion, AuxiliaryRoot, ServerSHA256, RuntimeGrantSHA256, ApplicationAllowance, BootstrapAllowance, PayloadBytes, ComputationUnitBytes, OperationTimeoutMS, ExchangeTimeoutMS, FileDenominator. No unlimited or 1 TiB default exists. The controlled tests alone choose their own synthetic grants.

Configuration fields: Profile=`PRIVATE_EXISTING_HOST_PAGED_INVENTORY_V3_1`; Application, ScopeSHA256, ProducerConfigSHA256, ApprovalSHA256, HumanReceiptSHA256, PreviousConfigSHA256, AllowanceRevision, RolePromptSHA256 (the two exact fixed compiled role-prompt digests), Store, Requested, StartBatch, Exchange, Preparation, Seeds, MaxCalls, MaxRequestBytes, MaxResponseBytes, MaxTotalBytes. `ApprovalSHA256=sha256(json.Marshal(Configuration with ApprovalSHA256=""))`; HumanReceiptSHA256 remains a separate field. `ProducerConfigSHA256` hashes the canonical typed tuple of CensusArguments, Policy, RevisionAssertion and ServerSHA256. RuntimeGrantSHA256 hashes the complete canonical request with RuntimeGrantSHA256 empty. These hashes bind supplied bytes, not external authority, historical authenticity, or permission by themselves. Do not author them on behalf of an unapproved caller.

Setup is the explicit new validation-only contract: syntax/path checks first; setup creates private 0700 roots; the actual production root identity/ancestry and closed-store scan then run before provider startup. Configuration/history path is fixed within plan. The closed application store contains only plan, pages, claim, result, host. Source, original page pairs, resource journal, transfer and role IPC live in separate explicitly pinned auxiliary/source roots, not a foreign scope/proof overlay inside the store. All new files are 0600. Failed opens do not borrow a root concurrently. Same-user malicious whole-history rollback is outside this unauthenticated private contract.

`run` creates one create-only original claim after source/config/runtime/readiness admission, executes the existing original Census/Manager lease, uses ProducerPagesPrivateV3, exports a separate checkpoint, and ends the original process. Retained opening uses OpenValidatedCurrentLedgerPrivateV3 with a separately explicit bootstrap budget BEFORE fresh source Freeze/admission. No decoded JSON mints an original owner. Selected computation, assessment, own-AST preparation and paired publication use the distinct retained V3 types.

Semantic family: `PRIVATE_V3_OWN_AST_EVIDENCE_CAPSULE_1`. Bounded per-item cohorts have one own target each, ordered by original batch and prepared target order. InputID, Target, Attempt, Sequence, Predecessor, RequestDigest, source family, own-body hash, prepared/checkpoint references and four original raw-object references are explicit. Raw graph bytes remain byte-exact in paged retention and are explicitly NOT all supplied in the semantic capsule. Direction, occurrence order/duplicates, nulls and numeric lexemes of original artifacts are not rewritten by this semantic route. Any CALLS claim must come from server-reported retained structural evidence, never inference from text. Current capsules deliberately withhold unsupported structural detail rather than invent it.

Reports contain every admitted candidate row, alternatives, rejection conditions, exact evidence references, unassigned IDs, correction-ready revision/predecessor fields, source gaps, requested/completed/gap/pending counts, conservative processing reservation and actual semantic request/response byte/call totals, checkpoint and ledger tip, safe original phase/class and explicit unknown error details. No model text is used as a raw error diagnostic. Pauses/later failures retain earlier rows and paired references. Pair creation uses staged atomic no-replace publication with nonblocking reader/writer locking; no partially visible IPC JSON is admitted.

## Explicit remaining boundaries

- One bounded original source unit per production request; the existing original file/member/target limits remain. Larger application staging/arbitrary-total manifest enumeration is NOT delivered. The application progress snapshot additionally has a disclosed conservative 4 MiB pre-serialization field-graph bound. It retains minimal exact own-body observations, not duplicate declaration byte/base64 arrays; a refused next snapshot retains the last admitted progress and cumulative costs. Oversized units refuse; no unexplored target is silently called covered.
- The same page ledger accounts implemented page/source/parse/math/preparation and explicit host-processing reservations. Acquisition/session enumeration, separately supplied bootstrap retry totals, inference billing/tokens, host orchestration, and complete application-store/report IO are EXPLICITLY EXCLUDED. Do not call this whole-application cost accounting. PolicyReservation is not measured heap/CPU or practical scalability.
- Semantic allowance revisions preserve cumulative calls/bytes and need explicit new caller grants. Existing page-ledger application allowance cannot be extended by this route. A resource-ledger pause can therefore remain paused until a separately reviewed ledger-successor design exists.
- Current schemas carry correction-ready external IDs and revision fields; they do not yet implement multi-revision semantic correction or cross-candidate grouping/withdrawal. Every candidate remains visible and unassigned. No structural merge or singleton product-purpose claim is performed.
- Host role-return cleanup is reported as unobserved by the CLI; the existing host must inspect actual role returns. The controlled harness supplies predetermined payloads and is not evidence of fresh independent semantic judgment, actual Agent execution, live performance, or application feature usefulness.
- Malformed inputs/provider failure, interrupted publication and arbitrary OS failures do not guarantee a successful report. Existing useful immutable references remain; no retry can refund spending or restore spent authority.

Parent review/retest is required before live activation. Historical real application directories, source snapshots, spent claims, old profiles, protected documents, old wire/hash families and public defaults must remain unchanged.
