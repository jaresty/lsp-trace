## Independently provisioned authority and commit protocol

Assumption from maintainer: one trusted installation provisions canonical private root identity, device/inode, installation identity, genesis head and epoch 1 before claimant records. Candidate host anchor path is a host-selected canonical sibling file URI under a separately host-owned 0700 directory, outside *every* claimant-writable descendant and outside the private record namespace; its exact deployment path is selected during trusted provisioning, persisted independently and pinned to a no-follow regular single-link descriptor identity. It is not discovered by scanning claimant records. The anchor's prepare and commit slots are immutable no-replace host-owned files in that sibling directory. Prepare binds previous independently selected head, next consecutive epoch, proposed next private-root head ref, root identity and anchor identity; the root `headTransition` binds the same previous/next head and epoch and points to the prepare host slot; commit binds those same values and points to both the prepare host slot and root transition. The transition's `publication_verification` verifies its own publication, not the later host commit. The commit is not included in either earlier record, avoiding a digest cycle. Every slot's role URI, domain, selector, exact path, byte length and digest are verified under the pinned sibling anchor. Enumerate all bounded host prepare and commit slots at replay, reconcile with all root transitions and selected anchor head, require exact one-to-one consecutive epoch links and verification of no-replace, readback and directory sync at each step. Missing, extra, forked, orphan or divergent slots block rather than silently electing a head. Under the one exclusive root OS advisory file lock, stage arbitrary provider work outside lock; replay anchor, complete bounded successors, pins and fence inside lock; verify no-replace, exact readback and parent directory sync on record and host prepare/commit slots before adopting the next head. A crashed/missing/uncertain slot, divergence between committed record and anchor, rollback, extra successor, fork or ambiguous order blocks; **never automatically elect, heal, or advance** an anchor from claimant hashes. An independent maintainer-reviewed reconciliation must establish unique continuation, else denial remains. This is a proposed model, not a claim that a filesystem provides a multi-file atomic transaction.

All publication, admission, pin/release, new use, traversal/grouping, fence/child/root/terminal, reconciliation and unlink entry points take that same root-wide OS exclusive lock, verify canonical root and lock device/inode against pinned provisioned identities before and after acquisition, and replay anchored head/fence. Replacement of lock pathname or root, timeout, interrupt, unsupported locking, failed descriptor check or missing anchor denies action; no process mutex fallback. No lock spans network waits or arbitrary provider calls. New use acquires a durable lease under lock before releasing it; cached epoch is never authority. An OS lock released by process death does not release a durable fence.

Closure starts from at least one independently selected owned dependency and is independently enumerated from immutable issuance refs and registered pin/lease authorities, transitive, bounded and sorted; record's `completeness_witness` identifies independently replayable owner evidence, not a claimant assertion. A verified revoke may have zero dependents: its root binds `dependent_count=0` and `children=[]` after complete empty-set enumeration; it still requires the selected owned dependency, verified fence and exact root readback, and it proves no unlink or physical erasure. Missing/cyclic/ambiguous/newly admitted evidence blocks. Re-enumerate anchored head, closure, bytes, selectors and pins immediately before every unlink. For retirement prove no live pin/lease at selection and before each unlink; for revoke only an exact verified all-child root cuts over eligibility, irreversibly. A child-only or unverified root is inert and the fence continues denial. Each intent must be no-replace published, synced, read back and verified *before* its one identified syscall. A post-effect observation cannot replace the intent or assert no invocation from missing logs. An intent with missing durable observation is `EFFECT_UNCERTAIN`: **NEVER automatic no-unlink abort**, whether target is present, absent or later reappears. No automatically available independently durable no-invocation proof is proposed. Manual reviewed evidence may retain denial or classify history, never manufacture missing evidence. `ABORT_VERIFIED_NO_UNLINK` is a schema vocabulary for externally reviewed exceptional proof only, and is unavailable from ordinary process report, current presence, or missing observation. A verified root cannot be reversed even by reconciliation. A terminal `REMOVED_VERIFIED` requires every intent, attributable successful invocation, absent post-readback, successful close and parent sync, verified chain and complete replay. An absent target without earlier verified terminal is unexplained; successful unlink with unknown/failed sync is uncertain durability, not erasure.

## Transition and failure table (under lock on every restart)

| Boundary / event | Durable classification and admission | Permitted action |
|---|---|---|
| OS lock contention, timeout, interrupt, unsupported lock, changed inode/root or stale cached epoch | deny pin, use and mutation | acquire same verified root lock within deadline and replay; no mutex fallback |
| Before fence, successor commit/readback/sync ambiguous | committed-unverified head; deny all affected admission and cleanup | manual reviewed unique-head reconciliation, not auto-select old head |
| Anchored head missing/stale/rolled back, gap, unexpected future successor, duplicate/fork, malformed or over-limit replay | ambiguous head; deny admission/pin/use/cleanup | independent reviewed reconciliation only |
| Verified fence, before child publication | affected use/pins denied; originals held | replay closure; continue reviewed operation; only independently proven no-effect abort before any verified unlink intent |
| Some children, no root | children inert; fence denies; no unlink | verify exact set and complete root or retain denial |
| Root committed but sync/readback or child replay uncertain | no cutover; fence denies; no unlink | reconcile exact bytes; no speculative upgrade |
| Verified revoke root (including an independently verified empty dependent set), before unlink | all enumerated dependents inactive permanently; empty set grants no removal claim | revalidate epoch/closure; start individually evidenced unlink only for selected owned targets |
| Retirement with pin/lease or new dependent | no unlink; fence denies affected use | stop and review new closure/decision |
| Before verified pre-effect intent | no syscall authorized for that ordinal | revalidate and publish fresh exact intent |
| Intent commit/sync/readback uncertain | no unlink permitted; deny | reconcile publication, not presumed success |
| Verified intent, killed before or after syscall without durable observation | `EFFECT_UNCERTAIN`, even if present or absent; deny | no auto abort/removal/retry; manual reviewed evidence only |
| Observation reports failed/unknown syscall or close/readback | failed/uncertain, deny | no successful terminal; new reviewed attempt requires fresh decision |
| Successful unlink report but failed/unknown parent sync | uncertain durability, deny | no verified removal; manual review |
| Missing target without prior verified terminal, including partial cleanup | `REPLAY_UNAVAILABLE_UNEXPLAINED`; deny | investigate; do not synthesize success |
| Full verified observation chains and terminal | removal classification persists; root cutover if revoke remains | replay terminal; later reappearance is anomaly, never resurrection |
| Reconciliation with absent no-invocation proof or divergent head | denial persists | no automatic advancement or `ABORT_VERIFIED_NO_UNLINK` |
