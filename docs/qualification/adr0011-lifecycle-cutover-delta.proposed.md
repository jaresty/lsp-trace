# ADR 0011 lifecycle atomic-cutover delta — independent review draft

**PROPOSED ONLY.** This refines accepted-for-implementation lifecycle proposal SHA-256 `fe8206e2c6af38e7869372653f055007699b0c30018a945351c5031599e8df7d`. It does not authorize cleanup or change issued state. The existing `internal/publication` selector `sync.Mutex` is process-local; it cannot exclude pins by a second process or survive restart. `RemovePrivateFile` reports unlink and directory sync separately and issues no tombstone.

## Root-wide exclusion and persistent fence

All publication, admission, pin, replay-as-active and cleanup operations for the selected private root must participate in **one root-wide OS advisory exclusive lock** acquired through a separately pinned, no-follow, owner-only lock-file descriptor under the root (not the existing per-selector in-process mutex). Require root device/inode identity, a regular 0600 single-link lock file, a documented platform implementation with process-to-process exclusion and automatic crash release, and bounded lock acquisition. A process lacking this capability must fail closed, not fall back to `sync.Mutex`. Under the lock, publish and verify a no-replace versioned fence-intent record whose monotone epoch binds root identity, exact decision ID, selected dependency set and previous verified epoch. The lock serializes active-use/pin checks and the epoch selection; the **verified immutable fence** retains the block after lock release or crash. All new-use readers and pin writers must reacquire the root lock and replay the latest verified epoch/fence before use or mutation. A stale generation or unverified latest epoch denies both. No lock held through arbitrary provider calls.

## All-dependent cutover and record identity

A new complete Draft 2020-12 lifecycle schema file (distinct `$id`, immutable whole-file hash selected before writing) defines closed `fenceIntent`, `tombstoneChild`, `tombstoneRoot`, `unlinkAttempt`, `cleanupTerminal`, and `reconciliation` records. Each canonical record has versioned role, decision/root/epoch identities, bounded selector/ref arrays, complete byte-length/digest and domain-separated selector; duplicates, omissions and cycles fail. A verified `tombstoneRoot` names the exact complete sorted dependent set and the exact `tombstoneChild` digest for each member, plus previous epoch and intent ref. Child records are inert before a fully verified root; root readback and full child-set replay are the **single eligibility cutover**. Under lock, validate complete transitive dependents and current epoch, publish all children no-replace, verify them, publish root no-replace and verify close, parent sync, readback and full set replay. Only then may unlock or unlink. A crash before root verification retains the verified fence and blocks new use; a crash after root verification leaves all dependents inactive even when bytes remain. Reconciliation may terminate uncertainty only after independently checking every expected byte and epoch under the same lock.

## Removal outcomes and recovery

Before **each** unlink reacquire/hold the root lock, verify epoch/fence, re-enumerate pins and replay tombstone root or retirement eligibility. Log a distinct no-replace `unlinkAttempt` with expected selector/digest, pre-read status, syscall outcome, post-read status, directory sync/close status; do not record successful removal before sync. If already missing without an earlier verified terminal, record `REPLAY_UNAVAILABLE_UNEXPLAINED` and stop. If unlink succeeded but sync failed, record `REMOVED_UNCERTAIN_DURABILITY`, keep fence and deny active replay; neither success nor secure erasure may be inferred. A verified `cleanupTerminal` declares completed removal only if all attempts and directory syncs replay and all targeted selectors are absent; partial failure publishes a typed uncertain terminal that **never** upgrades prior issuance or releases eligibility. Restart scans the latest verified epoch and reconstructs fence, root tombstone, attempts and terminal without trusting in-memory flags or filesystem absence. Byte reappearance cannot resurrect a tombstoned ledger. Historical final bytes/counts remain immutable and available claims retain their original temporal meaning; new-use eligibility is separate.

## Review and falsification

Before implementation, independently review the complete lifecycle schema bytes, domain strings, role/multiplicity and selector rules, root lock platform mechanics and epoch/recovery state table. Tests must run two independent processes contending on the same root, kill one after verified fence and at every child/root/unlink/sync boundary, then restart and check that a second process cannot pin or use an affected dependency. Perturb partial child publication, stale epoch, forged root, missing object, unlink success/sync failure, and reappearing bytes; only verified complete root cuts over and cleanup never mutates issuance history. Return `ACCEPT_LIFECYCLE_CUTOVER_DELTA_FOR_IMPLEMENTATION_ONLY` or `REVISE` over exact schema and prose bytes. The existing lifecycle contract acceptance alone does not choose these wire identities or permit implementation guesswork.
