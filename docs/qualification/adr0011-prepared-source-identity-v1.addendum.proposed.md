# ADR0011 prepared-source identity — narrow implementation proposal

Status: **PROPOSED; not an occurrence qualification or issuance decision.** This proposal closes only the local, single-user prepared-source/source-identity prerequisite. It does not amend the frozen predecessor schema bytes or upgrade the accepted successor role mapping. No source record in the partially implemented test owner is accepted by this text alone.

## Owner-selected inputs and canonical URI

Before preparing the document, select the exact READY session ID/generation and its exact registered worktree root. Require that root to be an absolute POSIX path whose spelling is clean (`filepath.Clean(root)==root`), and that `filepath.EvalSymlinks(root)==root`; a symlinked worktree/root alias is ineligible. Require the registered root URI, when available, to equal the canonical local URI defined below; never substitute a different canonical root after observing the query. The acquired document's URI must equal both the query URI and Manager's prepared-supply URI. Decode it as a local `file:` URI with no authority, userinfo, opaque part, query, fragment, or malformed percent escapes. Its decoded path must be absolute, clean, valid UTF-8, and free of NUL. Reject repeated separators, dot segments, and alternate percent spellings by requiring the original URI to equal the URI constructed below from its decoded path; do not silently normalize an alias.

The canonical URI is `file://` followed by the slash-prefixed absolute POSIX path with each UTF-8 byte outside RFC 3986 unreserved `[A-Za-z0-9._~-]` and `/` percent-encoded using **uppercase** hex. This is the same byte-encoding rule used by the accepted host-Git root observation. `filepath.Rel(selectedRoot,documentPath)` must succeed and be neither `..` nor start with `../` nor absolute; the root itself is not an eligible source document. A pre- or post-read `EvalSymlinks` equality check is **insufficient** to prove that Manager did not traverse a symlink during its read: path components can change between check and open. For filesystem-backed supply, eligibility instead requires Manager to acquire the exact bytes with a descriptor-bound, no-follow walk: open each component of the selected absolute root from `/` and each relative document directory component with no-follow directory semantics, then open the leaf with no-follow semantics, require a regular file by descriptor, and read the bounded bytes from **that same leaf descriptor** into the prepared supply. A symlink in any root or document component, unsupported no-follow platform, failed descriptor verification, path escape, or ambiguous/racing acquisition is ineligible; do not fall back to Manager's existing `os.OpenRoot` read for this profile. An independent lexical/symlink check may strengthen rejection but cannot replace descriptor-bound supply. A seeded/retained Manager source must either carry equivalent owner-verifiable no-follow acquisition custody from the same bytes or be ineligible; an arbitrary retained byte slice does not prove filesystem no-follow custody. If a directory is renamed after a descriptor is opened, this rule attests only no-follow acquisition under the opened directory handles, **not** that the historical registered path remained immutable or that the server analyzed these bytes. On platforms where Manager's canonical URI check disagrees with this stricter spelling, acquisition is **ineligible**, never reinterpreted.

## Prepared bytes, version and zero length

Bind the *exact* `Manager.PrepareDocument` supplied UTF-8 content bytes without line-ending conversion, Unicode normalization, JSON reserialization, or disk reread. The separately retained private `adr0011-references-prepared-text-v1-<sha256hex>.bin` contains those exact bytes; digest is `sha256:` plus lowercase SHA-256 of the entire payload and length is its byte count. Require `1 <= byte_length <= sessionruntime.MaxDocumentSupplyBytes` for a **new references issuance**. A zero-byte document is a valid schema-representable prepared-source shape (`text_byte_length` permits zero), but this local references producer does not issue or publish a prepared-source/source-identity pair for it: there can be no eligible nonempty uniquely selected document symbol from an empty source. Treat it as an ineligible/incomplete target, `T=A=0`, not a zero-byte substitute or success. Empty bytes are never interpreted as a missing payload on replay; historical records, if any, remain subject to their original contract and cannot be promoted by this rule.

The prepared version is the nonnegative Manager result `Version`, never a caller-provided integer. Select position encoding from the same exact session metadata independently; this local Go/gopls profile permits **only `utf-16`**. The query's session ID and generation are independently bound in the owner request and method/owner-read closure, not invented fields on these two schema shapes; replay must compare the owner-expected session/generation, URI, version, encoding and original bytes, rejecting a substituted session/generation even if a standalone source record is internally self-consistent. A changed prepared version, content, encoding, URI, root, or generation cannot reuse a verified source identity to issue a new occurrence.

## Record identity, replay, and custody

Use exactly the accepted successor whole-schema `$id` with `#/$defs/preparedSource` and `#/$defs/sourceIdentity`, pinned to complete-file SHA-256 `86bb214e419f7c69b80ff5dfbdf0f0760c495c9bf0f88d06bdc227b77920fc8e`. Do not accept a schema digest asserted by a record. `REFERENCES_PREPARED_SOURCE_V1` records the selected canonical URI, Manager version, `utf-16`, exact text digest and exact byte length. `REFERENCES_SOURCE_IDENTITY_V1` repeats URI/version/digest/encoding and contains the exact independently verified prepared-source ref. The separately retained text object is a mandatory dependency derived from that digest even though the prepared-source JSON has no explicit payload-ref field. Use the accepted restricted JCS canonical bytes, role-separated `SHA256(role || 0x00 || canonical_record_bytes)` and the accepted flat private selectors. Preserve equal bytes with distinct versions as distinct source identities; do not conflate source identity with target, occurrence, or eventual grouping node.

Publish each dependency no-replace under the selected private 0700 root with 0600 objects, verify commit/close/directory-sync status and exact independent readback, then replay all canonical bytes, digests, selector derivations, full prepared-text payload, equality of repeated fields and owner-selected expectations. `ABSENT` and `COMMITTED_UNVERIFIED` do not authorize a successor. Fail closed on aliases, symlinks, wrong workspace, changed bytes/version/session/generation, schema-digest substitution, custody substitution, missing payload/ref, no-replace collision or failed readback. `HOST_OBSERVED_GIT` and a prepared document do not authenticate the provider or prove the server analyzed that version; revision identity remains separately pinned and caller custody cannot be upgraded. No public response carries prepared text, private records, or inferred source completeness. Issued `T=A=0` until a separately verified final transaction.

## Implementation-only exit

An independent review must accept this exact rule for implementation *before* wiring the draft producer. Demonstrate one private no-replace source pair, exact readback and independent replay with assertion-specific negative controls for URI spelling/alias and symlink, containment, zero length, content/digest, version/session/generation, schema digest and custody substitution. Preserve the historical final-issuance RED at `PublishReferences` and all omitted-selector `CALLS_ONLY` bytes. Stop after this prerequisite: no final references transaction, index, entrypoint-distance metric, definitions, grouping, Leiden or CLI/MCP selector is authorized here.
