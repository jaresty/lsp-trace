# ADR 0011 method-receipt seam audit — unqualified

**Status: UNFROZEN SOURCE AUDIT.** This is not an acquisition receipt, schema, authenticated provider statement, query-target identity, occurrence admission, request-outcome policy, or grouping authorization. ADR 0011's subsequent CALLS-parity decision drops same-process forgery resistance **and mandatory exact-frame retention** as prerequisites, not the need for a production immutable **canonical query/result** transaction record and offline byte/identity consistency verifier; the frame observations below are optional diagnostics and remain unadmitted. ADR 0011's `authority=0`, `accepted=false`, `completeness=UNKNOWN` ceiling remains in force. The [transaction draft](adr0011-method-transaction-receipt-draft.md) lists candidate receipt fields; this audit asks which fields this private transport can actually observe.

## Evidence and limits

A READY exact-workspace `project` generation 1 returned bounded `lsp_trace_v2_structural_context` request `sc_feee09e5d940f1570b731dae0a9d1d8a`: `Transport.Execute` has server-reported outgoing arcs to `validate`, `Metadata`, and `RoundTrip`; two external calls were omitted. Its `authority=0` and `source_graph_complete=UNKNOWN` do not establish a complete call graph, runtime execution, or producer authentication. ## Consequence and next falsification

**Do not hash or publish the current `Result` as a method receipt.** Two requests can differ in exact URI, position, generation, or policy while exposing the same method, transport outcome, response counters, and raw method result. Conversely, a caller-provided snapshot of those fields is not evidence that the managed process sent the named request.

A private in-memory `TransactionObservation` now carries the caller-declared query coordinates, digest and length of one validated parameter-byte copy, selected limits, runtime-reported capability/provider metadata, `RoundTripCalled`, and runtime-reported key and counters. A separate RED/GREEN check showed that valid raw params one byte beyond 65,536 previously reached `RoundTrip` and oversized malformed params reached JSON validation; both now fail with fixed preflight text before copy, observation, metadata, or wire. Exact-limit valid definition and references requests retain copied bytes and local digest. This is not a receipt-wide size, privacy, or wire-custody qualification. External tests separately substitute URI, position, generation, and whitespace under identical method-result bytes; verify absent capability and failed metadata do not invoke `RoundTrip`; and keep invalid preflight observation-free. A controlled missing-`RoundTripCalled` perturbation fails the named assertion. This does not retain the raw request, prove a completed wire write, or make the observation an immutable receipt. A separate RED/GREEN result-byte guard distinguishes absent versus present-empty success, `null` versus `[]`, and same-length distinct bytes, while checking exact local digest and defensive `Raw()` copying. A failure-boundary control with an oversized raw result and `-32601` confirms that neither raw digest nor server-error code escapes a transport-bound failure. These are fake-runtime observations and do not establish an authenticated provider result or `COMPLETE_EMPTY`.

A private manager-local test reconstructs the complete framed JSON-RPC request and checks its observed frame length and digest, session/generation/key/method, copy isolation, and unchanged JSON serialization. A server-error response retains the completed-write observation; a later response timeout does too. Stale generation, oversized framing, and a deliberately short child-pipe write expose no completed-write observation even when request-attempt bytes were counted. Named controlled perturbations of the frame digest and premature publication at write attempt each failed their dedicated assertion before restoration. These are in-process pipe controls, **not** an independently authenticated provider or managed external-process receipt.

The managed reader now offers `ReadWithFrame()` with a local digest and byte count of the exact consumed header and body; the manager exposes `CompletedResponseRead()` only after the keyed response is accepted and its selected byte limit passes. An in-process reader guard accepts two different valid frames that decode to the same JSON-RPC message yet have different frame digests. Manager tests withhold the observation for unmatched, malformed, stale, timed-out, or over-limit responses. A supervised test-owned process checks the accepted definition error response against a reconstructed frame; it does not attest to an arbitrary provider. **When optional exact-frame diagnostics are selected, replay cannot independently verify exact response-frame custody from decoded JSON plus this digest alone:** reserialization may choose different valid framing. A **frame-diagnostic candidate** must retain exact bounded frame bytes under an explicitly private owner-controlled policy, or supply a separately verifiable binding of the observed frame to its decoded response; a canonical query/result transaction need not make a raw-frame custody claim. The existing `publication.Root` can confine immutable bytes to a pinned owner-only directory and `PublishVerifiedGeneration` can check published byte consistency, but neither authenticates which runtime produced them. An arbitrary fake `Runtime` can replay a genuine `RoundTripResult`, including local observations. Acquisition-owner capture provenance, selected privacy/withholding behavior, and offline replay of the exact bound request/response therefore remain open. Do not issue a method receipt or infer `COMPLETE_EMPTY` from these manager-local observations.

A supervised test-owned method peer now explicitly checks that definition `null` and references `[]` reach successful bounded transport and parse, with completed manager-local write and keyed read, **while both optional raw-frame captures remain absent by default**. This verifies that frame retention is not a prerequisite for those private wire/parse facts; it is not a canonical immutable query/result receipt or occurrence admission. The manager also has separately opt-in, bounded, private in-memory exact-frame capture for **both** definition and references successful keyed responses; a method-neutral accessor returns a defensive copy, and the old definition-only accessor retains its meaning. A further default-off D/R option now retains the exact framed **request** write bytes only after the owned write completes and a keyed success response is accepted, under an independent provisional 2 MiB cap. Tests compare exact wire-framed bytes to the completed-write digest/length and withhold them on default-off, other-method, over-cap, over-ceiling, short-write, stale, malformed, timeout, unmatched-only, resource-bound, and server-error paths. Premature assignment immediately after write made the server-error guard RED and was restored. This request-frame copy is still in-memory and caller-replayable; it is not immutable publication or an owner receipt. Test-owned responses distinguish references `null`, `[]`, and two repeated `Location` members without equating any shape to a terminal-member verdict. An earlier unmatched frame cannot fill an over-cap accepted response slot (controlled leak RED/GREEN). `sessionruntime.VerifyMethodFrameCorrespondence` is a private **local byte-consistency** check: it requires explicit positive request bounds, a selected D/R cap at most its provisional 2 MiB verification ceiling, completed manager-local write/read observations, reconstructed framed request length/digest, exactly one captured valid success frame with no trailing bytes, matching read length/digest and numeric key, and exact decoded result bytes. One-field request, key, frame, read, write, result, and bound substitutions fail with fixed non-sensitive text; a removed read-digest check caused a named RED and was restored. A self-consistent replacement of captured definition frame, decoded result, and read digest **passes** deliberately: these are caller-supplied replayable local observations, not an authenticated owner or provider receipt. Raw capture caps bound retention, not total wire, CPU, or reader allocation; the verifier ceiling bounds only its own replay work. Neither method result is immutable, owner-verified, a selected terminal-member ledger, a reference query-target identity, or an admitted occurrence.

A separate package-private manager test hook now probes owner-path retention without a production publication capability: only a bounded D/R accepted success with both exact frames and passing local correspondence emits copied candidate bytes. Test-only publication under a private `publication.Root` verified readback and no-replace bytes; closed-root failure remained separate from method success. An early-hook perturbation failed the server-error withholding guard and was restored. A fake method-transport `Runtime` can still return transport success but cannot configure the unexported manager hook from an external Go package. This is a test-owned owner-path observation and byte-integrity probe, **not** producer authentication, independently owner-verified immutable method receipt, selected privacy policy, terminal ledger, or occurrence admission.

The private method transport now records `LocalWriteCorrespondence` as diagnostic `NOT_OBSERVED`, `LOCAL_MATCH`, or `CONFLICT`. Only a supplied manager-local completed-write observation can match the exact declared session/generation/method, returned request key, request-body byte/message accounting, and reconstructed header-plus-body length/SHA-256. A fake runtime without that observation remains `NOT_OBSERVED` even after transport success. In-process controls use an actual manager-produced result wrapped by a fake `Runtime`: both methods match; changed URI, session, generation, method, key, or request counters conflict without changing the transport outcome or retained raw result. A controlled missing frame-digest comparison made the URI substitution falsely match and failed the named replay assertion before restoration. **Whitespace-only raw-parameter changes can still yield `LOCAL_MATCH`** because Go's JSON marshaling compacts `json.RawMessage` into the same framed body; the separately retained `ParamsSHA256` differs, but the completed-frame observation does not attest the original parameter formatting. `LOCAL_MATCH` is self-consistency, not an authenticated owner receipt or replay verifier; fake runtimes can replay a genuine result, and no status admits an occurrence.

Next falsification: verify any proposed acquisition-owner custody against the exact managed session/generation and manager-local completed-write evidence, then test replay substitution beyond the compared frame/key, runtime-interface substitution, and privacy withholding on a separately selected canonical serialization. The manager-local frame digest is not a provider-authenticated wire receipt. Independently select and verify numeric request/parameter bounds, the managed-path byte/identity consistency verifier, revision/document evidence, retention/privacy policy, permitted omissions, and replay behavior **before** naming a production receipt or admitting an occurrence. A signature or independently trusted owner is not required for parity and must not be implied by the verifier. Do not map JSON-RPC `-32601` to ADR `UNSUPPORTED` from this audit.
