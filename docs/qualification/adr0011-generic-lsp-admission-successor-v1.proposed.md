# ADR0011 generic LSP exact admission successor V1 — proposed implementation contract

**Decision requested:** `ACCEPT_GENERIC_LSP_ADMISSION_SUCCESSOR_CONTRACT_FOR_IMPLEMENTATION_ONLY` / `REVISE` (cite clause and counterexample) / `DECLINE`. **Current checkpoint: REVISE / INCOMPLETE; authority 0.** Acceptance would authorize only a separately reviewed implementation and assertion-specific tests, never live issuance, occurrence-specific `QUALIFIED`, public wiring, lifecycle activation, indexing/grouping, or semantic feature acceptance. This is a provider-neutral *eligibility-to-attempt* contract, not a provider qualification or process authentication claim. It adds `GENERIC_LSP_REFERENCES_EXACT_V1` and `GENERIC_LSP_DEFINITION_EXACT_V1`; it does not edit, supersede in place, or reinterpret accepted `REFERENCES_SYMBOL_V1`, its Go/gopls-only `GO_GOPLS_EXACT_V1` gate, 162-row matrix, 21 final-reference dependencies, historical receipts, source pins 90/92, held-out CUE requirements, or omitted-selector `CALLS_ONLY`. Definition V1/V2 and generic correction packets remain proposals. A generic selector must be explicit; absence cannot silently opt into generic admission.

## Basis, boundary and identity selection

The accepted references implementation decision (`adr0011-references-contract-implementation-acceptance.md`) authorizes implementation, **not** occurrence qualification. Its admission gate (`adr0011-production-admission-gate.review.md`) selects Go/gopls only. The generic decision correction packet chooses a contrary future product direction and a separate versioned path; this proposal does not grant it existing gate authority. The definition terminal V2 proposal selects the *proposed* nonempty exclusion semantics below, but its schema role URI and policy are not registered accepted originals. Owner-reported fields, server advertisements and self-hashes never establish independently selected custody. The intended exact transaction identity binds method, query declaration and raw params, source version/bytes, READY session/generation, workspace custody, adapter version, effective capability, negotiated encoding, owner-observed PROCESS provenance (without executable or launch-chain admission), actual request key and completed write/read, raw result and method-specific immutable policy/schema roles. Each distinct generation, bytes, launch configuration or reported metadata denotes distinct evidence, never an allowlist denial solely for unfamiliar name/version.

Before implementation acceptance can become a **closed exact acceptance**, an independent maintainer must select the exact public/private selector spelling and version routing, record collision domains and canonical fixtures, every schema role URI/version/exact byte digest, every method/admission/privacy/retention/limit policy original and digest, and each original's owner/publisher/reader role and predecessor edge. **These identities remain unresolved here; this prose is not their freeze.** No invented URI, digest, default policy or self-referential receipt fills the gap. Implementation may be accepted as design work only with these explicit gates still closed; an implementation claiming issuable generic records before their independent selection must be rejected.

## Eligibility and pre-invocation binding

The managed owner normalizes *standard* initialize server capabilities independently for `textDocument/references` (`referencesProvider`) and `textDocument/definition` (`definitionProvider`). The following table applies to each method at the completed initialize observation, before any registration; an unsupported static value does not disable an independently valid later dynamic registration. Client-advertised dynamic-registration support alone is never server support.

| Original initialize member for that method | Static contribution to an exact URI request |
| --- | --- |
| Absent | None (`UNSUPPORTED` absent dynamic support); preserve member absence, not JSON `null`. |
| JSON `false` | None (`UNSUPPORTED` absent dynamic support). |
| JSON `true` | Static support for the method; no invented options or document selector. |
| JSON object | Only a strictly validated standard method-specific options object contributes static support and exactly its applicable options; reject invalid field types, unknown/nonstandard admission extensions, or an inapplicable URI constraint rather than coercing the object to `true`. Preserve explicit presence of each option. |
| JSON `null`, other type, or malformed object | No static support; emit a typed malformed-capability failure where the selected policy requires it, otherwise `UNSUPPORTED`; never coerce to support. |

For any URI constraint actually present in a valid options object, evaluate it against the exact predeclared query URI with the same conservative selector rules below; static `true` has no implicit URI constraint. A valid but URI-inapplicable options object supplies no support for that URI. Unknown applicability is not positive support. The method-specific allowed fields and exact malformed-versus-unsupported disposition require independently selected policy originals; this table does **not** select those originals or authorize permissive unknown fields.

Maintain two separate contributions at each owner-observed event boundary: immutable static support from initialize, and active dynamic registrations keyed by `(session, generation, registration ID)`. A valid `client/registerCapability` item records its original ID, exact standard method, original `registerOptions`, selector presence/value, normalized selector, and monotonically ordered owner-observed event; only a method-matching, URI-applicable, active item contributes dynamic support. Registration IDs are unique within that session/generation across methods: an exact repeat with identical original bytes is an idempotent replay only if the owner proves it is the same event, not a second event; a duplicate ID with conflicting method, selector, options, or original bytes fails closed with typed registration conflict and cannot replace the earlier item. A distinct later registration reusing an ID, even with identical bytes, is not silently merged. Unregistration removes **only** the active dynamic item whose registration ID **and registered method** both match the unregistration item in that same session/generation; an ID paired with another method is a typed invalid-unregistration event and removes nothing. Missing, stale-generation or mismatched ID/method cannot revoke static support or another dynamic item and require a recorded typed invalid-unregistration disposition. For each invocation boundary `i`, `effective(method, URI, i) = staticApplicable(method, URI) OR exists activeApplicableDynamic(method, URI, i)`. Thus initialize `referencesProvider: true`, then a valid references registration, then unregistration of that ID leaves references eligible through static support; if static was absent, only the dynamic contribution disappears. Do not collapse static and dynamic contributions into one boolean whose unregistration clears both.

The owner freezes an invocation eligibility snapshot **before its completed WRITE** from only initialize and registration events already observed in that session/generation. A registration, unregistration, notification or result observed after that snapshot changes only subsequent snapshots; it cannot rescue or invalidate that earlier eligibility, even if its message claims an earlier time. Preserve the complete original initialize bytes and each full registration/unregistration notification byte sequence (including original array order, IDs, methods, options and selectors), ordered observation index, generation, snapshot index, normalized result and explicit absence; decoded/reordered or reserialized equivalents are not replacements for these originals. If ordered originals are missing or inconsistent, no exact eligibility receipt issues.

For dynamic registration `documentSelector`, an explicit JSON `null` means no document-selector restriction **only if** the exact method's independently selected standard/policy contract affirmatively permits that meaning; an omitted selector is distinct and is not inferred to mean all documents. Until the contract selects its interpretation, omitted or explicit-null applicability is `UNKNOWN`, not URI-applicable and not an admission basis. A non-null selector must be a valid nonempty array of valid filter objects whose language/scheme/pattern conditions can be evaluated from independently pinned exact URI/document facts; a matching filter grants applicability, no matching filter denies it, and any needed unavailable fact yields `UNKNOWN`, never wildcard success. Malformed selector shapes and unsupported filter semantics fail typed validation rather than broaden support. Provider-specific refinements may narrow a separately selected mode, but no per-provider profile or executable/name/version allowlist is a prerequisite for generic eligibility.

Record PROCESS provenance separately from generic occurrence admission as `LOCAL_EXECUTABLE_MEASURED`, `LOCAL_CONFIGURATION_ONLY`, or `EXTERNAL_PROCESS_UNMEASURED`, according to what the managed owner actually observed. A local measurement may record selected executable path, length and digest, but neither a complete executable chain nor retained executable bytes are prerequisites for an admitted occurrence. A wrapper, interpreter, symlink, remote or unmanaged process, changed on-disk file, or unknown dependencies must not be represented as verified process correspondence; these conditions do not by themselves bar an otherwise eligible generic admission attempt. Capture `serverInfo.name` and `.version` as optional server assertions including explicit absence. PROCESS provenance is contextual host observation, not proof of which executable produced a response, response authorship, process correspondence, provenance authenticity or honesty. Optional private executable snapshots, when selected, have a separate budget and policy; they are not part of mandatory transaction retention. See `adr0011-generic-process-provenance-correction.proposed.md` for the narrow superseding correction.

The generic query target is an independently held **exact source URI/version/bytes/digest and point**, declared and bound before invocation together with the negotiated `utf-8`, `utf-16` or `utf-32` encoding, valid nonnegative line/character at a code-point boundary (including no UTF-16 surrogate-interior point or UTF-8 continuation-byte point), original JSON request params, READY session/generation, and distinct query and occurrence identities. The original params must select that same URI and point; a source-version or byte ambiguity cannot be resolved from the provider's answer. A changed URI, version, bytes/digest, point, encoding or generation is a different query-target identity, even when later reference locations coincide. Exact URI+position needs no fabricated language identifier range. A caller starting from a symbol/range needs a separately admitted, unambiguous, replayable derivation receipt; source-only regex may locate a point but does not manufacture a referenced symbol. For generic references, `REFERENCES_SYMBOL` names the server-reported references relationship queried **at this point**, not an independently verified referenced-symbol identity, and confers `authority=0`; no document-symbol response or independently verified symbol identity is required to admit an otherwise eligible generic query from an unknown provider. An optional exact, uniquely selected document-symbol derivation may strengthen a separately scoped generic claim, but cannot gate the point-bound path. The accepted V1 document-symbol unique strict most-specific nested selection remains compulsory and unchanged for V1, not replaced by this additive path. If independently held source custody/version or the encoded point cannot uniquely select the query target, fail `TARGET_IDENTITY_UNRESOLVED` before invocation with B=T=A=0, never `EMPTY`; unsupported method support and completed `null` retain their distinct dispositions. Bind before/after workspace/revision custody without upgrading caller-asserted Git revision to provider-verified.

Source custody is provider-neutral, not source-free. Independently select and replay exact URI/version/digest/**bytes** for the query and each returned target: an owner-held unsaved editor buffer at a pinned document version, a managed virtual document with stable URI/version and exact owner-supplied bytes, or clean registered Git worktree with bounded owner-observed root/HEAD/cleanliness before and after plus pinned file bytes. Each alternative must prove the same transaction's source identity and URI/version correspondence; no ambient checkout, inferred current buffer, stale generation or cross-document fallback. For unknown URI scheme or absent/withheld target bytes, fail selected occurrence eligibility. A verified complete definition-only excluded terminal is possible only under the separate all-or-none rule below, never by pretending source existed.

## Wire, grammar and precedence

For every **complete inbound frame actually consumed during the transaction**—matched result, error response, notification or unrelated response—count original consumed LSP header **plus** body bytes inclusively, and compare to `2,097,152`: exactly at cap passes this comparison; `2,097,153` fails. This is not Content-Length alone, body length, buffered prefetch, decoded value or reserialization. Record earliest causally observed terminal failure: a preceding oversized unrelated frame is not forgiven by a later small matched success. Incomplete header/body or EOF does not assert a complete-frame length; a separate bounded partial-reader byte, message, deadline and work disposition records actual consumed prefix, pending key/read phase and cause without inferring E=0. Separately apply positive decoded JSON-RPC body ceiling, exact raw result ceiling, message count, cumulative transaction bytes, elapsed deadline, evaluation work and allocation bounds in declared causal order. Proposed definition decoded-body ceiling `1,048,576` and result ceiling `524,288`; references V1's existing exact result ceiling `1,048,576` remains unchanged. Generic references must independently select its own result/decoded/transaction limits; a shared wire bound does not silently transplant the V1 result cap. The owner-observed `FrameBytes` of one completed response and private correspondence checks do not establish an all-inbound-frame implementation.

Strictly consume one original UTF-8 JSON result token with permitted trailing whitespace only; reject invalid escapes/surrogates, duplicate **decoded** object keys at every depth (`"uri"` and `"\u0075ri"` collide), trailing values, extra/missing fields, invalid coordinate number tokens or malformed ranges before schema admission. Preserve exact request/result token bytes, offsets, lengths/digests, result-presence distinction, top-level shape and original zero-based ordinal. Definition grammar is exactly `null | Location | Location[] | LocationLink[]`; arrays homogeneous, `[]` distinct from `null`; scalar `LocationLink`, mixed arrays and any malformed later member make whole result `MALFORMED`, P=A=0, even if a prefix is diagnostic. A link retains separate `targetRange`, contained `targetSelectionRange` and optional `originSelectionRange` (present versus absent); origin, if present, must match an independently derived query occurrence range under its encoding/version, not an inferred universal identifier. References grammar is exactly `null | Location[]`; scalar Location, LocationLink, mixed/nullable members and coercion are invalid. Equal returned locations retain separate original ordinals and occurrence identities. Never reinterpret definition targets as references `returned_range` or either as `CALLS`.

## Evaluation, publication and verified terminal

Predeclare N queries; B begins only when owner-observed evaluation starts; T is a **verified** terminal query member; E is bounded complete top-level element count or `UNKNOWN`; E_B/E_T count actually observed element begin/terminal events; P is successfully whole-parsed elements, zero on malformed whole result; A is new immutable admitted occurrences. Enforce `0≤T≤B≤N`, `0≤E_T≤E_B≤E` when known and `0≤A≤P≤E`; unknown never means zero. Preserve diagnostic prefix separate from P/A. One query per request, bounded counts and original-token spans; no fabricated begin or terminal from a decoder slice. A complete, independently verified `null` or `[]` may produce E=P=A=0, `COMPLETE_EMPTY`, `EMPTY`, T=1, with distinct raw byte identities. A two-element fully parsed definition with one independently proven unavailable exact target source has E=E_B=E_T=P=2, A=0, disposition `EXCLUDED`, proposed definition-only `EXCLUDED_VERIFIED`, T=1 **only** after both distinct ordinal events, one terminal per ordinal, `WHOLE_PARSE_SUCCESS`, a proven complete denominator and original source-availability evidence for both, committed no-replace publication, independent readback of every held selected original and **separate fresh external final readback**. It is never `COMPLETE_EMPTY`. Other nonempty all-or-none exclusion requires its own reviewed general rule; this 2/2/1/0 witness does not license an unbounded extension. References V1 accounting/terminal identity remains unchanged.

The owner publishes raw role-separated originals default-off under host-selected private root, bounded no-replace regular single-link artifacts; complete canonical records bind independently selected role URI, policy/schema exact bytes and digests, predecessor selectors and collision domains. The owner records the **actual request key only after completed framed WRITE**, bound to the write original; match response ID and completed keyed READ in separate originals. WRITE does not prove provider receipt. Retain original query/params, capability and registration events, completed WRITE and inbound frames/result, source and target bytes, raw result and spans, events, terminal, publication/dependencies and redacted failure inventory; record PROCESS provenance separately without making launch or executable measurement a replay gate; compare each against independently held expected values, then perform final fresh readback, never accepting a claimant `verified` field. Precommit failure issues no verified receipt. Committed-but-unverified bytes are quarantined `PUBLICATION_UNVERIFIED`, outcome/disposition null, T=A=0 despite provisional evaluator counts; neither retry nor later hash heals that failed receipt. Missing/withheld originals, wrong role, altered byte, stale generation or policy mismatch fail new replay/issuance; historical immutable records are not rewritten. The proposed mandatory transaction-retained cap and strict same-process expiry are selected in `adr0011-generic-process-provenance-correction.proposed.md`; other retention, privacy, revocation and optional executable-snapshot policies need separate originals. Expiry denies access but does not imply deletion or release activation.

Typed gates retain `UNSUPPORTED`, `REVISION_MISMATCH`, `POLICY_MISMATCH`, `TARGET_IDENTITY_UNRESOLVED`, `CANCELLED`, `TIMEOUT`, `RESOURCE_LIMIT` (including unrelated complete frame excess), `PROVIDER_FAILURE`, `MALFORMED`, `PARTIAL`, publication-unverified and replay-unavailable distinctions. Apply earliest causally witnessed failure, not a convenient later parse outcome. If terminal evidence or denominator cannot be independently reconstructed, qualification is `INCOMPLETE`, never a fabricated `EMPTY`/`EXCLUDED_VERIFIED`. Every successful generic artifact remains `authority=0`, `accepted=false`, `completeness=UNKNOWN`, without producer authentication, source completeness, runtime dispatch, semantic identity, ownership, production authority or feature acceptance. Any future typed grouping input, held-out corpus, index, CLI/MCP and lifecycle have separate gates.

Assumptions: the requested generic direction does not repeal V1; owner custody can be proposed without claiming it currently exists. Gaps: selectors/domains, exact schema/policy bytes and provider-neutral source alternatives require independent selection; PROCESS observation cannot establish process correspondence.
