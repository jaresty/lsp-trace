# ADR 0011 Lane C — V2 lifecycle contract review

**Disposition: `ACCEPT_LIFECYCLE_CUTOVER_DELTA_FOR_IMPLEMENTATION_ONLY`.** This independently reviewed disposition applies only to the exact proposed contract and bounded synthetic controls below. It accepts the trusted-local-host root-wide lock, durable epoch/fence and lifecycle transition **contract for implementation**, not any implementation, installed host authority, actual persistent fence, publication, cleanup, runtime custody, qualification row or public operation. The accepted retention/tombstone predecessor and V1 proposed schema/policy are not overwritten. The trusted local installation is the selected principal; hostile same-UID replacement/rollback and producer authentication remain outside the claim. No automatic abort after a verified pre-unlink intent without durable effect observation.

## Falsification and resolution

An earlier independent review returned `REVISE` because a complete revoke with **zero independently enumerated dependents** was prohibited by `tombstoneRoot.dependent_count >= 1`, despite the contract requiring one child *per dependent*. The maintainer selected an explicitly verified empty dependent set. The revised schema allows `dependent_count=0` and `children=[]`, while `closureSnapshot.selected_dependencies` requires at least one independently selected owned dependency. The targeted zero-dependent fixture was RED on the former minimum (`minimum: got 0, want 1`), then GREEN on the exact reviewed V2 bytes; the positive closure fixture was updated to contain one selected dependency rather than relaxing the schema.

A separate test-only process-local-state RED is retained at `/tmp/adr0011-lifecycle-v2-synthetic-red.log` (ephemeral local log, **not** an immutable qualification artifact): `ASSERT_B_DENIED_WHILE_A_HOLDS` failed because independent B was not denied while A held its local-only state. Under test-only OS `flock`, the same assertion passed; after A was killed B reacquired the synthetic root lock but denied use/pin upon reading a persisted **synthetic fence marker**. A test-only lock-inode replacement and stale/partial state oracle further deny. Offline targeted V2 run: **68 passing test/subtest events**; offline `go test ./docs/qualification/schemas -count=1`: **273 passing test/subtest events**. Commands used `GOPROXY=off GOSUMDB=off GOTOOLCHAIN=local`. These are proposal-level shape and synthetic process checks, not proof of production cross-process root participation, actual durable publication or full transition-table runtime coverage. `git diff --check` passed; both historical 90- and successor 92-file source-pin manifests remain unchanged.

The subsequent independent read-only reviewer returned **`ACCEPT_LIFECYCLE_CUTOVER_DELTA_FOR_IMPLEMENTATION_ONLY`** on the exact four V2 artifacts above after checking the formerly failing empty-set rule and finding no further decisive contract-level falsifier. Reviewer caveat: the synthetic ref helper uses placeholder paths and role URIs; its schema-positive shapes cannot prove referenced-record semantic equality or ownership. The two-process test establishes bounded lock contention/reacquisition and marker-based denial, **not** anchored epoch replay or an actual production lock. An earlier read-only correction-packet review accepted only a `REVISE`-gap map and is not this disposition.

## Next boundary

Implementation remains **NOT_STARTED**. A separately authorized implementation and independent verification must prove descriptor-pinned root and host-anchor provisioning, all participant entry points under the same bounded OS lock, consecutive durable head transitions and verified fence surviving crash/restart, independent complete closure/leases, one cutover only after verified root, pre-effect intent before each unlink, post-effect/sync uncertainty, monotone reconciliation and fail-closed handling of forks, stale epochs, absent bytes and unverified commits. Two real independent process tests and kill/restart at effect and directory-sync boundaries must exercise that implementation rather than the proposal oracle. There is no fallback to `sync.Mutex`, no automatic abort of an unobserved possible unlink, and no change to historical issuance. This contract acceptance does **not** authorize cleanup, live qualification, owner wiring or references public issuance; public `T=A=0`, references qualification `0/162`, and `PublishReferences` fail-closed remain.
